## 29.1 Quyết định cốt lõi

### Repo strategy: Single repo + runtime/ gitignored

**Không tách 2 repos.** Một `ritsu-works/` repo chứa:
- Code + architecture (committed)
- Tier 1 declarative YAML files (committed)
- Wiki pages — Bài #14 entities (committed v1.0, migrate to Supabase Storage v2.0+)
- Runtime data trong `runtime/` folder (gitignored — never committed)

**Lý do:**
1. Phase A architecture giả định filesystem (Bài #14 wiki/, .archives/, raw/)
2. Onboarding lowest friction (1 clone command)
3. Multi-operator works (Supabase Cloud = shared truth, runtime/ = per-laptop local data)
4. Backup separate from Git (rsync, Borg, cloud storage)
5. Defer over-engineering until concrete need

### Deployment strategy: A → B migration path

**Tuần 1-6 (Phương án A — Local-first):**
- Founder dev local
- Supabase Cloud (Free tier) cho database
- Push to GitHub
- Migrations apply via `supabase db push`
- Cost: $0/mo

**Tuần 7+ (Phương án B — VPS-Hosted Worker):**
- Add Hetzner VPS €5/mo cho always-on workers
- Telegram bot, MCP HTTP server, webhook receivers chạy on VPS
- Auto-deploy via GitHub webhook
- Founder vẫn dev local
- Cost: ~$10/mo

**Trigger để migrate A → B:**
- Cần Telegram bot 24/7
- Cần test Bài #18 voice notes ingestion
- Operator joins
- Founder đang Wave 4+ (Visibility + Access)

# Runtime Data Directory

This folder contains all per-machine runtime data:
- Local secrets (.env files)
- Voice note buffers
- Ingestion temp files
- Local logs
- LLM response caches

- GDPR exports

The `.gitignore` excludes `runtime/` entirely. If you see runtime

After `git clone`:

\`\`\`bash

This folder is NOT version controlled. To backup:

\`\`\`bash
# Local backup:
rsync -av runtime/ ~/backups/ritsu-works-runtime-$(date +%Y%m%d)/

# Cloud backup (e.g., to encrypted Borg repository):
borg create /path/to/borg-repo::ritsu-runtime-{now} runtime/
\`\`\`

\`\`\`bash
# After git clone:
rsync -av ~/backups/ritsu-works-runtime-LATEST/ runtime/
# OR
borg extract /path/to/borg-repo::ritsu-runtime-LATEST
\`\`\`

## Multi-operator note

Each user has THEIR OWN runtime/ folder. Shared data lives in

## 29.5 Pre-commit hook (.husky/pre-commit)

```bash
#!/bin/sh
. "$(dirname -- "$0")/_/husky.sh"

# Reject if runtime files staged
if git diff --cached --name-only | grep -E "^runtime/[^R]" > /dev/null; then
  echo "❌ ERROR: Attempting to commit runtime data!"
  echo ""
  echo "Files staged in runtime/:"
  git diff --cached --name-only | grep -E "^runtime/"
  echo ""
  echo "If this is a genuine commit (e.g., updating runtime/README.md),"
  echo "review carefully. Otherwise, unstage with:"
  echo "  git reset HEAD runtime/"
  exit 1
fi

# Reject if .env files staged (except .env.example)
if git diff --cached --name-only | grep -E "^\.env(\..+)?$" | grep -v "^\.env\.example$" > /dev/null; then
  echo "❌ ERROR: Attempting to commit .env file!"
  echo ""
  echo "Files staged:"
  git diff --cached --name-only | grep -E "^\.env"
  exit 1
fi

# Detect potential secret patterns
git diff --cached -U0 | grep -iE "(api[_-]?key|secret|password|token)\s*[:=]\s*['\"]?[a-z0-9]{16,}" && {
  echo "⚠️ WARNING: Potential secret detected in diff!"
  echo "Review carefully before committing."
  exit 1
}

# Run linter on staged files
if command -v pnpm >/dev/null 2>&1; then
  pnpm lint-staged
fi
```

# .github/workflows/security-check.yml
name: Security Check

on:
  pull_request:
    branches: [main]
  push:
    branches: [main]

jobs:
  no-runtime-data:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Check for runtime data leaks
        run: |
          if git diff origin/main..HEAD --name-only 2>/dev/null | grep -E "^runtime/[^R]"; then
            echo "❌ Runtime data detected in PR!"
            git diff origin/main..HEAD --name-only | grep -E "^runtime/[^R]"
            exit 1
          fi

      - name: Check for committed .env files
        run: |
          if git ls-files | grep -E "^\.env(\..+)?$" | grep -v "^\.env\.example$"; then
            echo "❌ .env file in repo!"
            git ls-files | grep -E "^\.env"
            exit 1
          fi

      - name: TruffleHog secret scan
        uses: trufflesecurity/trufflehog@main
        with:
          path: ./
          base: ${{ github.event.pull_request.base.sha || github.event.before }}
          head: ${{ github.event.pull_request.head.sha || github.sha }}
          extra_args: --only-verified

  validate-tier1:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version-file: '.nvmrc'
      - run: corepack enable
      - run: pnpm install --frozen-lockfile
      - run: pnpm validate-tier1

## 29.10 Sync với multi-operator

### Source of truth ranking

| Type | Source of truth | Sync mechanism |
|---|---|---|
| Code (skills, adapters) | GitHub repo | git pull |
| Tier 1 YAML | GitHub repo | git pull |
| Wiki pages (Bài #14) | GitHub repo (v1.0), Supabase Storage (v2.0+) | git pull |
| Database schemas | `supabase/migrations/` in GitHub | `supabase db push` |
| Database data | Supabase Cloud | Realtime / direct queries |
| Secrets | Supabase Vault (server) + .env.local (per-laptop) | Manual share |
| Runtime cache | Per-laptop `runtime/` | NOT shared (per-machine) |
| Logs | VPS centralized (Phase B) | Optional: aggregator service |

## 29.12 Defense in depth — preventing accidents

### Layer 1: .gitignore
- `runtime/` excluded entirely
- `.env*` excluded (except `.env.example`)
- Build outputs excluded

### Layer 2: Pre-commit hook
- Reject commits với runtime/ files
- Reject commits với .env files
- Detect secret patterns in diffs

### Layer 3: GitHub Actions security check
- Re-validate on every PR
- TruffleHog secret scan
- Schema validation

### Layer 4: Branch protection
- main requires PR review
- main requires passing CI
- No force-push allowed

### Layer 5: Founder vigilance
- Periodic `git log --all --full-history -- runtime/` checks
- Quarterly secret rotation
- Audit team access lists

## 29.13 Tóm lại

**Repo strategy:** Single `ritsu-works/` repo. Runtime data in `runtime/` folder. `.gitignore` strict. Pre-commit hook + CI defense.

**Deployment path:** Phương án A (local-first) → Phương án B (VPS) when triggers met.
