#### Axis 2 — Tool Catalog: knowledge/mcp-tools.yaml

```yaml
tools:
  - id: ritsu.ops.tasks_active
    description: |
      List active workforce tasks (status: pending, in_progress, blocked).
      Use this when founder wants to see what AI workforce is currently doing.
    inputs:
      - name: limit
        type: integer
        default: 50
    role_scope: [founder, operator-ops]
    requires_hitl: false
    cost_bucket: read-only
    
  - id: ritsu.sop.execute
    description: |
      Execute a SOP by ID with parameters.
      Triggers ops.sop_runs creation. Subject to SOP's HITL tier.
    inputs:
      - name: sop_id
        type: string
        required: true
        validation: "^SOP-[A-Z]+-\\d{3}-.+"
      - name: params
        type: object
        required: true
    role_scope: [founder, operator-by-pillar]
    requires_hitl: per_sop  # follows SOP definition

# Auto-discovery: skills/SOPs become tools automatically
auto_discovery:
  - source: manifest.yaml.skills
    template: { id: "ritsu.skill.{{skill_name}}", ... }
  - source: knowledge/<pillar>/sops/SOP-*.yaml
    template: { id: "ritsu.sop.{{sop.id}}", ... }
```

**Properties:**
- Static curated cho stable LLM-facing interface
- Auto-discovery cho skills/SOPs
- Naming: `ritsu.<resource>.<action>`
- Schema validation

#### Axis 3 — Role-Scoped Access + HITL Gate

```yaml
# knowledge/mcp-roles.yaml
roles:
  founder:
    tools: ["ritsu.*"]
    rate_limit: unlimited
    cost_bucket: founder
    
  operator-ops:
    tools: ["ritsu.ops.*", "ritsu.alerts.*", "ritsu.events.query"]
    rate_limit: 1000/hour
    excludes_pii: true
    
  operator-growth:
    tools: ["ritsu.sop.execute(sop_id starting with SOP-GROWTH-*)", 
            "ritsu.kpi.*", "ritsu.knowledge.search"]
    rate_limit: 500/hour
    
  trust-safety-reviewer:
    tools: ["ritsu.alerts.*", "ritsu.events.query", "ritsu.knowledge.search"]
    rate_limit: 200/hour
```

**Authorization flow:**

```
Tool call arrives
  ↓ Identify caller (stdio: founder, HTTP: from token)
  ↓ Lookup role permissions
  ↓ Check tool allowed → if not, 403
  ↓ If requires_hitl Tier B/C/D:
     spawn HITL request (Bài #2) → block until approve/deny
  ↓ If has cost (Bài #7):
     check budget → if over, 429
  ↓ Execute tool
  ↓ Audit log to ops.mcp_calls
  ↓ Return result
```


## 20.8 Anti-patterns

- ❌ Hardcode tool list (use auto-discovery + curation)
- ❌ Skip tool testing (LLM picks wrong tool silently)
- ❌ No role scoping (single token compromise = total access)
- ❌ No HITL gate at MCP layer ($5000 ad campaign auto-fired)
- ❌ No audit trail (cannot debug "who called what")
- ❌ Stdio-only or HTTP-only
- ❌ Tool description as docstring afterthought
- ❌ No schema validation
- ❌ No rate limiting (Cursor agent loop = cost explosion)
- ❌ No cost attribution (Bài #7 budgets meaningless)
- ❌ PII in responses without redaction (GDPR)
- ❌ Synchronous HITL block (use async pending pattern)
