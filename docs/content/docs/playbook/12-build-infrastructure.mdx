# Chương 12 — Boilerplate `_build/`: ROADMAP, recipes, checklists, templates

> Founder không nhớ "cách add new role" qua mỗi tháng. `_build/` chứa **procedural memory cho founder** — recipes, checklists, templates. Founder reads, follows, ships.

## 12.1 Tại sao `_build/` quan trọng

One-person company phải optimize founder's cognitive load. Mỗi lần phải re-think "how to add a role" = lãng phí. `_build/` chứa:

- **ROADMAP.md** — what's done, what's next, where we are
- **recipes/** — multi-step workflows ("how to do X")
- **checklists/** — atomic operations ("did I do all 10 steps for Y?")
- **templates/** — boilerplate ("starting point for new Z")
- **notes/** — brainstorm summaries (the WHY behind decisions)

Đây là thư viện trí nhớ founder. Sau 6 tháng, founder không nhớ chi tiết của Phase A; `_build/notes/problem-3-context-window-economics.md` reconstructs the reasoning.

## 12.3 `_build/recipes/`

Multi-step workflows. Each recipe assumes founder knows context but không nhớ steps.

### Example: `_build/recipes/add-new-skill.md`

```markdown
# Recipe: Add a new skill

When you want to add a skill to Ritsu's workforce:

## Steps

1. **Identify the trigger pattern**
   - When should agents invoke this skill?
   - What's the input/output?
   - Reference: similar existing skills in 05-ai-ops/skills/

2. **Determine owning role**
   - Which role is allowed to invoke?
   - Add to that role's `permissions.skills` list in
     governance/ROLES.md

3. **Copy template**
   - cp -r _build/templates/skill 05-ai-ops/skills/<your-skill>
   - Edit SKILL.md frontmatter:
     - name: kebab-case
     - description: when to use, when NOT to use
     - allowed-tools: subset role can use
     - disable-model-invocation: false (or true for safety-critical)

4. **Write the procedure**
   - Step-by-step what the skill does
   - Inputs / Outputs schema
   - Examples (3+ examples typical)
   - Anti-patterns to refuse

5. **Cost estimate**
   - SQL queries × est latency
   - Token estimate (input + output)
   - Per-invocation cost
   - Per-month projection

6. **Update governance/ROLES.md**
   - Add skill to invoking roles' permissions.skills

7. **Open PR**
   - Tier B (skill addition is reversible)
   - Title: "Add skill: <name> (Bài #N)"

8. **After merge:**
   - Skill available next session
   - Test with manual invocation
   - Monitor first 5-10 invocations for unexpected behavior

## Time estimate
- Simple skill: 30-60 min
- Complex skill (multi-step + new schema): 2-4 hours
```

### Other recipes in Ritsu

- `add-new-pillar.md` — when scope expands beyond 05-ai-ops
- `provision-supabase-ops.md` — Phase B step-by-step
- `add-new-mcp-server.md` — when new MCP integration needed

**Convention:** new recipes added when founder finds self re-thinking same workflow. Recipe lives in `_build/recipes/`, atomic PR.

## 12.4 `_build/checklists/`

Atomic operation checklists. Different from recipes (which are workflows): checklists ensure NOTHING IS FORGOTTEN in a single high-stakes operation.

### Example: `_build/checklists/new-role.md`

```markdown
# Checklist: Adding a new role

Per `governance/ROLES.md` schema requirements + Bài #6 identity mapping.

Atomic — all items in one PR.

## Identity & secrets (must exist before role activates)

- [ ] GitHub bot account created (`ritsu-{role}-bot`)
- [ ] Email forwarder configured (`{role}@ritsu.ai`)
- [ ] Anthropic API key created with monthly cap
- [ ] All secrets stored in secret manager (1Password)
- [ ] Secrets named per `governance/SECRETS.md` convention

## Documentation

- [ ] Role added to `governance/ROLES.md` with full schema:
  - [ ] permissions (files, schemas, mcp_servers, skills, secrets)
  - [ ] hitl_max_tier
  - [ ] budget + economic_budget
  - [ ] context_budget (Bài #3)
  - [ ] memory_config (Bài #4)
- [ ] Identity mapping added to `governance/IDENTITY.md`
- [ ] Secrets entry added to `governance/SECRETS.md`

## Runtime

- [ ] `.claude/agents/<role>.md` created (Claude Code agent file)
- [ ] System prompt thin (<100 lines)
- [ ] References governance + relevant skills

## Hooks tests

- [ ] `pre-tool-secrets` recognizes new role
- [ ] `pre-tool-publish` tier classification correct for role
- [ ] `pre-llm-call-budget` reads new role's economic_budget

## Verification

- [ ] Role can be invoked manually
- [ ] First invocation logs correctly to ops.agent_runs
- [ ] Telegram notifications work for role's tier escalations

## After merge
- [ ] Monitor first 24h for unexpected behavior
- [ ] First weekly cost review check role's actuals vs budget
```

**Convention:** checklists are checkboxes for FOUNDER, not agents. Founder runs through, ticks each. PR description includes "checklist completed".

## 12.7 Anti-patterns `_build/`

- **"ROADMAP gets updated when we feel like it."** Stale = lost trust. Update each meaningful work session.
- **"Recipes are duplicates of architecture docs."** No — architecture docs say WHAT and WHY. Recipes say HOW. Different audiences.
- **"Templates so detailed they don't need filling in."** Defeats purpose. Templates are skeletons; specifics fill in.
- **"Brainstorm notes get edited as decisions evolve."** No — notes are historical. New decisions = new notes + update Tier 1.
- **"Skip checklists, just do it."** Checklists exist for high-stakes operations. Skipping = forgetting.

## 12.8 How `_build/` evolves

After Phase A, `_build/` contains 7 brainstorm notes + foundational recipes/checklists/templates. As phases progress:

- **Phase B+** adds infrastructure provisioning recipes (provisioned-supabase, configured-secrets, etc.)
- **Phase C+** adds skill implementation logs (skill-X-implementation-notes.md)
- **Phase F+** adds pillar build records (pillar-growth-build-log.md)

Each meaningful project = a note (or recipe, or checklist). Over 12 months, `_build/` accumulates institutional memory.

For a new founder forking this template: `_build/` is **the most valuable folder**. Tier 1 files describe WHAT. `_build/` describes HOW and WHY. Without it, fork is just markdown; with it, fork is institutional memory.

## 12.9 Tổng kết

- **`_build/`** = procedural + historical memory cho founder
- **`ROADMAP.md`** = phase progression, updated each meaningful turn
- **`recipes/`** = multi-step workflows (add new skill, provision infra)
- **`checklists/`** = atomic operations (new role, new secret, monthly review)
- **`templates/`** = boilerplate (skill, agent, pillar, SOP)
- **`notes/`** = brainstorm summaries (the WHY)
- **Notes are historical** — don't edit; new decisions = new notes
- **Without `_build/`**, fork is markdown. With it, fork is institutional memory.
