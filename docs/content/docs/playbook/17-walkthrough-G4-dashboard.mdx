4 axes:

#### Axis 1 — Data Layer

Supabase Realtime + materialized views. ops.* extensions:

```sql
CREATE TABLE ops.external_events (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  source          text NOT NULL,  -- 'stripe' | 'sentry' | 'google-analytics' | 'vercel'
  event_type      text NOT NULL,
  external_id     text,           -- source's ID for dedup
  payload         jsonb NOT NULL,
  occurred_at     timestamptz NOT NULL,
  ingested_at     timestamptz DEFAULT now()
);

CREATE TABLE ops.metrics (
  metric_id       text NOT NULL,
  value           numeric NOT NULL,
  measured_at     timestamptz NOT NULL,
  dimensions      jsonb,
  PRIMARY KEY (metric_id, measured_at, dimensions)
);

CREATE TABLE ops.alerts (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  alert_id        text NOT NULL,
  severity        text NOT NULL,  -- info | warning | critical
  title           text NOT NULL,
  triggered_at    timestamptz NOT NULL DEFAULT now(),
  acknowledged_at timestamptz,
  acknowledged_by text,
  resolved_at     timestamptz,
  related_metrics jsonb
);
```

**Tại sao not separate analytics DB (e.g., ClickHouse):**
- v1.0 scale doesn't need it (thousands of users, not millions)
- Postgres + materialized views handle 99% OLAP queries
- Less infra to maintain
- Defer ClickHouse to v1.x when materialized view query latency degrades

#### Axis 3 — Anomaly Detection + Alerting

Hybrid: threshold rules + statistical anomaly detection.

**Threshold rules (Tier 1 declarative):**

```yaml
# knowledge/alert-rules.yaml
rules:
  - id: mrr-drop-5pct
    metric: mrr_daily
    condition: "value < ma_7d * 0.95"
    severity: warning
    notify: [founder]
    channels: [telegram, dashboard]
    cooldown_min: 60
    
  - id: stripe-webhook-stale
    metric: stripe_events_per_hour
    condition: "value == 0 AND last_event > '1h ago'"
    severity: critical
    notify: [founder]
    channels: [telegram, dashboard, email]
    cooldown_min: 30
    
  - id: activation-rate-drop
    metric: activation_rate_24h
    condition: "value < 0.30 AND ma_30d > 0.40"
    severity: warning
    notify: [founder, growth-orchestrator]
    cooldown_min: 360
```

**Statistical anomaly detection (`anomaly-detect` skill):**
- Runs every 15 minutes via Bài #8 schedule
- Z-score, IQR outlier, change-point detection
- Flags suspicious metrics → ops.alerts (severity: info)
- Founder review weekly to graduate stat-detected → threshold rule

**Alert dispatch:**
- ops.alerts INSERT triggers ops.alert_dispatch (Bài #8 dispatcher pattern)
- Telegram inline: "Acknowledge", "Investigate", "Snooze 1h"

#### Axis 4 — Integration + Bidirectional Workflow

**New pillar `08-integrations/`** for webhook receivers:

```
dashboard.ritsu.ai/api/webhooks/
├── /stripe         → ops.external_events
├── /sentry         → ops.external_events + ops.alerts
├── /google-analytics → ops.external_events (batched)
├── /vercel         → ops.external_events
└── /github         → ops.external_events
```

**Bidirectional: dashboard drill-down → spawn agent task:**

User flow:
1. Founder sees alert "Stripe webhook stale"
2. Click "Investigate" → spawns ops.tasks, task_kind='investigate-alert', state_payload includes alert_id
3. Trust-safety role picks up task
4. Investigation result → updates ops.alerts (resolved_at + resolution_note)
5. Dashboard reflects "resolved"

**Pattern: dashboard is read view + action launcher, not just static viz.**
