> *"Mỗi LLM call costs theo token. Context window 200K. 100 sessions/ngày × 50K tokens preamble = $300/ngày chỉ riêng preamble — chưa làm gì cả."*

## 6.1 Failure mode đặc thù

Bài #3 phải giải 6 failure mode:

1. **Token cost spiral từ preamble.** Mỗi session load full CLAUDE.md (10K tokens) + 9 SOPs (45K tokens) + 3 brand docs (10K tokens) = 65K input tokens BEFORE bất kỳ task nào. Multiplied across calls/day.
2. **"Lost in the middle".** Research từ Anthropic và OpenAI: model performance degrades khi context dài. Information ở giữa context bị overlook. Long contexts ≠ better contexts.
3. **Repetitive context.** Cùng CLAUDE.md được rebill trên mỗi request — không cache. 200K tokens × 100 requests = 20M tokens charged for the SAME content.
4. **Cross-task pollution.** Session làm task A → context dài → tiếp tục task B trong cùng session → context của A vẫn ở đó, "pollute" reasoning về B.
5. **No graduation between roles.** GPS (orchestrator, complex reasoning) và `etl-runner` (simple data pulls) cùng có context budget = 200K. Lãng phí cho roles nhẹ.
6. **Trigger compaction wrong time.** Compaction quá sớm = mất useful context; quá muộn = hit hard limit, fail.

## 6.2 Pivot lesson

Đây là bài Ritsu had the **biggest pivot** trong Phase A. Initial design: build custom context management layer (custom skill loaders, custom compaction, custom caching).

Sau khi research Anthropic platform: **~70% planned scope là overengineering**. Anthropic platform đã ship:

- **Skills progressive disclosure** — frontmatter ~100 tokens trong tool list, full SKILL.md loaded on-demand
- **`@imports` trong CLAUDE.md** — lazy reference thay vì copy content
- **Server-side compaction** — `/compact` command, auto-trigger ở threshold
- **Subagents** — fresh context, return summary only
- **Prompt caching** — auto-applied cho repeated content

→ Lesson: **research platform first, build only the gap**.

Ritsu's Outer Harness layer cho Bài #3 chỉ cần:
- CLAUDE.md discipline (lean, \<2K tokens)
- Per-role `context_budget` field (Ritsu-specific policy)
- Default budgets by role archetype

3 thành phần. Không có hook, không có skill mới. Phần lớn work là REMOVING things từ initial design.

## 6.3 CLAUDE.md discipline

CLAUDE.md là file mỗi Claude Code session load đầu tiên. Đây là entry point.

**Tham:** stuff everything vào CLAUDE.md (governance, brand voice, all SOPs, all skills metadata).

**Discipline:** CLAUDE.md là **router**, không phải repository. Use `@imports` để reference khi cần.

### `@imports` mechanics

`@governance/HITL.md` không inline content. Khi agent thực sự cần HITL details (e.g., classifying a tool call's tier), agent TÌM file đó qua tool. Không load upfront.

Lợi ích:
- Preamble nhỏ → mỗi session start cheap
- Knowledge available on-demand (full file readable when needed)
- Updates to imported file không invalidate session cache

### Anti-pattern

```markdown
# CLAUDE.md (BAD)

You are a member of Ritsu workforce.

## Full HITL policy
[copies entire HITL.md content, 8K tokens]

## Full ROLES.md
[copies entire ROLES.md, 14K tokens]

## All skills available
[lists every skill with full description, 20K tokens]

## Brand voice
[copies brand_voice.md, 6K tokens]

[total: 50K+ tokens, charged on every session]
```

This is the most common shape of CLAUDE.md and the most expensive.

## 6.4 Per-role `context_budget`

Mỗi role có 3 numbers trong `context_budget`:

```yaml
context_budget:
  preamble_tokens: 2000      # max session-start preamble
  working_tokens: 60000      # max accumulated working context
  trigger_compact_at: 0.75   # fraction at which agent self-invokes /compact
```

### Default budgets by role archetype

```yaml
# Heavy reasoners (orchestration, deep synthesis)
gps:
  preamble_tokens: 2500
  working_tokens: 80000
  trigger_compact_at: 0.70

# Mid-volume specialists
growth-orchestrator:
  preamble_tokens: 2000
  working_tokens: 60000
  trigger_compact_at: 0.75

content-drafter:
  preamble_tokens: 2500    # needs brand voice loaded
  working_tokens: 70000
  trigger_compact_at: 0.70

# High-volume light roles
support-agent:
  preamble_tokens: 1500
  working_tokens: 30000
  trigger_compact_at: 0.80   # compact aggressively, sessions short

etl-runner:
  preamble_tokens: 1000
  working_tokens: 15000
  trigger_compact_at: 0.85   # most ETL is single-shot

# Read-only roles
code-reviewer:
  preamble_tokens: 1500
  working_tokens: 40000
  trigger_compact_at: 0.75
```

**Rationale:**

- `preamble_tokens` = how rich CLAUDE.md + role-specific preamble may be
- `working_tokens` = how much accumulated reasoning before compact mandatory
- `trigger_compact_at` = aggressiveness; high-volume roles compact aggressively (0.80-0.85), heavy reasoners less aggressive (0.70)

### Setting budgets — heuristic

Ask: *"Nếu role này tiêu hết working_tokens, nó đã làm bao nhiêu work?"*

- `etl-runner` 15K tokens = ~10 SQL queries. Compact reasonable.
- `support-agent` 30K tokens = ~20 customer interactions. Compact reasonable.
- `gps` 80K tokens = orchestration of 3-4 sub-tasks deep. Compact loses context.

Set budget at point where **further accumulation degrades quality more than compaction loses context**.

## 6.5 How budgets interact with platform features

### Skills progressive disclosure

Anthropic platform: skill frontmatter (~100 tokens) là always loaded; full SKILL.md only loaded khi agent invokes skill.

→ With 7 skills in Ritsu, frontmatter total ~700 tokens. Full skills (~3K tokens each) only loaded when invoked.

Without progressive disclosure, 7 skills × 3K tokens = 21K tokens always loaded. With it: 700 tokens always + 3K when actively in use.

### Subagents

Subagent có **fresh context window**. Parent passes only task_id (uuid); subagent reads task from `ops.tasks`, executes, returns summary.

→ Parent's `working_tokens` không grow when subagent does verbose work. The verbose part lives in subagent's context (then dies when subagent completes).

Compose with Bài #5 orchestration: spawn subagent when own context gets full = strategy of context preservation.

### Compaction

`/compact` (manual or auto-triggered):
- Anthropic generates compressed summary of conversation
- Replaces full history với summary
- Conversation continues from summary

Important: compaction is LOSSY. Some details discarded. If you have task state that MUST persist, write to `ops.tasks.state_payload` (Bài #5) BEFORE compacting.

### Caching

Anthropic auto-caches repeated content (e.g., CLAUDE.md, system prompt). Cache reads ~10% of standard input cost.

→ With lean CLAUDE.md (1.2K tokens) + cache: cost is negligible across sessions. Without lean (50K tokens) + cache: cache reads of 50K tokens × N sessions still adds up.

Caching helps but doesn't eliminate the cost of bloat. Lean first, cache second.

## 6.7 Anti-patterns Bài #3

- **"Stuff everything into CLAUDE.md just in case."** Tăng preamble cost mỗi session. Use `@imports` thay.
- **"Disable compaction để giữ full history."** Working tokens hit ceiling, session fail. Compact aggressively cho high-volume roles.
- **"Per-role budget = 200K cho mọi role."** Lãng phí. Tail role (etl-runner) chỉ cần 15K.
- **"Skills frontmatter dài 1000 tokens."** Defeats progressive disclosure. Frontmatter ~100 tokens; details trong body.
- **"Pre-load every skill at session start."** Same problem. Trust progressive disclosure.
- **"Custom context manager thay vì platform compaction."** Often overengineered. Platform tested at scale; your custom layer not.

## 6.8 Tổng kết Bài #3

- **Pivot lesson:** research platform first, build gap only. ~70% initial scope was overengineering.
- **Platform primitives** Ritsu rely on: skills progressive disclosure, `@imports`, `/compact`, subagents fresh context, auto-caching.
- **Outer Harness layer** chỉ 3 thành phần: CLAUDE.md lean (~1.2K tokens), per-role `context_budget`, archetype defaults.
- **No hook, no skill** new for Bài #3 (đặc biệt — minimal infrastructure).
- **Compaction is lossy.** State that MUST persist → ops.tasks state_payload BEFORE compact.
- **Lean first, cache second.** Caching không eliminate bloat cost.

Bài #3 là bài shortest infrastructure-wise. Sang Chương 7 (Bài #4 — Memory & Learning Loop) — bài long-form về cách workforce HỌC theo thời gian.
