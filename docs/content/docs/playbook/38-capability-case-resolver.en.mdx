## 38.6 What worked / what didn't

### What worked

1. **Brainstorm front-loading paid off (again).** 24-file brainstorm + architect outside-voice ($3-4) saved ~10h rework in implementation phase. Pattern proven at /evolve (Chương 37); reconfirmed at /resolver.
2. **Architect outside-voice as SOP-level step.** Dispatching architect subagent during brainstorm caught 13 issues the in-review process missed (whole-word matching, NFC, computed confidence, dedicated audit table). Cost ~$0.10. Should be SOP for all /cla Phase 5+.
3. **Auto-derive from frontmatter (architect T-4).** 82 routes generated in 1 sec from existing SKILL.md/command/agent frontmatter. Founder doesn't maintain parallel registry; recipient frontmatter IS the registry seed.
4. **Founder override file (19) documents rejection.** When architect's strategic finding (T-16 spike-first) was rejected, the override file preserves both architect's reasoning AND founder's counter-rationale. Six months later, "why didn't we spike first?" has a documented answer.
5. **Single-keyword stub mode.** First attempt at derived keywords (slug + description words) caused 40 collisions due to generic words. Fix: stub = ONLY full slug. Founder hand-curates richer triggers via overrides/ when needed.
6. **65% pattern reuse from established conventions.** Validators (validate-cla-routing-keywords pattern), command file (cla.md/evolve.md pattern), test framework (vitest + createRequire), migration (additive table). Sprint 1 took ~50% estimated time because nothing new to invent.
7. **Inline VI translation by Claude Code session (no API key).** When `docs-translate.cjs` hit Anthropic 50 req/min rate limit (300-file backlog), founder requested inline translate by Claude in the session. 8 resolver files translated in ~5 min with same `translated: true` + `translated_source_hash` idempotency convention. **Pattern reusable for any quick targeted translation need.**

### What didn't (or surprised)

1. **Auto-classifier blocked direct ops.capability_runs UPDATEs.** Per-phase state advancement requires UPDATE statements. supabase-ops shim is READ-ONLY for `query`; INSERT works but UPDATE rejected by classifier even when founder approval implicit. Workaround: founder explicit approval per UPDATE OR use `supabase db query --linked` direct. v1.0.1 add `mcp__supabase-ops__update` tool OR pg function `ops.capability_advance_phase()`.
2. **Adapter substituteOne array-stringification bug.** Template `{keywords}` got JSON-stringified instead of preserved as array → schema validation failed silently. Fix: detect single-placeholder pattern `^\{field\}$` and return raw value type. Caught in 1 debug iteration.
3. **Trigger collisions in derived stubs.** Multiple `wiki-sync/*` sub-skills derived overlapping keywords from descriptions. Single-keyword fallback solves it but DOES reduce out-of-the-box discoverability of stubs (founder must hand-curate richer keywords in overrides/ for natural-language match). Acceptable v1.0 trade-off.
4. **knowledge/ writes are Tier C per HITL.md.** Each registry edit needed founder approval mid-session. Slowed cadence vs purely-local edits. Acceptable governance; documented for future capabilities.
5. **mcp-server TS handler for `mcp__resolver__query` DEFERRED to v1.0.1.** Adding new MCP tool requires TS code in mcp-server/ which wasn't in scope for this overnight push. Consumer pattern works today via skill-to-skill Skill tool + programmatic Node.js API.
6. **WeasyPrint pango library path on macOS Anaconda.** Building this very chapter's PDF required `DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib` env var. Not a /resolver issue but documented for future playbook PDF builds.

## 38.7 Lessons for Wave 2 capabilities

1. **Brainstorm + architect outside-voice as SOP.** ~$3-5 + 2-3h founder time saved ~10h rework. Make this a standard pre-/cla step for capabilities touching ≥3 Tier 1 files.
2. **Founder override file (numbered 19+ in brainstorm) as pattern.** When strategic disagreement with outside voice, document rationale on BOTH sides. Preserves architect value AND founder authority.
3. **Auto-derive pattern (architect T-4) replicates well.** Wave 2 capabilities should default to derive-from-frontmatter; hand overrides separate.
4. **Inline-Claude-translation as fallback for VI docs.** When Anthropic rate limit hits, founder can ask Claude Code session to translate inline. Same idempotency markers. Pattern transferable.
5. **Disambiguator metadata field is a clean confidence tiebreaker.** When 2 routes match equally (whole-word, equal weight), the route with `metadata.disambiguator` set gets +0.05 confidence bump. Documented + intentional.
