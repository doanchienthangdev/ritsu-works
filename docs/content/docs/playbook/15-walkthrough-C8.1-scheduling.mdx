#### Axis 1 — Schedule registry

`knowledge/schedules.yaml` Tier 1 declarative file:

```yaml

    invoking_role: gps

    skip_conditions:
      - founder_vacation_mode
    status: active
```

PR-edited (Tier B normal). Single canonical inventory.

#### Axis 2 — Trigger mechanism

Supabase pg_cron + Edge Function dispatcher. NOT GitHub Actions.

```
knowledge/schedules.yaml (Tier 1)
   ↓ on PR merge
GitHub Action regenerates pg_cron entries
   ↓
Supabase pg_cron jobs (mirrors yaml)
   ↓ pg_notify on schedule fire
ops.scheduled_runs INSERT
   ↓
Edge Function dispatcher
   ↓ pre-flight checks
Spawn agent run via Anthropic API
   ↓
ops.agent_runs với scheduled_run_id reference
```

Tại sao pg_cron > external:
- Already have Supabase ops (no new infra)
- Postgres-native audit
- Triggers write directly to ops.* — same trail

#### Axis 3 — Failure handling

```sql
CREATE TABLE ops.scheduled_runs (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  schedule_id     text NOT NULL,
  scheduled_at    timestamptz NOT NULL,
  triggered_at    timestamptz,
  agent_run_id    uuid REFERENCES ops.agent_runs(id),
  status          text NOT NULL,  -- pending/running/done/failed/dead_letter/skipped
  retry_count     int DEFAULT 0,
  next_retry_at   timestamptz,
  failure_reason  text,
  skipped_reason  text,
  created_at      timestamptz DEFAULT now()
);

CREATE TABLE ops.settings (
  key             text PRIMARY KEY,
  value           jsonb NOT NULL,
  updated_at      timestamptz DEFAULT now(),
  updated_by      text
);
```

Retry: exponential backoff (5min, 25min, 2h). After max → `dead_letter` + Telegram alert.

Skip: `skip_conditions` evaluated before trigger. Skipped ≠ failed (preserves analytics).

#### Axis 4 — HITL + Budget integration

Pre-flight checks in dispatcher:

```python
def trigger_scheduled_run(schedule_id):
    schedule = load_from_yaml(schedule_id)
    
    # 1. HITL check
    if schedule.hitl_tier in ['C', 'D-Std', 'D-MAX']:
        await queue_for_founder_approval(schedule)
        return  # Don't auto-execute Tier C+ scheduled
    
    # 2. Budget check (Bài #7's logic)
    budget_status = check_budget(schedule.invoking_role, projected_cost=...)
    if budget_status == 'block':
        await alert_telegram(f"Schedule {schedule_id} blocked")
        return
    elif budget_status == 'escalate':
        await queue_for_founder_approval(schedule, reason='budget_overage')
        return
    
    # 3. Concurrency lock
    lock = await acquire_lock(f"schedule:{schedule_id}", timeout='1m')
    if not lock:
        await alert_telegram(f"Schedule {schedule_id} skipped: previous still running")
        return
    
    # 4. Skip conditions
    for cond in schedule.skip_conditions:
        if await check_condition(cond):
            await mark_skipped(schedule_id, reason=cond)
            return
    
    # 5. Execute
    try:
        agent_run_id = await invoke_agent(schedule)
        await mark_done(schedule_id, agent_run_id)
    except Exception as e:
        await handle_failure(schedule_id, e)
    finally:
        await release_lock(lock)
```

Tier C scheduled UX flow:

```
Friday 4pm UTC: cost-optimization-review scheduled (Tier C)
   ↓
Dispatcher pre-flight: Tier C detected
   ↓
Telegram cho founder:
   "📅 Scheduled: cost-optimization-review (weekly)
    Will analyze last week's costs and propose PR.
    Approve now / Defer 1h / Skip this week"
   ↓
Founder approve → execute
   ↓
PR opened → "Cost review PR #123 ready"
```

## 15.7 Lessons captured

1. **Scheduling = layer, not skill.** Skill executes; scheduler triggers. Different abstractions.
2. **pg_cron > external scheduler.** Same-database = same audit trail.
3. **Pre-flight in dispatcher, not skill.** Skill doesn't know scheduled vs ad-hoc.
4. **Tier C scheduled = HITL queue.** Don't auto-execute just because scheduled.
5. **Skip ≠ failure.** Distinct status preserves analytics.
6. **Bottom-up validation works:** không thể design Bài #8 đúng nếu không list 60+ schedules cụ thể.
