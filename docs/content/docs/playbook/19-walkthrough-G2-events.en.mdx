## 19.1 Tình huống

Founder TH6 anchor: *"Sentry → Telegram → agent fix → deploy — luồng tự động?"*

5 concrete event scenarios:

1. **Sentry critical error** (01:23 UTC) → investigate-sentry-incident SOP → Telegram + suggested fix → founder approve morning → deployed by 09:00
2. **Customer churn signal** (login event aggregation, 14d inactive) → churn-intervention SOP → personal email draft → Tier B HITL
3. **Stripe webhook stale** (heartbeat anti-event, no events 1.5h) → investigate-stripe-stale SOP → Telegram critical alert
4. **DMCA takedown received** (email parser) → dmca-handling SOP với 24h SLA → founder approve takedown
5. **High-value signup** (Stripe webhook + Pro tier) → high-value-onboarding SOP → personal welcome + 7d check-in

**Common pattern:** Event arrives → trigger evaluation → SOP execution → outcome.

**Founder expected:** events automatically trigger appropriate SOPs without polling.

**Khi sai:**
- Events lost (Sentry alert seen 12h late)
- Wrong routing (customer churn email → support agent role)
- Duplicate processing (same Stripe event fires SOP 2x)
- Race conditions (3 alerts simultaneously, dispatcher can't queue)

### Proper extension — Bài #11: Event-Driven Triggers

4 axes:

#### Axis 1 — Event Taxonomy (3 sources, unified)

**Source 1 — External events** (Bài #10 webhooks): Stripe/Sentry/GA/Vercel/GitHub

**Source 2 — Internal events** (NEW): workforce state transitions, customer state transitions
- Outbox pattern: same transaction = no event loss
- Helper function `emit_event()` called from skills/triggers

**Source 3 — Synthetic events** (NEW): aggregations/correlations
- Computed by `event-aggregator` skill (scheduled)
- "Customer-inactive-14d", "activation-funnel-completed"

**Unified table:**

```sql
CREATE TABLE ops.events (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  event_type      text NOT NULL,
  source          text NOT NULL,
  external_id     text,
  occurred_at     timestamptz NOT NULL,
  ingested_at     timestamptz DEFAULT now(),
  payload         jsonb NOT NULL,
  routing_status  text DEFAULT 'pending',
  routed_to       text[],
  routing_error   text
);
CREATE UNIQUE INDEX ON ops.events (source, external_id) WHERE external_id IS NOT NULL;
```

#### Axis 2 — Subscription Registry

`knowledge/event-subscriptions.yaml` Tier 1 declarative:

```yaml
subscriptions:
  - id: sentry-critical-to-investigate
    event_type: "sentry.error.created"
    condition: "payload.level == 'error' AND payload.severity_count > 50"
    action:
      kind: trigger_sop
      sop_id: SOP-OPS-001-investigate-sentry-incident
    hitl_tier: B
    dedup_key: "payload.fingerprint"
    
  - id: customer-inactive-14d-intervention
    event_type: "ritsu.customer.inactive_14d"  # synthetic
    condition: "payload.customer.tier IN ('plus', 'pro', 'ultra')"
    action:
      kind: trigger_sop
      sop_id: SOP-CUSTOMER-003-churn-intervention
    hitl_tier: B
    dedup_key: "payload.customer_id"
    cooldown_days: 30
    
  - id: dmca-takedown-handling
    event_type: "ritsu.email.dmca_received"
    condition: "true"
    action:
      kind: trigger_sop
      sop_id: SOP-COMPLIANCE-001-dmca-handling
    hitl_tier: C
    dedup_key: "payload.email_message_id"
    sla_minutes: 1440
```

Properties: declarative, condition expression, actions, dedup_key, cooldown, HITL override, SLA.

#### Axis 3 — Event Router

`event-dispatcher` Edge Function reuses Bài #8 pattern:

```
ops.events INSERT
  ↓ pg_notify('events_pending', event_id)
event-dispatcher
  ↓
1. Load matching subscriptions
2. For each match:
   a. Dedup check (ops.event_dedup)
   b. Pre-flight (HITL, budget per Bài #7)
   c. Spawn action (sop-execute / skill / chain emit)
3. Update routing_status, routed_to
```

**GBrain Minions integration:** event-dispatcher = deterministic (rule match → action) → ops.minion_jobs queue, NOT subagent. **60-80% cost saving.**

`ops.event_dedup`:
```sql
CREATE TABLE ops.event_dedup (
  subscription_id text NOT NULL,
  dedup_key       text NOT NULL,
  triggered_at    timestamptz NOT NULL,
  expires_at      timestamptz NOT NULL,
  PRIMARY KEY (subscription_id, dedup_key)
);
```

#### Axis 4 — Aggregation + Replay

`event-aggregator` skill (scheduled every 15min via Bài #8):

```yaml
# knowledge/event-aggregation.yaml
aggregations:
  - id: customer-inactive-14d
    output_event_type: "ritsu.customer.inactive_14d"
    cadence: "15 minutes"
    query: |
      SELECT c.id AS customer_id, c.tier
      FROM customers c
      LEFT JOIN events e ON e.payload->>'customer_id' = c.id::text
        AND e.event_type = 'ritsu.user.login'
        AND e.occurred_at > now() - interval '14 days'
      WHERE c.status = 'active' AND e.id IS NULL
    payload_template: '{ "customer_id": "{{customer_id}}", "tier": "{{tier}}" }'
    idempotency_window: "30 days"
```

**Replay:** `ritsu-cli events replay --from <ts> --to <ts>` for outage recovery. Idempotency via dedup table.
