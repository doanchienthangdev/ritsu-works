## 47.1 Bài toán — styling là tài sản phân tán, không có "Ritsu trông thế nào" tái sử dụng

deepask render được 12 format; docs-engine render Fumadocs; các command khác sẽ còn tạo HTML/slide/poster. Nhưng *cách chúng trông* đang là improv của từng renderer — không có một định nghĩa **tái sử dụng** về palette/type/logo của Ritsu, cũng không có cách "mặc" một phong cách bên-ngoài (Stripe, Linear) lên một artifact. Hai thiếu hụt: (1) một identity *"Ritsu trông như thế nào"* sống ở Tier 1, dùng được bởi mọi renderer; (2) một cách *plug* một design system bất kỳ vào output mà không phải sửa renderer.

## 47.2 Hai phần — thư viện + flag universal

1. **Thư viện design system.** Mỗi system = **1 folder + 1 `DESIGN.md`** theo định dạng *google-labs-code/design.md / Google Stitch* đang nổi: **YAML design tokens** (colors/typography/rounded/spacing/components) + **Markdown rationale** (Overview personality + Do's/Don'ts). Nguyên tắc khoá: **ADOPT chuẩn đang-nổi, KHÔNG tự phát minh** một format token mới.
2. **Flag UNIVERSAL `--style=<name>`.** Bất kỳ command tạo-output nào cũng pass `--style`; orchestrator resolve nó MỘT lần qua `scripts/design-system/resolve-style.cjs` rồi tiêm DESIGN.md đã-resolve làm **design context** vào *bất kỳ* renderer mà `--format` dispatch tới. `--style` là **DATA**, không bao giờ thêm một dispatch row / renderer mới (AD-4). Bỏ qua `--style` → `{mode:'plain'}` (mặc định, zero-cost).

## 47.3 SPLIT registry — owned ở Tier-1, downloaded ở cache gitignored

Một quyết định kiến trúc trung tâm: **registry tách đôi**, vì owned và downloaded có *vòng đời khác nhau*.
- **owned/canonical** → `00-core/design-system/<name>/` (Tier-1, PR-governed). Hệ thống `ritsu` ("Electric Cyan V2", primary `#0ABCD0`) sống ở đây — nó LÀ *"Ritsu trông như thế nào"*, graduate stub `00-core/design-system.md` thành canonical.
- **downloaded third-party** → `runtime/design-systems/<name>/` (gitignored cache, re-downloadable). Stripe/Vercel/Linear/… nằm đây sau khi fetch.
- **Index** = `knowledge/design-systems.yaml` + JSON schema; validator `validate-design-systems.cjs` (L2). `registration ≠ materialization` (AD-2): một system đăng-ký metadata-first (`status: not_cached`) và materialize lười khi `--style` đầu tiên cần. Verb `vendor` promote một cache → Tier-1 cho CI reproducibility.

## 47.4 `/design-system` command — 9 verb, HITL A→B→C

Thin orchestrator soi gương hình dạng của `/deepask`, trên `scripts/design-system/*.cjs` (`resolve-style`, `parse-design-md`, `registry-io`, `download`):

| Verb | Mục đích | HITL |
|---|---|---|
| `list` / `show <name>` / `search <query>` | liệt kê / xem tokens+rationale / tìm thư viện remote (no download) | A |

## 47.5 Resolution order + AD-3 (determinism cho CI)

`resolve-style.cjs` cho `--style=<name>`: **index → owned path → cache path → (miss + interactive) download → cache → use**. Bỏ qua → `plain`. Một DESIGN.md "có-mặt-nhưng-không-dùng-được" (prose tokenless, frontmatter hỏng, màu non-sRGB, `{ref}` cycle) **không bao giờ crash** command tiêu thụ — degrade về `plain` + một `warning` đã-log. **Non-interactive/CI (AD-3):** chỉ đọc file có-sẵn (owned + cache materialized), **hard-fail khi cache-miss** — KHÔNG bao giờ lén `npx` trong CI/cron/edge.

## 47.6 Hai ràng buộc khoá — NO MCP / NO API key, và license gate fail-closed

- **NO persistent MCP server, NO API key** (tôn trọng api-key-vs-subscription policy): download = `Bash(npx getdesign@latest add)` key-free; `build --from` nghiên cứu repo. Không có conduit MCP đứng-luôn.
- **License gate R2 (Muse ethical-compass) — fail-closed:** *"downloaded ≠ redistributable"*. Một system `license: null` (chưa ghi license) bị `assertCacheable` (`license-gate.cjs`) **CHẶN cache vào registry** cho tới khi founder ghi một license redistributable. Mặc định an-toàn (refuse) thay vì giả-định cho-phép.

## 47.7 Orthogonal với `--format` — và compose với deepask

`--style` **trực giao** với `--format`: *format = loại artifact; style = ngôn ngữ thị giác*. Chúng compose bằng cách tiêm DESIGN.md đã-resolve vào renderer mà `--format` chọn — **no-op trung thực** cho format phi-thị-giác (inline/text/article/xlsx). Đây chính là trục mà deepask `--art-style` (genre, §45.9) *nhân lên*: brand (`--style`, capability này) thắng palette/logo/type; genre (`--art-style`, deepask) sở-hữu composition/assets/mood. Hai capability, một merge function brand-thắng.
