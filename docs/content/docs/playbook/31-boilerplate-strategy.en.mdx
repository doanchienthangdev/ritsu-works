## 31.1 Bài toán tái sử dụng

Founder có 1 framework architecture (Phase A + A.2 = 19 bài toán, 18 Tier 1 files, 10 layers). Nếu founder muốn vận hành nhiều dự án (Ritsu + Hollywood film channel + future projects), có 3 lựa chọn:

### Option A — Build từ đầu mỗi project

**Pros:** Tối ưu cho từng dự án.

**Cons:** 9-18 months mỗi project. Architecture inconsistent. Lessons learned không chuyển giao.

### Option B — Copy-paste rồi modify

**Pros:** Nhanh hơn Option A.

**Cons:** Drift theo thời gian. Bug fixes không sync. Improvements ở project sau không apply ở project trước.

### Option C — Boilerplate framework

**Pros:** Architecture consistent. Bug fixes propagate. Lessons learned → framework improvements. 50-70% time saved per subsequent project.

**Cons:** Upfront investment refactor. Versioning complexity. Cần ≥2 projects để justify.

**Recommendation cho Ritsu founder:** **Option C — sau khi Ritsu Wave 1-3 stable.** Premature generalization là anti-pattern.

### Sharing strategies (3 lựa chọn)

#### Strategy 1 — Git submodule

```bash
cd ritsu-works
git submodule add git@github.com:doanchienthangdev/agent-os-boilerplate.git core
```

**Pros:** Version pinning explicit, clear separation.
**Cons:** Submodule complexity, friction cho operators không quen.

#### Strategy 2 — pnpm workspace + npm package

```yaml
# pnpm-workspace.yaml (in agent-os-boilerplate monorepo)
packages:
  - 'core/*'
```

```json
// package.json (in ritsu-works)
{
  "dependencies": {
    "@doanchienthangdev/agent-os-core": "^1.0.0"
  }
}
```

**Pros:** Native package manager, natural versioning.
**Cons:** Cần publish package (private registry hoặc public npm).

#### Strategy 3 — Template repo + cherry-pick (RECOMMENDED)

```bash
# Create new project from template
gh repo create ritsu-works \
  --template=doanchienthangdev/agent-os-boilerplate \
  --private

# Run init script
cd ritsu-works
./.scripts/bootstrap-new-project.sh \
  --name "Ritsu" \
  --domain "B2C EdTech" \
  --locale "vi"

# Boilerplate updates merged manually via cherry-pick
git remote add boilerplate git@github.com:doanchienthangdev/agent-os-boilerplate.git
git fetch boilerplate
git cherry-pick <improvement-commit>
```

**Pros:** Đơn giản nhất, no extra tooling, GitHub native.
**Cons:** Manual sync upstream changes (acceptable cho ≤5 projects).

**Recommendation: Strategy 3** cho founder solo / small team.

# core/.scripts-core/bootstrap-new-project.sh
#!/bin/bash
set -e

PROJECT_NAME=${1:?"Usage: $0 <project-name> <domain>"}
PROJECT_DOMAIN=${2:?"Usage: $0 <project-name> <domain>"}
PROJECT_TIMEZONE=${3:-"UTC"}
PROJECT_LOCALE=${4:-"en"}

# Replace placeholders
find core/knowledge-core/templates -name "*.template.yaml" | while read template; do
  output="knowledge/$(basename ${template%.template.yaml}.yaml)"
  sed -e "s|{{PROJECT_NAME}}|$PROJECT_NAME|g" \
      -e "s|{{PROJECT_DOMAIN}}|$PROJECT_DOMAIN|g" \
      -e "s|{{PROJECT_TIMEZONE}}|$PROJECT_TIMEZONE|g" \
      -e "s|{{PROJECT_LOCALE}}|$PROJECT_LOCALE|g" \
      "$template" > "$output"
done

# Copy charter template
mkdir -p 00-charter
sed -e "s|{{PROJECT_NAME}}|$PROJECT_NAME|g" \
    -e "s|{{PROJECT_DOMAIN}}|$PROJECT_DOMAIN|g" \
    core/00-charter-template/charter.template.md > 00-charter/charter.md

# Generate agent-os.config.yaml
cat > agent-os.config.yaml <<EOF
boilerplate:
  version: "1.0.0"
  upstream: github.com:doanchienthangdev/agent-os-boilerplate
  pinned_commit: $(git -C core rev-parse HEAD)
project:
  name: "$PROJECT_NAME"
  domain: "$PROJECT_DOMAIN"
  timezone: "$PROJECT_TIMEZONE"
  locale: "$PROJECT_LOCALE"
EOF

echo "✅ Project $PROJECT_NAME scaffolded!"

## 31.7 Versioning & breaking changes

### Semantic versioning cho boilerplate

```
v1.0.0 — Initial release
v1.0.x — Bug fixes, no breaking changes
v1.x.0 — New features (e.g., Bài #20 added)
v2.0.0 — Breaking changes (e.g., schema migration required)
```

### Breaking change protocol

Khi boilerplate có breaking change:

1. Document migration steps trong `MIGRATIONS.md`
2. Provide migration scripts (`.scripts-core/migrate-vX-to-vY.sh`)
3. Tag boilerplate với new major version
4. Project repos chọn upgrade timing
5. Project bumps `agent-os.config.yaml.boilerplate.version`

### Project pinning strategy

```yaml
# Conservative: pin minor version
boilerplate:
  version: "~1.0"  # accepts 1.0.x patches

# Aggressive: pin patch version
boilerplate:
  version: "1.0.5"  # exact

# Bleeding edge: track main branch
boilerplate:
  branch: main  # not recommended
```

## 31.9 Anti-patterns

### ❌ Generalize quá sớm
**Symptom:** Founder spent weeks tách boilerplate trước khi build Ritsu Wave 1.
**Why bad:** Architecture chưa battle-tested. Generalization based on theory, not real friction.
**Fix:** Build Ritsu Wave 1-3 first. Generalize sau khi có data points.

### ❌ Generalize quá muộn
**Symptom:** Founder copy-paste Ritsu → Hollywood, drift xảy ra trong 6 tháng.
**Why bad:** Bug fixes ở Hollywood không apply Ritsu. Improvements scattered.
**Fix:** Khi 2nd project đầu, tách boilerplate ngay (Maturity Level 2).

### ❌ Over-abstraction
**Symptom:** Boilerplate có 100 config options "for flexibility."
**Why bad:** Nobody uses 90%. Maintenance burden. Onboarding harder.
**Fix:** Start với minimal config. Add option chỉ khi 2+ projects cần.

### ❌ Tight coupling project ↔ boilerplate
**Symptom:** Project code import directly from boilerplate paths.
**Why bad:** Boilerplate refactor breaks all projects.
**Fix:** Boilerplate exports stable interfaces. Project depends on interface, not implementation.

### ❌ Boilerplate becomes monorepo
**Symptom:** All projects merged into single boilerplate repo.
**Why bad:** Conflict between projects. Permissions issues. Deploy complexity.
**Fix:** Boilerplate = template + library. Projects = separate repos.
