## 30.2 Bước A — Local Workshop Mode

### 30.2.1 Định nghĩa

**Bước A:** Tất cả workloads chạy local trên laptop founder/operator. Supabase Cloud cung cấp database, nhưng:
- Background workers chạy local (chỉ khi laptop on)
- Telegram bot chạy local (chỉ khi laptop on)
- MCP server stdio mode (chỉ Claude Code đang mở)
- Schedules/Events fire on Supabase Cloud (always-on), nhưng skill execution có thể queue đợi laptop online

### 30.2.3 Đặc điểm Bước A

**Pros:**
- ✅ Setup nhanh (~2h)
- ✅ Cost = $0 (Supabase Free tier)
- ✅ Privacy 100% (no third-party VPS)
- ✅ Offline dev possible (local workers)
- ✅ Validate architecture trước khi cam kết VPS

**Cons:**
- ⚠️ Telegram bot offline khi laptop sleep
- ⚠️ Schedules fire ở Supabase, but skill execution có thể delay nếu laptop offline
- ⚠️ Webhooks (Stripe, GitHub) cần Supabase Edge Functions hoặc ngrok cho local
- ⚠️ Multi-operator coordination thủ công hơn

### 30.2.5 Webhooks trong Bước A

**Vấn đề:** External services (Stripe, GitHub) cần URL public để post webhooks. Laptop không có IP public.

**Giải pháp 3 lựa chọn:**

#### Option A.1 — Supabase Edge Functions làm webhook receiver
- ✅ Always-on (Supabase managed)
- ✅ No local setup
- ✅ Recommended cho Bước A

```typescript
// supabase/functions/stripe-webhook/index.ts
Deno.serve(async (req) => {
  const event = await verifyStripeWebhook(req)
  // Insert to ops.events outbox
  await db.from('ops.events').insert({
    source: 'stripe',
    event_type: event.type,
    payload: event.data
  })
  return new Response('OK')

```

External webhook URL: `https://<project-ref>.supabase.co/functions/v1/stripe-webhook`

#### Option A.2 — ngrok / Cloudflare Tunnel cho local dev
- Use `ngrok http 3000` → get temporary public URL
- Useful when developing webhook handlers
- ❌ Not for production (URL changes)

#### Option A.3 — Skip webhooks entirely cho Bước A
- Use polling instead (Stripe API poll, GitHub API poll)
- Simpler nhưng higher latency
- OK cho v0.5 validation phase

### 30.3.5 Migration A → B step-by-step

#### Trigger conditions (when to migrate):
- ✅ Telegram bot 24/7 needed
- ✅ Cần test Bài #18 voice notes ingestion
- ✅ External webhooks (Stripe production, GitHub auto-deploy) cần public URL stable
- ✅ Operator joins
- ✅ Founder Wave 4+ implementation

#### Step 1: Provision VPS (15 min)

```bash
# Hetzner Cloud Console → New Server
# - Image: Ubuntu 24.04 LTS
# - Type: CX22 (€5.18/mo, 2 vCPU, 4GB, 40GB)
# - Location: Frankfurt (EU) or Helsinki
# - SSH key: add your public key
# - Hostname: ritsu-vps-prod
```

#### Step 2: Initial server setup (30 min)

```bash
ssh root@<vps-ip>

# Update + harden
apt update && apt upgrade -y
ufw allow 22 && ufw allow 80 && ufw allow 443
ufw enable

# Create deploy user
adduser ritsu
usermod -aG sudo ritsu
mkdir -p /home/ritsu/.ssh
cp ~/.ssh/authorized_keys /home/ritsu/.ssh/
chown -R ritsu:ritsu /home/ritsu/.ssh
chmod 600 /home/ritsu/.ssh/authorized_keys

# Install runtime
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs git caddy
npm install -g pnpm

# Verify
su - ritsu
node -v && pnpm -v && git --version && caddy version
```

#### Step 3: Deploy ritsu-works (30 min)

```bash
# As ritsu user
sudo mkdir /opt/ritsu-works
sudo chown ritsu:ritsu /opt/ritsu-works
cd /opt
git clone git@github.com:doanchienthangdev/ritsu-works.git
cd ritsu-works
./.scripts/bootstrap.sh

# Create production .env
vim runtime/secrets/.env.production
# Fill in production credentials

# Symlink for systemd
ln -sf runtime/secrets/.env.production .env.production
```

#### Step 4: Setup systemd services (1h)

Create `/etc/systemd/system/ritsu-telegram-bot.service`:

```ini
[Unit]
Description=Ritsu Telegram Bot
After=network.target

[Service]
Type=simple
User=ritsu
WorkingDirectory=/opt/ritsu-works
EnvironmentFile=/opt/ritsu-works/runtime/secrets/.env.production
ExecStart=/usr/bin/pnpm telegram-bot:start
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

Tương tự cho:
- `ritsu-mcp-http.service` → port 3001, công cụ Bài #12
- `ritsu-workers.service` → Minions queue processor
- `ritsu-deploy-webhook.service` → port 3002, GitHub webhook listener

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now ritsu-telegram-bot ritsu-mcp-http ritsu-workers ritsu-deploy-webhook

# Verify
sudo systemctl status ritsu-*
```

#### Step 5: Setup Caddy reverse proxy + SSL (15 min)

`/etc/caddy/Caddyfile`:
```
mcp.ritsu.ai {
  reverse_proxy localhost:3001
}

deploy.ritsu.ai {
  reverse_proxy localhost:3002
}
```

DNS: A record `mcp.ritsu.ai` + `deploy.ritsu.ai` → VPS IP.

```bash
sudo systemctl reload caddy
# Caddy auto-fetches SSL via Let's Encrypt

# Verify
curl https://mcp.ritsu.ai/health
# Should return 200 OK
```

#### Step 6: Setup auto-deploy via GitHub webhook (15 min)

Deploy webhook handler (in `ritsu-deploy-webhook.service`) listens on port 3002, verifies signature, runs:
```bash
cd /opt/ritsu-works
git pull origin main
pnpm install --frozen-lockfile
pnpm build
sudo systemctl restart ritsu-telegram-bot ritsu-mcp-http ritsu-workers
```

GitHub repo → Settings → Webhooks → Add:
- URL: `https://deploy.ritsu.ai/webhook`
- Secret: `<from .env.production GITHUB_WEBHOOK_SECRET>`
- Events: Just push events to main
- Active: ✅

#### Step 7: Smoke test (15 min)

```bash
# From local laptop
curl https://mcp.ritsu.ai/health
# {"status": "ok"}

# Send test Telegram message — bot responds from VPS
# Push test commit — VPS auto-deploys

git commit --allow-empty -m "test: trigger deploy"
git push

ssh ritsu@<vps-ip> "git -C /opt/ritsu-works log -1"
ssh ritsu@<vps-ip> "sudo systemctl status ritsu-*"
ssh ritsu@<vps-ip> "journalctl -u ritsu-telegram-bot -n 50"
```

## 30.4 LLM Access Modes (Trục độc lập với A/B)

### 30.4.1 Tại sao cần modes?

Phase A.2 architecture đầu tư heavy vào autonomous patterns. Reality: founder có thể bắt đầu với chi phí thấp (subscription only) và scale up theo revenue.

3 modes để founder chọn:

### 30.4.2 Mode 1 — Subscription-Only

#### Định nghĩa
- Chỉ dùng Claude Pro/Max subscription
- Không có ANTHROPIC_API_KEY hay OPENAI_API_KEY
- Mọi LLM call qua Claude Code session (manual interaction)

#### Cost
- Claude Pro $20/mo (5x usage)
- Claude Max $100/mo (20x usage, recommended)

#### Lost capabilities
- ❌ Background AI workforce 24/7
- ❌ Auto-morning brief
- ❌ Auto-pre-call dossier

- ❌ Embeddings + semantic search (need OpenAI)
- ❌ Muse panel autonomous runs (29 personas)
- ❌ Multi-surface auto-adaptation
- ❌ Customer data auto-categorization
- ❌ Stale decision auto-review

#### Retained capabilities
- ✅ Full data architecture (schemas, state machines)
- ✅ Tier 1 declarative configs work as-is
- ✅ MCP integration (Claude Code = primary surface)
- ✅ Dashboard + visibility
- ✅ Knowledge graph auto-link extraction (zero-LLM regex)
- ✅ HITL workflows (deterministic gating)
- ✅ Deterministic SOPs
- ✅ GDPR deletion (deterministic SQL)
- ✅ Full-text search (Postgres FTS, no embeddings needed)

#### Vision impact
**~50-60% Phase A.2 features lost.** Vision shifts from "AI-native services với autonomous workforce" → "AI-augmented founder workflow với strong data architecture."

#### When to choose
- v0.5 proof-of-concept phase
- Privacy-conscious (no data sent to API providers)
- Cost-conscious early stage
- Validating architecture before committing

### 30.4.3 Mode 2 — Hybrid (Recommended sweet spot)

#### Định nghĩa
- Claude Pro/Max subscription cho dev work
- ANTHROPIC_API_KEY ONLY cho high-leverage autonomous skills
- OPENAI_API_KEY cho Whisper + embeddings

#### Cost
- Claude Pro $20/mo + Anthropic API $20-30/mo + OpenAI API $5-15/mo
- **Total: $45-65/mo**

#### Selective API usage (which skills get API key)
```bash
# In .env.local
ANTHROPIC_API_KEY=sk-ant-...     # for autonomous skills
OPENAI_API_KEY=sk-...             # for Whisper + embeddings

# Feature flags — turn on selectively
RITSU_FEATURE_AUTO_MORNING_BRIEF=true       # 1 LLM call/day = ~$0.03
RITSU_FEATURE_AUTO_PRE_CALL_DOSSIER=true    # 1-3 LLM calls/day = ~$0.10
RITSU_FEATURE_VOICE_NOTE_CLASSIFY=true      # ~$0.01 per note
RITSU_FEATURE_AUTO_INGESTION=true           # cost depends on volume

# Disable expensive features initially
RITSU_FEATURE_AUTO_MUSE_PANEL=false         # 29 personas = $0.50/run
RITSU_FEATURE_CROSS_DECISION_PATTERNS=false # weekly heavy
RITSU_FEATURE_AUTO_SURFACE_ADAPTATION=false # multi-surface variants
```

#### Code-level pattern

Skills check feature flag before calling API:

```typescript
async function executeMorningBrief() {
  if (process.env.RITSU_FEATURE_AUTO_MORNING_BRIEF !== 'true' || 
      !process.env.ANTHROPIC_API_KEY) {
    // Subscription mode: queue for manual review in Claude Code
    await queueTaskForFounder({
      type: 'morning-brief-manual',
      data: gatherSourcesData(),
      hint: 'Open Claude Code, ask "synthesize this morning brief"'
    })
    return { mode: 'manual', queued: true }
  }
  
  // API mode: execute autonomously
  const sources = await gatherAllSources()
  const brief = await callAnthropic({
    system: morningBriefSystem,
    messages: [{ role: 'user', content: JSON.stringify(sources) }]
  })
  await deliverViaTelegram(brief)
  return { mode: 'auto', delivered: true }
}
```

#### Vision retention
**~85% Phase A.2 features functional.** Critical autonomous workflows preserved (morning brief, pre-call dossier, voice classification), expensive ones manual.

#### When to choose
- **Default recommendation cho Ritsu v1.0+**
- Founder wants autonomous high-leverage tasks
- Cost-conscious but accept $50/mo
- Phase B implementation Wave 1-7

## 30.5 Combination playbook — 6 cells

### Cell 1: A + Sub-Only (Workshop mode)

**Setup:**
- Local laptop only
- Claude Pro/Max subscription
- No API keys

**Use case:** v0.5 proof-of-concept, validating Phase B Wave 1-3 architecture.

**Daily workflow:**
```
07:00 Founder opens laptop, runs `pnpm workers:start`
07:15 Opens Claude Code, asks "build today's morning brief"
       (manual, takes 5 min)
09:00 Customer call — manually preps via Claude Code (~5 min before)
12:00 Lunch — closes laptop
13:00 Reopens — workers resume
17:00 Closes laptop — workers stop
```

**Cost:** $20-100/mo (subscription only)

### Cell 2: A + Hybrid (Power user mode)

**Setup:**
- Local laptop only
- Claude Pro + selective API keys
- Workers run when laptop on

**Use case:** Founder solo, validating autonomous skills before committing to VPS.

**Daily workflow:**
```
07:00 Founder opens laptop
07:01 Workers auto-start (systemd-like via launchd/pm2)
07:05 Auto-morning brief delivered to Telegram (1 LLM call)
09:00 Customer call — auto-pre-call dossier delivered 8:30 (Telegram)
12:00 Lunch — workers continue if laptop on
17:00 Closes laptop — autonomous workflows pause
```

**Caveat:** Bot offline khi laptop off. OK cho v0.5-v1.0 solo founder.

**Cost:** $45-65/mo

### Cell 3: A + Full API (Dev preview)

**Setup:**
- Local laptop, full API keys
- All features enabled

**Use case:** Rare. Maybe testing performance trước khi deploy VPS.

**Cost:** $120-200/mo (most expensive cell relative to value — paying for full API but limited by laptop uptime)

### Cell 4: B + Sub-Only (Limited workshop)

**Setup:**
- VPS for always-on (Telegram bot, MCP HTTP)
- No API keys
- Subscription cho Claude Code dev

**Use case:** Founder wants always-on Telegram bot but không muốn API costs yet.

**Reality check:** Telegram bot trên VPS chỉ làm được rất ít without LLM. Mainly:
- Receive voice notes (store raw, can't transcribe without Whisper)
- Receive HITL approvals (deterministic state changes)
- Forward to Claude Code session manually

**Cost:** $25-110/mo (Claude sub + €5 VPS)

**Honestly:** This cell is awkward. Either bump to Hybrid or stay at A.

### Cell 5: B + Hybrid (⭐ Sweet spot)

**Setup:**
- VPS always-on workers
- Selective API keys
- Subscription cho dev work

**Use case:** **Recommended cho Ritsu v1.0 production.**

**Daily workflow:**
```
05:45 ICT — VPS auto-runs morning brief assembly (autonomous)
06:00 — Telegram delivers brief to founder
06:00-09:00 — Founder deep work (laptop opens whenever)
09:00 — Customer call, auto-dossier delivered 30 min before
       (assembled by VPS, no laptop needed)
Throughout day — Telegram bot always responsive
22:00 — Sleep mode active (no notifications)
05:45 next day — Cycle repeats
```

**Cost:** $50-75/mo (Claude sub + API + VPS)

### Cell 6: B + Full API (Production target)

**Setup:**
- VPS + full API
- All features
- Multi-operator ready

**Use case:** v1.5+ scale, revenue justifies, operators joined.

**Cost:** $170-310/mo

## 30.6 Trigger conditions tổng hợp

### Trigger để migrate A → B (infrastructure)
- Telegram bot 24/7 needed (founder daily-active surface)
- External webhooks production (Stripe, GitHub auto-deploy)
- Operator joins
- Founder Wave 4+ implementation
- Voice note ingestion testing (Bài #18)

### Trigger để migrate Sub → Hybrid (LLM mode)
- Founder spending >2h/day on manual LLM tasks (e.g., morning brief)
- Want voice note auto-transcription (Whisper irreplaceable feature)
- Knowledge graph search caps at keyword-only (need embeddings)
- Customer feedback piling up (need auto-categorization)
- Revenue >$500/mo (cost manageable)

### Trigger để migrate Hybrid → Full API
- Revenue >$5000/mo
- ≥2 operators joined (operators expect autonomous workflows)
- Customer base requires multi-locale auto-translation
- Decision velocity becoming bottleneck

## 30.8 Implementation: feature flag matrix

```yaml
version: "1.0.0"
mode: hybrid     # subscription | hybrid | full_api

# === LLM access requirements ===
api_keys:
  anthropic: required_for_autonomous   # null in subscription mode
  openai: required_for_whisper_embeddings

# === Feature flags by mode ===
features:
  # Always on (deterministic, work without API)
  state_transitions:           { enabled: true, requires: [] }
  dashboard:                    { enabled: true, requires: [] }
  hitl_routing:                 { enabled: true, requires: [] }
  gdpr_deletion:                { enabled: true, requires: [] }
  auto_link_extraction:         { enabled: true, requires: [] }    # zero-LLM
  
  # Subscription mode: manual via Claude Code
  morning_brief:
    enabled: true
    requires_api: anthropic
    fallback: manual_via_claude_code
  
  pre_call_dossier:
    enabled: true
    requires_api: anthropic
    fallback: manual_via_claude_code
  
  voice_note_classify:
    enabled: true
    requires_api: anthropic
    fallback: manual_via_claude_code
  
  # Hybrid mode: enable selectively
  whisper_transcription:
    enabled: true
    requires_api: openai
    fallback: manual_phone_transcription
  
  embeddings:
    enabled: true
    requires_api: openai
    fallback: postgres_full_text_search
  
  semantic_search:
    enabled: true
    requires_api: openai
    fallback: keyword_search
  
  # Full API mode: enable when scale justifies
  muse_panel_autonomous:
    enabled: false
    requires_api: anthropic
    cost_warning: "$0.50 per panel run"
    fallback: manual_muse_via_claude_code
  
  cross_decision_patterns:
    enabled: false
    requires_api: anthropic
    cost_warning: "$5-10 per weekly run"
    fallback: manual_pattern_recognition
  
  multi_surface_auto_adaptation:
    enabled: false
    requires_api: anthropic
    cost_warning: "$0.10 per content piece × N surfaces"
    fallback: manual_per_surface_in_claude_code
  
  customer_auto_categorization:
    enabled: false
    requires_api: anthropic
    fallback: manual_categorization
```

Skill loader reads this and routes accordingly:
- API available + flag enabled → autonomous
- API missing or flag disabled → queue task for founder Claude Code review

## 30.10 Tóm lại

### Quyết định lớn cho founder

**Bước 1 — Infrastructure trục:** Bắt đầu Cell A (local), migrate Cell B (VPS) khi trigger met.

**Bước 2 — LLM Access trục:** Bắt đầu Sub-only (validate), upgrade Hybrid (default), Full API khi revenue scales.

### Recommended journey cho Ritsu

```
v0.5 (Wave 1-3):  Cell 1 (A + Sub) → $20-35/mo
v1.0 (Wave 4-7):  Cell 2 → Cell 5 (A→B + Hybrid) → $55-75/mo
v1.5 (post-launch): Cell 5 (B + Hybrid) → $95-230/mo
v2.0+ (scale):    Cell 6 (B + Full API) → $265-410/mo
```

### Critical insight

**Cell 5 (B + Hybrid) là sweet spot cho Ritsu v1.0.** Không phải vì "cân bằng cost" đơn thuần, mà vì:
1. Phase A.2 architecture investment (autonomous patterns) preserved ~85%
2. Always-on infrastructure (VPS) enables Bài #19 founder workflow capstone
3. Cost ~$60/mo = nhỏ hơn 1 Pro customer ($59/mo)
4. Easy to upgrade Cell 6 khi revenue grows (just enable more flags)
5. Easy to downgrade Cell 1-2 nếu cost concerns (disable flags, decommission VPS)

### Anti-patterns to avoid

- ❌ Skip Cell 1 entirely — losing validation phase value
- ❌ Jump straight to Cell 6 — burning cash before validating
- ❌ Cell 4 (B + Sub) — paying VPS for limited automation
- ❌ Permanent Cell 1 — eventually founder bandwidth = bottleneck
- ❌ Mix modes per skill ad-hoc — use feature flags YAML for declarative control
