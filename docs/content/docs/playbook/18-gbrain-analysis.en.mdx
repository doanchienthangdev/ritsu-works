### 18.9.3 5 Lessons học được (không có trong pre-install analysis)

**Lesson 1 — Supabase Direct host IPv6-only.** GBrain Connection Manager dùng dual-pool: read pool (pooler 6543, transaction mode) + DDL pool (`db.PROJECT.supabase.co:5432` auto-derived). Trên Mac local không có IPv6 routing → DDL pool fail. Mitigation: env var `GBRAIN_DIRECT_DATABASE_URL` override → trỏ Session pooler (port 5432 cùng pooler host). Documented memory entry: `reference_gbrain_dual_pool_architecture.md`.

**Lesson 2 — `aws-N-` region prefix is project-specific.** Cannot guess. Verify qua Supabase Management API `/v1/projects/<ref>/config/database/pooler`. Wrong prefix → "tenant/user not found". Documented: `reference_supabase_pooler_url_construction.md`.

**Lesson 3 — GBrain hard-code `public` schema.** Original plan ("Cách 1 cũ") = trỏ gbrain vào ritsu-ops Supabase shared. Phát hiện kịp thời: gbrain tạo `public.pages/sources/chunks/links/...` collide với ritsu-ops `public.customers/persons/companies`. Auto-RLS event trigger sẽ fire trên TẤT CẢ future public.* migrations → break ritsu-ops production. Mitigation: Supabase project hoàn toàn riêng (`ritsu-brain`).

**Lesson 4 — Bash secret-check anti-pattern.** Script `${VAR:-MISSING}` returns VAR's VALUE when set, leaking OpenAI + Anthropic API keys vào session output. Both keys rotated. Documented: `feedback_never_leak_env_values_in_bash_checks.md`. Use `[ -n "$VAR" ] && echo SET || echo MISSING` ternary.

**Lesson 5 — Brain repo IS system of record, DB là mirror.** Đọc operations đều từ DB (vector + tsvector). Write qua `gbrain capture/put` = write-through (filesystem + DB atomic). Edit markdown qua editor → cần `gbrain sync --repo .` để mirror sang DB. Implication: backup = `git push` brain repo (markdown portable, DB rebuildable).

### 18.11.3 Pattern: ONE bundled PR per sprint

Per /cla protocol "one PR per sprint, multi-session". Compressed multi-session → 6 single-PR cycles. Each cycle:

1. `git checkout -b claude/gbrain-operational-brain-sprint-N origin/main`
2. Apply N changes (atomic — all schema/skills/hooks of sprint in 1 commit)
3. `pnpm check` clean
4. `gh pr create` + founder review (real-time)
5. `gh pr merge --squash --delete-branch` per founder auth
6. `git -C /Users/doanchienthang/ritsu-works pull origin main` (main repo separate from worktree — manual sync needed)

Friction: each `gh pr merge` errored locally với *"fatal: 'main' is already checked out at..."* (worktree conflict). GitHub merge succeeded; only local cleanup failed. Workaround: pull from main repo path. Documented for v1.1 follow-up automation.

## 18.12 4 Errors caught at apply time — brainstorm assumes, live verifies †

### 18.12.1 Migration 00037 `cost_bucket` column doesn't exist

Sprint 3 PR #102 merged clean (drift gate passed: validators check yaml structure, not actual DB schema). Founder ran `supabase db push --linked` — Migration 00036 succeeded; Migration 00037 erred:

```
ERROR: column "cost_bucket" does not exist (SQLSTATE 42703)
At statement: 1
CREATE OR REPLACE VIEW metrics.gbrain_cost_daily AS
SELECT split_part(cost_bucket, '.', 2) AS role, ...
```

Root cause: Sprint 1-6 spec docs reference `cost_bucket text` column convention từ brainstorm `knowledge/economic-architecture.md` v1.1 addendum. Real schema (migration 00017): `agent_role text + task_kind text + cost_usd numeric`. No `cost_bucket`.

Fix (v1.0.1 hotfix PR #106 `6100bce9`): rewrite migration 00037 view to use real columns:
- `cost_bucket LIKE 'gbrain.%'` → `task_kind LIKE 'gbrain.%'`
- `split_part(cost_bucket, '.', 2)` → `agent_role`
- `split_part(cost_bucket, '.', 3)` → `REPLACE(task_kind, 'gbrain.', '')`
- NEW companion RPC `metrics.sum_gbrain_cost_rolling(days_back)` for wrapper script
- `scripts/pre-budget-check.sh` updated to call `/rpc/sum_gbrain_cost_rolling`

Re-applied successfully. View + RPC live. Rolling 30d spend query returns 0 (no gbrain.* cost yet).

### 18.12.2 /brain v1.0.1 had 4 naming errors

Sprint 7 follow-up (PR #107) shipped `/brain` slash command + `@brain` subagent based on brainstorm-implied tool names. After `.mcp.json` Sprint 5 activated, real gbrain MCP schema loaded — 4 names didn't match:

| ❌ v1.0.1 assumption | ✓ Live gbrain v0.40.2.0 |
|---|---|
| `mcp__gbrain__update_page` | tool doesn't exist — `put_page` IS idempotent (handles create + update) |
| `mcp__gbrain__archive_page` + 90d window | tool doesn't exist — `delete_page` (soft) + `restore_page` (72h undo) + `purge_deleted_pages` |
| `mcp__gbrain__get_brain_info` | wrong name — `get_brain_identity` + `get_stats` |
| `mcp__gbrain__dream_cycle_manual` | tool doesn't exist — no manual dream trigger; use `sync_brain` (git) or `submit_agent` (LLM job) |

Fix (v1.0.2 PR #109 `83110dca`): rewrote `/brain` + `@brain` against live schema, expanded từ 18 → 30 subcommands, added "Lifecycle facts you must know" section in agent.md so future sessions don't repeat.

### 18.12.3 The deeper pattern — verify against running, not against drafts

Brainstorm-to-implementation pipeline has THREE drift points:
1. **Brainstorm → spec.md** (architect synthesizes; may assume schemas/tool names that don't exist)
2. **Spec.md → migration/code** (developer faithfully implements wrong assumption)
3. **Migration/code → live system** (only fails at `supabase db push` OR first MCP call)

Drift gate (pnpm check) catches structural inconsistencies in Tier 1 yaml. Does NOT catch:
- Yaml entries referencing non-existent DB columns
- MCP tool names that don't exist in live MCP server schema
- Cost bucket conventions vs real attribution column names

**Lesson v1.0.2**: ALWAYS run `mcp__gbrain__get_brain_identity` + `get_stats` + `run_doctor` BEFORE writing /brain spec. ALWAYS run `supabase db push --dry-run` BEFORE Sprint 3 commit. Live system is single source of truth; brainstorm is hypothesis.
