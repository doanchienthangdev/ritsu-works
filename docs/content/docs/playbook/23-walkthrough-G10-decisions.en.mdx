**`muse-panel` skill flow:**

```
muse-panel(decision_topic, panel_id, alternatives, context_pages)
  ↓
1. Load persona definitions
2. Each persona invocation:
   - Pull context from knowledge graph (Bài #14)
   - Generate position paper (parallel, Minions queue if deterministic enrichment)
3. Aggregate papers → ops.muse_runs row
4. Trigger Tier C HITL request to founder
5. Founder synthesis (must approve)
6. On approval → decision-capture skill
   - Creates wiki/decisions/<slug>.md
   - Mirrors to ops.decisions
   - Emits ritsu.decision.made event
```

#### Axis 3 — Time-Decay & Supersession

Decision domain state machine (Bài #13):

```yaml
# Add to knowledge/state-machines.yaml
domains:
  decision:
    initial_state: active
    states:
      - name: active
      - name: stale
        sla:
          to_state: [active, superseded, reversed]
          deadline: 30 days
          alert_on_breach: stale-decision-needs-review
      - name: superseded
      - name: reversed
      - name: archived
    transitions:
      - id: decision-becomes-stale
        from: active
        to: stale
        guard: "now() > next_review_at"
        triggered_by:
          - schedule: daily-decision-staleness-check
        emits:
          - event: ritsu.decision.stale
```

**Daily staleness check** runs via Bài #8 schedule, marks past-deadline decisions stale, alerts founder.

**Supersession edges in knowledge graph:**
- New decision page có `supersedes: <old slug>`
- Old decision page updated: `superseded_by: <new slug>`
- Edges via Bài #14 auto-link extraction
- Old decision auto-transitions to superseded state
