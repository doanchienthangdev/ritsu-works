## 24.1 Tình huống

1. **B2C signup (free tier)** — anonymous → email signup, consent tracking, locale, payment_method=null

5. **Customer 360 view** — single query across profile + subscription + usage + support + LTV + health + graph relationships

**Founder expected:**

- GDPR machinery (find → categorize → delete/anonymize/retain)

- Consent untrackable
- Context-switching across 5 systems

4 axes:

#### Axis 1 — Unified Entity Schema

```sql
CREATE TABLE customers (
  id              uuid PRIMARY KEY,
  segment         text NOT NULL,         -- 'b2c' | 'b2b' | 'partner'
  display_name    text NOT NULL,
  primary_email   text NOT NULL UNIQUE,
  tier            text NOT NULL,
  stripe_customer_id text UNIQUE,
  
  -- State (Bài #13)
  state           text NOT NULL,
  state_since     timestamptz NOT NULL,
  state_payload   jsonb,
  
  -- Localization
  locale          text NOT NULL DEFAULT 'en',
  data_region     text NOT NULL,         -- 'eu' | 'us' | 'apac'
  
  -- Compliance
  consent_version text,
  consent_accepted_at timestamptz,
  deletion_requested_at timestamptz,
  deletion_completed_at timestamptz,
  is_anonymized   boolean DEFAULT false,
  
  CONSTRAINT customers_segment_valid CHECK (segment IN ('b2c', 'b2b', 'partner'))
);

CREATE TABLE companies (...);  -- B2B detail
CREATE TABLE persons (
  id, primary_email, display_name,
  customer_id_as_billing,
  phone,        -- encrypted at rest (pgcrypto)
  metadata,     -- encrypted
  consent_status jsonb
);
CREATE TABLE company_persons (...);  -- B2B relationships
```

**Pattern:**
- customers = billing entity (B2C: 1 person; B2B: company với persons)
- companies = optional B2B detail
- persons = humans (separate for PII isolation)
- Knowledge graph (Bài #14) auto-extracts edges: person→works_at→company

#### Axis 2 — Consent + Privacy Architecture

**Per-purpose consent (persons.consent_status):**

```yaml
consent_status:
  version: "1.0.0"
  accepted_at: 2026-04-15
  
  purposes:
    service_delivery:
      legal_basis: contract  # GDPR Article 6(1)(b)
      consent_required: false
      status: active
    
    marketing_email:
      legal_basis: consent  # 6(1)(a)
      consent_required: true
      status: granted | denied | withdrawn
    
    analytics:
      legal_basis: legitimate_interest  # 6(1)(f)
      status: granted | denied
    
    ai_personalization:  # EU AI Act
      legal_basis: consent
      status: granted
```

**Tier 1 retention registry:**

```yaml
# knowledge/data-retention.yaml
categories:
  - id: customer_pii
    legal_basis: contract
    retention_active: indefinite
    retention_post_termination: 30 days
    deletion_method: hard_delete | anonymize
    
  - id: payment_history
    legal_basis: legal_obligation  # tax law
    retention: 7 years
    deletion_method: anonymize  # cannot hard-delete
    
  - id: ai_training_data
    legal_basis: consent
    retention: 1 year  # EU AI Act max
    deletion_method: hard_delete

inventory:
  - location: customers (table)
    categories: [customer_pii, subscription_metadata]
  - location: persons (table)
    categories: [customer_pii, consent_status]
  - location: ops.events (filtered by payload.customer_id)
    categories: [usage_analytics, ai_training_data]
  - location: stripe (external)
    categories: [payment_history, customer_pii]
  - location: backups (S3)
    retention_override: 30 days
```

**PII isolation:**
- persons.phone, persons.metadata encrypted at column level (pgcrypto)
- Encryption key in Supabase Vault
- ops.audit_log every PII column read

#### Axis 4 — Customer 360 + Integrations

**Materialized view `mv_customer_360`:**

```sql
CREATE MATERIALIZED VIEW mv_customer_360 AS
SELECT c.id, c.segment, c.tier, c.state,
       s.lifetime_value_usd, s.churn_risk_score,
       usage.events_last_30d, usage.last_login_at,
       support.open_tickets,
       graph.related_companies, graph.referrals_count
FROM customers c
LEFT JOIN subscription_stats s ON true
LEFT JOIN usage_stats usage ON true
LEFT JOIN support_stats support ON true
LEFT JOIN LATERAL (
  SELECT array_agg(target_slug) FILTER (WHERE link_type = 'works_at') AS related_companies,
         count(*) FILTER (WHERE link_type = 'referred') AS referrals_count
  FROM ops.knowledge_links
  WHERE source_slug = 'customer/' || c.id::text
) graph ON true
WHERE c.deletion_completed_at IS NULL;
```

## 24.6 Lessons captured

1. **Customer entity = cross-cutting.** Phase A defer wrong (similar to Bài #13).
2. **Unified schema với discriminator** handles B2C + B2B.
3. **PII isolation** through dedicated persons table.
4. **Consent per-purpose, not blanket** (GDPR Article 6 legal bases differ).
5. **Data retention registry as Tier 1.**
6. **Customer-data inventory critical** — without it, GDPR deletion incomplete = €20M fine.
7. **Anonymization vs deletion routing** (tax records cannot hard-delete).
8. **Audit logging for PII access.**
9. **Customer 360 = materialized view + MCP tool.**
10. **EU AI Act adds layer** (ai_personalization consent + 1-year max retention).
11. **Knowledge graph reveals B2B relationships.**
12. **GDPR SOPs leverage Bài #9 architecture** (HITL gating, SLA, audit log built-in).
