# Docs Engine (umbrella)

## When to use

- Founder runs `/docs scaffold` → dispatches to `docs-engine/scaffold`.
- Founder runs `/docs sync` → dispatches to `docs-engine/sync`.
- Founder runs `/docs check` → dispatches to `docs-engine/check`.
- Founder runs `/docs publish` → dispatches to `docs-engine/publish` (Tier B).
- Founder runs `/docs nav` → dispatches to `docs-engine/nav`.
- Founder runs `/docs update <area>` → dispatches to `docs-engine/update`.
- Scheduled `docs-drift-nightly` cron → dispatches to `docs-engine/check`.
- Any agent calls `mcp__docs__ask` (v1.1 feature) → dispatches to a future `docs-engine/ask` sub-skill.

## Inputs

- `verb` — one of `scaffold` / `sync` / `check` / `publish` / `nav` / `update`. (Verb `scaffold` was named `build` in early drafts — renamed because `build/` is repo-gitignored.)
- `args` — verb-specific args (see `.claude/commands/docs.md`).

## State transition

`docs-engine` invocations are stateless w.r.t. the capability itself (the capability is `operating`). State lives in:
- `docs/content/**/*.mdx` (rendered output, in git)
- `ops.kpi_snapshots WHERE kpi_id = 'docs_drift_count'` (drift over time)
- Vercel project (last deploy state, externally hosted)

## HITL

Per verb above. Default Tier A; `publish` always Tier B; `sync` escalates to Tier B if cost > per-task-kind cap OR > 50% pages would change.

## Failure modes

| Symptom | Response |
|---|---|
| `pnpm check` non-zero before sync | Abort. Fix drift first. |
| Secret leak detected (any of 3 layers) | Abort loud. Open GitHub issue tagged `secret-leak-suspected`. |
| Hand-edit conflict on `<!-- generated-by -->` marked page | Write conflict report. Skip the file. Surface to founder. |
| Adapter partial failure | Continue rest. Aggregate errors. Affected pages count toward `docs_drift_count`. |
| Vercel deploy failed | Emit `ritsu.docs.published` with `status: failed`. Founder investigates manually. |
