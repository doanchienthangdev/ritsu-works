# PDF adapter (baseline Sprint 1)

## Khi nào dùng

- Được điều phối bởi `wiki-sync/ingest` khi path kết thúc bằng `.pdf`
- source_kind: `book`
- entity_type: `book`
- wiki target: `wiki/<slug>/source.md` (hoặc `wiki/<slug>/chapters/chapter-NN.md` khi được split — layout source-grouped v4.0)

## Inputs

- `path` — đường dẫn tuyệt đối dưới `raw/books/<filename>.pdf`

## Quy trình

### Bước 1 — Validate

- File có tồn tại không? Nếu không, dừng lại.
- Extension file `.pdf`? Nếu không, ủy thác lại.
- Kích thước file > 0? Nếu không, dừng lại.

### Bước 2 — Tính source_hash

```bash
sha256sum "$path"
```

Trả về `<sha256>:<filename>`. Đây là `source_hash` cho dedup.

### Bước 3 — Trích xuất text qua pymupdf

Sprint 1: shell out đến script `python3 -c "import pymupdf; ..."`. Sprint 2+ có thể
áp dụng thư viện PDF Node-native nếu cài đặt pymupdf gặp vấn đề.

Pseudocode:
```python
import pymupdf, json, sys
doc = pymupdf.open(sys.argv[1])
pages = [p.get_text() for p in doc]
meta = doc.metadata  # author, title, subject, etc.
print(json.dumps({
  'pages_count': len(pages),
  'pages': pages,
  'meta': meta
}))
```

### Bước 4 — Phát hiện trang text trống (tính năng Sprint 2+)

Nếu > 30 % trang trả về text trống → file là PDF scan; cần OCR.
Sprint 1: cảnh báo nhưng không OCR (hoãn lại). Đánh dấu `state_payload.ocr_needed=true`.

### Bước 5 — Tổng hợp raw_text

Nối các trang với separator `\n\n---PAGE-BREAK-PP-<N>---\n\n` để chunker downstream
có thể bảo toàn ranh giới trang khi chunking theo cấu trúc.

### Bước 6 — Tạo slug

- Ưu tiên title PDF từ metadata; nếu không thì dùng stem filename.
- Kebab-case, chữ thường, loại bỏ dấu câu.
- Giới hạn ở 50 ký tự.

## Các chế độ thất bại

| Triệu chứng | Phản ứng |
|---|---|
| File không tìm thấy | Dừng lại với đường dẫn tuyệt đối trong lỗi |
| Không phải PDF (magic bytes sai) | Dừng lại; gợi ý adapter đúng |
| pymupdf chưa cài | Dừng lại với hướng dẫn `pip install pymupdf` |
| > 30 % trang text trống | Tiếp tục với cảnh báo; gắn cờ OCR-needed cho Sprint 2 |
| PDF hỏng (pymupdf raise) | Dừng lại với exception của pymupdf |

## Ước tính chi phí

- Trích xuất (pymupdf): MIỄN PHÍ (tiến trình local)
- Embedding (downstream): ~$0.004 / sách 50 trang
- LLM-fallback (downstream, nếu được kích hoạt): ~$0.05 / chunk

Tổng cho mỗi cuốn sách thường: $0.40-$0.70 (LLM-fallback gây biến động).

## Phạm vi sprint

Sprint 1: chỉ text-layer; không OCR; pymupdf qua Python shell-out.
Sprint 2 PR2 (v2.0.0): tích hợp chapter-split LIVE — khi `pages_or_size_metric > 100` HOẶC founder truyền `--split`, ingest điều phối đến `wiki-sync/chapter-splitter` theo spec SKILL v2.0 của nó; adapter này trả về output không đổi và splitter tiêu thụ chúng.
Sprint 4: OCR fallback qua tesseract; trích xuất link LLM-fallback được kết nối qua feature flag.

## Hợp đồng Chapter-split (v2.0)

Khi `pages_or_size_metric > 100`:
- Adapter này vẫn trả về output chuẩn (raw_text với separator PAGE-BREAK, `pages_or_size_metric`, `attribution`, v.v.).
- `wiki-sync/ingest` Bước 5 thấy ngưỡng được kích hoạt + điều phối `wiki-sync/chapter-splitter`.
- Splitter đọc lại `attribution.title` để dẫn xuất book_slug và `raw_text` để phát hiện ranh giới chapter (chế độ `toc` đọc bookmark PDF qua `doc.get_toc()` — splitter gọi trực tiếp pymupdf, không qua adapter này).
- Mỗi chapter con có row `ingestion_jobs` riêng với `parent_job_id` trỏ đến cha (lần gọi adapter này).
