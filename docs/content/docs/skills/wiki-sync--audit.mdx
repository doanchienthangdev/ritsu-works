# wiki-sync / audit (Sprint 4 PR6 + Sprint 4 v3.0 update)

## Khi nào sử dụng

- Founder chạy `/wiki audit` (Tier A) → báo cáo toàn diện
- Founder chạy `/wiki audit --fix` (Tier B mỗi PR) → audit + mở một PR cho mỗi defect class
- CI chạy `scripts/cross-tier/validate-wiki-integrity.cjs` (warn-tier) → kiểm tra deterministic-subset trên mỗi PR

## Đầu vào

- `--fix` — tùy chọn; cho mỗi defect class có ≥ 1 instance, mở một PR remediation
- `--sample-pct` — tùy chọn; kích thước mẫu LLM stale-claim (mặc định 10%; tối đa 50%)
- `--skip-llm` — tùy chọn; bỏ qua check stale-claim (nhanh hơn, miễn phí)
- `--filter=<page_type>` — tùy chọn; giới hạn tất cả check vào một page_type

## Quy trình (5 check v2.0 + 4 check v3.0 = 9 tổng)

### Check 1 — Hash drift (deterministic)

Với mỗi dòng `ops.knowledge_pages` WHERE `file_hash IS NOT NULL`:
- Đọc file wiki tại `wiki/<file_path>`
- Tính `sha256(file_content)` hiện tại
- So sánh với `file_hash` trong DB
- Đánh dấu drift nếu hash khác

**Nguyên nhân thường gặp:**
- Founder edit trang bằng tay (marker `<!-- generated-by: wiki-sync vN -->` vẫn có → edit không cố ý trên trang được generate)
- Founder edit trang được generate bằng tay VÀ xóa marker → override CÓ CHỦ Ý; không phải defect
- File được regenerate qua `/wiki sync --force` mà không update DB → bug; cần đối chiếu

**Xử lý:**
- Nếu có marker + có drift → đánh dấu là "untracked_edit_to_generated_page"
- Nếu không có marker + có drift → không phải defect (founder làm chủ trang này)
- Nếu thiếu file hoàn toàn → xem Check 4

### Check 2 — Orphan links (deterministic)

```sql
SELECT id, source_page_id, link_type, source_text, extracted_from_section
  FROM ops.knowledge_links
 WHERE is_active = true
   AND target_page_id IS NULL;
```

Mỗi kết quả = một tham chiếu `[[type/slug]]` mà target chưa được tạo. Không nhất thiết là defect (founder có thể dự định tạo sau) — nhưng được theo dõi để cross-reference hồi tố khi target xuất hiện.

**Xử lý:**
- Group theo `target_slug_extracted_from_source_text`
- Báo cáo: "N links point to \<target>, which doesn't exist yet"
- Chế độ `--fix`: mở PR với các file stub `wiki/<source-slug>/<type>s/<target>.md` chứa comment TODO (layout v4.0 source-grouped — `--fix` cần source context từ chuỗi `extracted_from_source_id` của `source_page_id` của link để chọn đúng package; các stub orphan không thể đặt nếu không có source context, nên các link thiếu source-slug có thể truy vết được sẽ được flag cho founder thay vì auto-stub)

**Loại trừ v4.0:** `wiki/_index/` được loại trừ khỏi giải pháp target orphan-link. Các trang `_index/` là link-list reverse-lookup được regenerate bởi skill `wiki-sync/index-rebuild` từ `ops.knowledge_pages` + `ops.knowledge_extractions`; chúng là DERIVATIVE, không phải nơi lưu canonical entity. Một link `[[concept/wedge]]` KHÔNG resolve về `wiki/_index/concept/wedge.md` — nó resolve về các trang canonical per-package tại `wiki/<source-slug>/concepts/wedge.md`. Audit walk các file `_index/` chỉ cho mục đích hash-drift (tính toàn vẹn của output được regenerate), không phải resolve orphan.

### Check 3 — Dead URLs (network)

Với mỗi trang WHERE `source_kind = 'article'` AND `source_ref LIKE 'http%'`:
- HTTP HEAD đến `source_ref`
- Timeout 30s mỗi URL; tối đa 10 concurrent
- Đánh dấu nếu mã response là 4xx HOẶC 5xx HOẶC request fail (DNS, timeout)
- Bỏ qua nếu response 2xx HOẶC 3xx

**Chi phí:** miễn phí (chỉ network); ~1 phút cho 100 URLs ở mức 10 concurrent.

**Xử lý:**
- Chế độ `--fix`: mở PR thêm `dead_url: true` vào frontmatter của trang + comment `<!-- dead-url-detected: <date>; was: <code> -->`
- Founder có thể quyết định: re-ingest từ wayback snapshot, thay bằng URL archive.org, hoặc đánh dấu trang deprecated

### Check 4 — File missing trên disk (deterministic)

Với mỗi dòng `ops.knowledge_pages`:
- Kiểm tra `wiki/<file_path>` có tồn tại trên disk
- Đánh dấu nếu thiếu

**Nguyên nhân thường gặp:**
- Founder xóa file trực tiếp mà không dùng lệnh `/wiki`
- Filesystem corruption / git merge conflict để lại stub
- Migration di chuyển file nhưng DB chưa update

**Xử lý:**
- Chế độ `--fix`: founder xác nhận "regenerate from source_ref" (chạy lại /wiki sync) hoặc "delete the orphan DB row"
- Báo cáo bao gồm cả hai lựa chọn + source_ref để founder chọn

### Check 5 — Mẫu stale-claim (LLM; mặc định tắt)

Với N% trang ngẫu nhiên (mặc định 10%; tối đa 50%):
- Fetch body của trang + nội dung source_ref gốc (re-fetch nếu URL; re-read nếu file)
- Gửi cả hai đến Claude Haiku với prompt:
  ```
  You are auditing whether a wiki page's claims still match its source ref.

  Wiki page (current):
  <body>

  Source ref (re-fetched):
  <source_content>

  Output JSON:
  {
    "claims_consistent": bool,
    "stale_claims": [{ claim: string, why_stale: string, source_says: string }],
    "confidence": 0..1
  }

  If unsure, set confidence < 0.6 and return empty stale_claims.
  ```
- Đánh dấu trang có `claims_consistent: false AND confidence > 0.6`

**Chi phí:** ~$0.005/trang (Haiku rẻ). Cho 100 trang × 10% sample = 10 đánh giá = ~$0.05.

**Xử lý:**
- Chế độ `--fix`: mở PR với frontmatter `stale_claims_detected: <date>` + comment body liệt kê từng stale claim
- Founder review + sửa thủ công HOẶC chạy lại `/wiki sync --force` để regenerate từ source hiện tại

### Check 6 — Distillation completeness (v3.0 — deterministic)

Với mỗi dòng `ops.knowledge_pages` WHERE `extracted_from_source_id IS NULL` AND `legacy_v2_verbatim = false` AND `source_kind IS NOT NULL` AND `deleted_at IS NULL` (tức các trang source RECORD từ các ingest thời v3.0):

```sql
SELECT id, slug, source_kind, source_ref, created_at,
  (SELECT COUNT(*) FROM ops.knowledge_extractions WHERE source_page_id = ops.knowledge_pages.id) AS extraction_count
  FROM ops.knowledge_pages
 WHERE extracted_from_source_id IS NULL
   AND legacy_v2_verbatim = false
   AND source_kind IS NOT NULL
   AND deleted_at IS NULL
   AND NOT EXISTS (SELECT 1 FROM ops.knowledge_extractions WHERE source_page_id = ops.knowledge_pages.id);
```

Mỗi kết quả = một trang source KHÔNG có derived entity nào. Nguyên nhân khả dĩ:
- Skill distill sản sinh 0 entity trên ngưỡng confidence (source chất lượng thấp HOẶC prompt distill chưa tune)
- Skill distill bị skip (flag `--verbatim`) — KHÔNG phải defect; mong đợi nếu frontmatter hiển thị `legacy_v2_verbatim=false AND distill_mode='verbatim'` (TODO thêm field)
- Distill run fail giữa pipeline và source RECORD đã commit mà không có entity (defect)

**Xử lý:**
- Chế độ `--fix`: mở PR với cờ frontmatter `distillation_pending=true` + Telegram heads-up "Source X has 0 derived entities; run /wiki sync --force or skip if intentional"

### Check 7 — Citation integrity (v3.0 — deterministic)

```sql
SELECT kp.id, kp.slug, kp.page_type, kp.extracted_from_source_id
  FROM ops.knowledge_pages kp
 WHERE kp.extracted_from_source_id IS NOT NULL
   AND kp.legacy_v2_verbatim = false
   AND kp.deleted_at IS NULL
   AND NOT EXISTS (
     SELECT 1 FROM ops.knowledge_extractions ke
     WHERE ke.derived_page_id = kp.id
   );
```

Mỗi kết quả = một trang derived entity KHÔNG có dòng `knowledge_extractions` tương ứng. Đây là LỖI KỶ LUẬT CITATION — entity tồn tại nhưng không thể truy ngược về source chunk của nó.

Nguyên nhân khả dĩ:
- Skill distill INSERT dòng knowledge_pages nhưng transaction rollback trước khi INSERT knowledge_extractions (partial write)
- Bug schema: một thao tác downstream xóa extraction mà không soft-delete trang derived

**Xử lý:**
- Chế độ `--fix`: đây là invariant load-bearing của v3.0. Mở PR Tier B đề xuất: (a) hard-delete trang derived orphan (sạch nhất), HOẶC (b) thử tạo lại extraction bằng cách chạy lại distill trên source nếu có thể. Founder chọn.

Cũng được enforce bởi `validate-wiki-integrity.cjs` v0.2 ở chế độ DB (invariant D4).

### Check 8 — Dedup consistency (v3.0 — LLM-augmented)

Với mỗi `page_type` IN `concept` / `observation` / `decision` / `idea`:

```sql
WITH pairs AS (
  SELECT a.id AS a_id, b.id AS b_id, a.slug AS a_slug, b.slug AS b_slug,
         a.page_type,
         1 - (ae.embedding <=> be.embedding) AS cosine_similarity
    FROM ops.knowledge_pages a
    JOIN ops.knowledge_pages b ON b.page_type = a.page_type AND b.id < a.id
    JOIN ops.knowledge_embeddings ae ON ae.page_id = a.id
    JOIN ops.knowledge_embeddings be ON be.page_id = b.id
   WHERE a.deleted_at IS NULL
     AND b.deleted_at IS NULL
     AND a.extracted_from_source_id IS NOT NULL
     AND b.extracted_from_source_id IS NOT NULL
)
SELECT * FROM pairs WHERE cosine_similarity > 0.92;
```

Mỗi kết quả = một cặp trang derived entity LẼ RA phải được merge bởi `wiki-sync/dedup` nhưng không được merge. Nguyên nhân khả dĩ:
- Skill dedup chạy khi một trong hai trang chưa có embedding (trạng thái deferred); không bao giờ chạy lại sau backfill
- Ngưỡng skill dedup chưa tune chuẩn

**Xử lý:**
- Chế độ `--fix`: đưa từng cặp vào queue `wiki-sync/review` (gợi ý frontmatter ở mức trang: `review_state='pending_review'` + `pending_merge_candidate_id`)
- Founder chạy `/wiki review` để confirm/reject từng merge

Cũng được enforce bởi `validate-wiki-integrity.cjs` v0.2 ở chế độ DB (invariant D6).

### Check 9 — Kỷ luật ghi nhận nguồn A11 (v3.0 — deterministic + LLM-light)

a) Mọi trang source RECORD PHẢI có frontmatter `license_status`:
```sql
SELECT id, slug, source_kind FROM ops.knowledge_pages
 WHERE extracted_from_source_id IS NULL
   AND legacy_v2_verbatim = false
   AND source_kind IS NOT NULL
   AND deleted_at IS NULL
   AND (frontmatter->>'license_status' IS NULL
     OR frontmatter->>'license_status' NOT IN ('public_domain', 'creative_commons', 'fair_use_excerpt', 'copyrighted_internal_only'));
```

b) Không có source `copyrighted_internal_only` nào có > 5 extraction loại observation chưa được review:
```sql
SELECT sp.id, sp.slug, COUNT(*) AS unreviewed_obs_count
  FROM ops.knowledge_pages sp
  JOIN ops.knowledge_extractions ke ON ke.source_page_id = sp.id
 WHERE sp.frontmatter->>'license_status' = 'copyrighted_internal_only'
   AND ke.link_type = 'extracted_observation'
   AND ke.founder_reviewed = false
 GROUP BY sp.id, sp.slug
HAVING COUNT(*) > 5;
```

**Xử lý:**
- `--fix` (a): prompt founder mỗi source qua AskUserQuestion để set license_status
- `--fix` (b): Telegram heads-up "Source X has N unreviewed observations; review before any public content uses them" — leo thang sang skill `attribution-watcher` (Sprint 4)
