# wiki-sync / ask (nền tảng Sprint 3 PR5 — v2.0.0)

## Khi nào dùng

- Founder chạy `/wiki ask "<question>"` → điều phối tới đây.
- Agent khác gọi `mcp__wiki__wiki_ask` → cũng điều phối tới đây (bổ sung ở Sprint 3 PR5).

## Đầu vào

- `question` — chuỗi ngôn ngữ tự nhiên (3..2000 ký tự)
- `k` — top-K tuỳ chọn (mặc định 10)
- `rerank` — bool tuỳ chọn (mặc định false; thêm ~$0.05 chi phí khi true)
- `filter` — phạm vi truy hồi tuỳ chọn:
  - `page_type?` — lọc theo loại thực thể (concept/observation/decision/idea)
  - `source?` — **v4.0:** truy hồi giới hạn theo package; slug của source RECORD. Chỉ trả về các thực thể có `extracted_from_source_id` trỏ đến source mang slug này. Ví dụ `--source growth-playbook-fixture`.
  - `packages?` — **v4.0:** hợp nhiều package. Mảng các slug source RECORD. Ví dụ `--packages growth-playbook-fixture,sample`.
- Cú pháp cờ `--source <slug>` / `--packages <slug1,slug2>` từ slash command `/wiki ask` được dịch sang `filter.source` / `filter.packages` ở đây.

## Quy trình (mục tiêu v0.2 — triển khai đầy đủ)

### Bước 1 — Embed câu hỏi

```
POST https://api.openai.com/v1/embeddings
  { model: 'text-embedding-3-small', input: question }
→ 1536-dim vector
```

Chi phí: ~$0.00002 cho mỗi câu hỏi (không đáng kể).

### Bước 2 — Truy hồi hybrid ENTITY-FIRST (v3.0)

**Cập nhật v3.0:** truy hồi ưu tiên các trang THỰC THỂ DẪN XUẤT (đồ thị tri thức đã distilled) hơn là các chunk source RECORD. Trực giác: founder hỏi "tài liệu nói gì về X" — câu trả lời nên xuất hiện trang concept đa-nguồn về X trước, kèm trích dẫn đa-nguồn; các chunk nguồn chỉ là chi tiết thứ cấp.

**Thứ tự truy hồi:**

a) **Truy vấn entity-first (v4.0 hỗ trợ giới hạn package-scope):**
```sql
SELECT kp.id, kp.slug, kp.page_type, kp.title,
       kp.frontmatter->>'summary' AS summary,
       src.slug AS package_slug,
       src.title AS source_title,
       ke.embedding,
       1 - (ke.embedding <=> $question_embedding) AS cosine_similarity
  FROM ops.knowledge_pages kp
  JOIN ops.knowledge_pages src ON src.id = kp.extracted_from_source_id
  JOIN ops.knowledge_embeddings ke ON ke.page_id = kp.id
 WHERE kp.extracted_from_source_id IS NOT NULL    -- derived entities only
   AND kp.deleted_at IS NULL
   AND kp.legacy_v2_verbatim = false
   AND kp.review_state IN ('auto_accepted', 'founder_approved')
   AND (1 - (ke.embedding <=> $question_embedding)) > 0.7
   -- v4.0: package-scope filters
   AND ($filter_source IS NULL OR src.slug = $filter_source)
   AND ($filter_packages IS NULL OR src.slug = ANY($filter_packages))
 ORDER BY cosine_similarity DESC
 LIMIT $k;
```

JOIN tới `src` cho ta package_slug + source_title — cả hai đều dùng trong định dạng trích dẫn v4.0 (spec B9). Tham số `$filter_source` / `$filter_packages` đến từ cờ `--source` / `--packages`.

Nếu có ≥ 3 entity hit với sim > 0.7 → ĐƯỜNG DẪN ENTITY-FIRST. Nhảy đến Bước 3a.
Nếu \< 3 entity hit → CHẢY XUỐNG truy hồi theo source-chunk (b).

b) **Dự phòng source-chunk (hybrid v2.0):** đường dẫn vector + keyword + backlink gốc (giữ nguyên từ v2.0).

**Vì sao entity-first:** việc tái định khung v3.0 nêu rằng wiki/ là đồ thị tri thức của các thực thể đã trích xuất, không phải kho phóng-chiếu file. Truy hồi nên phản ánh ngữ nghĩa đó.

### Bước 2b — Truy hồi hybrid v2.0 ban đầu (đường dẫn dự phòng)

Theo công thức xếp hạng Bài #14, điểm là `vector*0.5 + keyword*0.3 + backlink*0.2`:

**Đường dẫn vector:**
```sql
SELECT page_id, chunk_index, chunk_text, embedding <=> $1 AS distance
  FROM ops.knowledge_embeddings
 WHERE ($filter_page_type IS NULL OR EXISTS (
     SELECT 1 FROM ops.knowledge_pages WHERE id = page_id AND page_type = $filter_page_type
   ))
 ORDER BY embedding <=> $1
 LIMIT $k * 2;  -- over-fetch for dedup
```

**Đường dẫn keyword (BM25 qua Postgres full-text):**
```sql
SELECT page_id, chunk_index, chunk_text,
       ts_rank_cd(to_tsvector('english', chunk_text), websearch_to_tsquery($question_text)) AS rank
  FROM ops.knowledge_embeddings
 WHERE to_tsvector('english', chunk_text) @@ websearch_to_tsquery($question_text)
 ORDER BY rank DESC
 LIMIT $k * 2;
```

**Đường dẫn backlink** (tăng điểm cho các trang được nhiều trang khác trích dẫn):
```sql
SELECT target_page_id, count(*) AS backlinks
  FROM ops.knowledge_links
 WHERE is_active = true
 GROUP BY target_page_id;
```

Kết hợp: chuẩn hoá điểm từng đường dẫn về [0, 1]; tổng hợp theo công thức xếp hạng; khử trùng lặp theo (page_id, chunk_index); lấy top K.

### Bước 3 — Rerank tuỳ chọn (nếu `rerank=true`)

Gọi model rerank của OpenAI trên top-K chunk đối với câu hỏi. Sắp lại theo điểm rerank. Chi phí ~$0.05 mỗi lần gọi.

### Bước 4 — Lấy ngữ cảnh đầy đủ của chunk

Với mỗi chunk top-K, lấy frontmatter của trang + các chunk lân cận (chunk_index ± 1) để có ngữ cảnh.

### Bước 5 — Tổng hợp câu trả lời (định dạng trích dẫn v3.0)

Gọi Claude (Sonnet hoặc Opus theo cờ `wiki_sync_llm_fallback`) với system prompt áp đặt kỷ luật trích dẫn v3.0 (Muse M5):

**Định dạng trích dẫn entity-first v3.0:**
```
"<extracted_quote_from_entity_summary_or_raw_quote>" — extracted from
[Source Title](wiki/<source-slug>/source.md#chunk-N), package `<source-slug>`, confidence X.XX
```

(Cập nhật v4.0: source RECORDs nằm tại `wiki/<source-slug>/source.md`. Trích dẫn bao gồm hậu tố `package` theo spec v4.0 §0 B9. Ví dụ v3.0 dùng `wiki/<source-type>/<source-slug>.md`.)

Ví dụ:
> "Companies that activate users within their first session retain 4-5x better at 30 days" — extracted from [Growth Playbook Fixture](wiki/growth-playbook-fixture/source.md#chunk-3), package `growth-playbook-fixture`, confidence 0.92

**System prompt:**
```
You are answering from a corpus of wiki ENTITIES (distilled knowledge graph)
+ optional source chunks. RULES:

1. PREFER entity pages (concept/observation/decision/idea with
   extracted_from_source_id set) over source chunks. Cite the ENTITY first,
   and the source chunk via its citation footer.

2. Every claim MUST cite via this format (v4.0):
   "<raw_quote>" — extracted from [Source Title](wiki/<source-slug>/source.md#chunk-N), package `<source-slug>`, confidence X.XX

   The Source Title comes from the source RECORD page's frontmatter.title.
   The chunk-N corresponds to knowledge_extractions.source_chunk_index.
   Confidence is the knowledge_extractions.confidence value.
   The `package` suffix lets the reader/skill consumer route by source-slug.

3. If the corpus does not contain enough information to answer, return
   {answer: null, reason: "no_coverage"}.

4. NEVER use information not in the provided entities/chunks.

5. NEVER invent a Source Title or wiki path. If you don't have title metadata
   for a cited chunk, omit the title (use bare wiki path).
```

Đầu vào cho Claude: câu hỏi + top-K thực thể (đường dẫn entity-first) HOẶC + top-K chunk (đường dẫn dự phòng), mỗi mục kèm khối metadata tường minh gồm slug trang, tham chiếu source RECORD, raw_quote từ knowledge_extractions nếu là thực thể, page_type.

### Bước 6 — Xác thực trích dẫn

Xác thực bằng chương trình mọi liên kết `[wiki/...]` trong câu trả lời:
- Đường dẫn tồn tại (khớp một dòng trong `ops.knowledge_pages.file_path`).
- Anchor `#chunk-NN` khớp với một chunk_index có thật trên trang đó.

Nếu xác thực thất bại, thử lại một lần với prompt nghiêm khắc hơn; nếu vẫn thất bại, trả về `reason: 'citation_validation_failed'`.
