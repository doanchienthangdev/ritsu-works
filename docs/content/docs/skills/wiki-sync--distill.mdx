# wiki-sync / distill (v3.0 core engine)

## When this skill runs

- Invoked by `wiki-sync/ingest` Step 6 after Step 5 (extract chunks from source adapter) completes.
- ONE invocation per source ingest. Loops internally over chunks.
- ONLY runs when `feature-flags.yaml::wiki_sync_distill_enabled` is `true` (default v3.0). If `false` OR if `--verbatim` flag is set, ingest pipeline falls through to v2.0 single-page write path (no distill, no entity pages, no extractions).

## Inputs

- `source_page_id` (uuid) — the source RECORD page already INSERT'd into `ops.knowledge_pages` by Step 5 (with `extracted_from_source_id = NULL` because the source IS the source).
- `chunks` (array of `{ index: int, text: string, token_count: int }`) — output of the adapter's chunking step.
- `source_kind` (text) — for per-adapter prompt tuning (e.g., growth playbook chunk needs different system prompt than research paper chunk).
- `license_status` (enum) — read from source RECORD frontmatter; informs attribution-watcher (Sprint 4 skill).

## Outputs

- INSERT N rows into `ops.knowledge_pages` for derived entities (`page_type` IN `concept` | `observation` | `decision` | `idea`; `extracted_from_source_id = source_page_id`; `legacy_v2_verbatim = false`)
- INSERT M rows into `ops.knowledge_extractions` (citation spine: `source_page_id`, `source_chunk_index`, `derived_page_id`, `link_type`, `confidence`, `llm_model`, `extraction_cost_usd`, `raw_quote`)
- INSERT N rows into `ops.knowledge_links` (relational graph: from source RECORD page → derived entity pages; `link_type` IN `extracted_concept` | `extracted_observation` | `extracted_decision` | `extracted_idea`)
- WRITE N Markdown files at `wiki/<source-slug>/<page_type>s/<slug>.md` with v3.0 frontmatter (see Frontmatter spec below); `<page_type>s` is the plural folder name (concepts/observations/decisions/ideas)
- One row in `ops.agent_runs` summarizing the distill (cost, entity counts, confidence distribution)
- Cost-bucket attribution: `ai-ops-knowledge`; task_kind per source_kind (see Cost section)

## Per-type model picker (CTO NIT 5)

| Entity type | Model | Per-chunk cost | Rationale |
|---|---|---|---|
| `concept` | `claude-haiku-4-5` | $0.005-0.02 | Concepts are noun-phrases; Haiku's recall is fine |
| `idea` | `claude-haiku-4-5` | $0.005-0.02 | Unfinished thoughts; lower fidelity bar |
| `observation` | `claude-sonnet-4-6` | $0.025-0.10 | Empirical claims need fidelity to source phrasing |
| `decision` | `claude-sonnet-4-6` | $0.025-0.10 | Framework choices need nuance |

Each chunk is sent to BOTH a Haiku call (for concept + idea extraction) AND a Sonnet call (for observation + decision extraction). The two outputs merge into the chunk's extraction set.

Optimization: when `chunks.length > 20` AND budget tight, batch chunks in Haiku call (one prompt, multiple chunks); Sonnet stays per-chunk (fidelity matters more).

## Confidence semantics (CTO NIT 4) — CRITICAL

`confidence` returned by the LLM is a **COARSE 3-BUCKET signal** in practice:

- ~0.6 = "this is plausibly an entity but I'm not sure"
- ~0.8 = "this is clearly an entity but I had to interpret"
- ~0.95 = "this is unambiguously an entity, source phrasing is direct"

**Do NOT treat the numeric value as a calibrated probability.** Future hooks/queries that compute "expected error rate at threshold X" against `confidence` are misusing the signal. The 3-bucket framing matches both Haiku self-report and Sonnet self-report behavior empirically.

Migration 00031 allows the full 0..1 range in the column (`CHECK (confidence >= 0 AND confidence <= 1)`), but downstream consumers should round-treat values into the 3 buckets.

Threshold dispositions (per spec §0 A6):
- `>= 0.85` → auto-accept; INSERT directly; page `review_state = 'auto_accepted'`
- `0.6 <= conf < 0.85` → queue; INSERT but page `review_state = 'pending_review'`; appears in `/wiki review` queue
- `< 0.6` → auto-reject; NO INSERT; logged to `ops.agent_runs.output_payload.rejected_extractions` for cost transparency

## Process

### Step 1 — Pre-flight checks

- Verify `wiki_sync_distill_enabled = true` in feature-flags.yaml. If false, abort with `state_payload.distill_skipped = true` and pass back to ingest for verbatim fallthrough.
- Verify source_page_id exists in `ops.knowledge_pages` and has `extracted_from_source_id IS NULL` (it IS the source).
- Verify `license_status` is set on source frontmatter. If NULL, prompt founder via AskUserQuestion: which license category? (Sprint 4 attribution-watcher needs this.)
- Estimate cost: `chunks.length × per-type-avg`. If exceeds per-task-kind cap (see Cost section), escalate via Tier B `AskUserQuestion`.

### Step 2 — Per-chunk extraction (loop)

For each chunk in `chunks`:

```
HAIKU call (concept + idea):
  POST https://api.anthropic.com/v1/messages
  model: claude-haiku-4-5
  max_tokens: 800
  system: |
    Extract knowledge ENTITIES from this source chunk. Output JSON only.
    
    Entity types you may extract:
      - "concept": a recurring noun phrase / vocabulary term the source defines or
        relies on (e.g., "product-led growth", "wedge", "ICP"). Slug in
        kebab-case derived from the canonical noun.
      - "idea": an unfinished thought the source raises but doesn't resolve
        (e.g., "what if X interacted with Y?"). Slug derived from the question
        topic.
    
    For EACH entity, output:
      {
        "type": "concept" | "idea",
        "name": "<canonical noun phrase>",
        "slug": "<kebab-case>",
        "summary": "<1-2 sentence summary of how the source defines/raises it>",
        "confidence": 0.6 | 0.8 | 0.95,
        "raw_quote": "<≤300 chars literal text from source supporting this>"
      }
    
    Rules:
      - confidence is a 3-bucket signal: 0.6 = plausibly an entity but unsure,
        0.8 = clearly an entity but I had to interpret, 0.95 = unambiguous.
      - Do NOT extract proper nouns of people/companies (those are other page_types).
      - Do NOT invent slugs; derive from canonical noun phrase.
      - If the chunk has no extractable entities, return [].
      - Output JSON array only. No prose.
  user: <chunk.text>

SONNET call (observation + decision):
  POST https://api.anthropic.com/v1/messages
  model: claude-sonnet-4-6
  max_tokens: 1500
  system: |
    Extract knowledge ENTITIES from this source chunk. Output JSON only.
    
    Entity types you may extract:
      - "observation": an empirical claim with source attribution
        (e.g., "Companies that did X had Y outcome — per Source A, Year B").
        Slug: kebab-case derived from the claim's main proposition.
        Observations MUST cite the source claim (often inline in chunk).
      - "decision": a framework choice or strategic ruling the source recommends
        (e.g., "Pick wedge before brand"). Slug: imperative kebab-case
        (e.g., "always-position-before-tactics").
    
    For EACH entity, output:
      {
        "type": "observation" | "decision",
        "name": "<canonical claim or ruling>",
        "slug": "<kebab-case>",
        "summary": "<2-3 sentence summary; for observations include attribution>",
        "confidence": 0.6 | 0.8 | 0.95,
        "raw_quote": "<≤500 chars literal text from source supporting this>"
      }
    
    Rules:
      - confidence is a 3-bucket signal (see Haiku prompt).
      - Observations MUST have a citable source claim — if the chunk just makes
        an assertion without attribution, prefer "decision" or skip.
      - Decisions are imperative ("do X" or "pick X over Y") with rationale.
      - Output JSON array only. No prose.
  user: <chunk.text>
```

Parse each LLM response as JSON. Validate shape. Reject entities with `confidence < 0.6` (auto-reject; logged to `output_payload.rejected_extractions`).

### Step 3 — Slug normalization + collision check

For each extracted entity:
- Normalize slug: lowercase, replace whitespace with `-`, strip non-alphanumeric except `-`, collapse repeated `-`.
- Check `ops.knowledge_pages` for existing row with same `(page_type, slug)`. If exists:
  - If existing row's `extracted_from_source_id IS NOT NULL` → this is a CROSS-SOURCE DEDUP candidate. Don't INSERT a new page; instead INSERT a `knowledge_extractions` row pointing to the EXISTING page (this source now cites the existing entity). Dedup pass in Step 4 may also flag this for `pending_review` if signals conflict.
  - If existing row's `extracted_from_source_id IS NULL` (manually created OR v2.0 legacy) → still cite via knowledge_extractions but DO NOT mark as conflict.
- If no collision → INSERT new `knowledge_pages` row.

### Step 4 — Cross-chunk dedup (within-source only; Sprint 3 ships cross-source semantic dedup)

Within this source ingest, if two chunks extracted the same `(page_type, slug)`, merge into ONE page with TWO `knowledge_extractions` rows (one per source_chunk_index).

## Failure modes

| Symptom | Response |
|---|---|
| Haiku JSON output malformed | Retry once with explicit "OUTPUT VALID JSON" prefix. If second fails, skip chunk's concept/idea extractions; continue Sonnet. Log to `output_payload.malformed_responses`. |
| Sonnet JSON output malformed | Same retry pattern. |
| Slug collision with v2.0 legacy verbatim page | Cite via knowledge_extractions; do NOT modify legacy page. `review_state` of new derived entity stays auto_accepted/pending_review based on extraction confidence. |
| All entities below 0.6 confidence | Source RECORD page is written but no entity pages. Founder gets Telegram heads-up "Source X distilled with 0 entities — review source quality or distill prompts". |
| Per-task-kind cost cap exceeded mid-ingest | Pause; emit Tier B AskUserQuestion with current cost + projected remaining cost. Founder approves continue OR cancel. |
| `license_status` missing on source RECORD | AskUserQuestion to founder ("Which license category for this source?"); cache answer in source frontmatter; resume. |
| OPENAI_API_KEY absent during Step 8 | Soft-defer per current v2.0 G3 pattern. Embeddings backfilled by hourly cron. No founder alert (handled normally). |

## HITL discipline

- Default Tier A (additive writes; reversible via `/wiki merge --undo` if any entity is wrong).
- Tier B if cost-cap exceeded OR pending_review queue grows (founder daily digest).
- Tier C never — distill never makes irreversible writes (soft-delete only via merge).
