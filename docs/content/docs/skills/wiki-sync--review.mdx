# wiki-sync / review (v3.0)

## Khi nào skill này chạy

- Founder chạy `/wiki review` (tùy chọn `/wiki review --limit=N` hoặc `/wiki review --type=concept`).
- Cron hàng ngày `wiki-review-queue-digest` (09:00 ICT) kiểm tra count `pending_review`; nếu > 0, kích hoạt Telegram heads-up: "N extractions pending /wiki review."

## Đầu vào

- `limit` — xử lý tối đa N mục mỗi session (mặc định 10; founder có thể chạy nhiều session)
- `type` — bộ lọc `page_type` tùy chọn (concept / observation / decision / idea)
- `min_confidence` / `max_confidence` — bộ lọc khoảng tùy chọn (mặc định 0.6-0.85)
- `source_page_id` — tùy chọn: chỉ review các extraction từ một nguồn cụ thể

## Đầu ra

- Với mỗi mục được review: UPDATE `knowledge_extractions.founder_decision` + `founder_reviewed = true` + `founder_reviewed_at = now()`
- Nếu extraction cuối cùng của mục chuyển khỏi pending: UPDATE `knowledge_pages.review_state = 'founder_approved'` (nếu tất cả accepted) HOẶC `'founder_rejected'` (nếu tất cả rejected)
- Nếu founder chọn "merge": dispatch đến skill `wiki-sync/merge` (Sprint 4)
- Nếu founder chọn "edit": mở tệp Markdown wiki trong $EDITOR (hoặc đưa nội dung lên để edit inline); UPDATE tệp + re-INSERT row knowledge_extractions đã sửa
- Một row `ops.agent_runs` tóm tắt các quyết định trong session này

## Quy trình

### Bước 1 — Xây queue

```sql
WITH pending_extractions AS (
  SELECT
    ke.id AS extraction_id,
    ke.derived_page_id,
    ke.source_page_id,
    ke.confidence,
    ke.raw_quote,
    ke.llm_model,
    dp.slug AS derived_slug,
    dp.page_type AS derived_type,
    dp.title AS derived_title,
    sp.slug AS source_slug,
    sp.title AS source_title,
    sp.source_kind,
    sp.frontmatter->>'license_status' AS license_status
  FROM ops.knowledge_extractions ke
  JOIN ops.knowledge_pages dp ON dp.id = ke.derived_page_id
  JOIN ops.knowledge_pages sp ON sp.id = ke.source_page_id
  WHERE ke.founder_reviewed = false
    AND ke.confidence BETWEEN $min_conf AND $max_conf
    AND dp.deleted_at IS NULL
    AND ($type_filter IS NULL OR dp.page_type = $type_filter)
    AND ($source_filter IS NULL OR ke.source_page_id = $source_filter)
  ORDER BY ke.created_at ASC
  LIMIT $limit
)
SELECT * FROM pending_extractions;
```

Cũng bao gồm các mục dedup-queue (cấp trang `review_state='pending_review'` với `frontmatter.pending_merge_candidate_id` được set).

### Bước 2 — Review từng mục (vòng lặp)

Với mỗi mục trong queue:

```
┌─ Pending review N of M ─────────────────────────────────────┐
│ Derived: <derived_type> / <derived_title>                   │
│ Confidence: <conf>  Model: <llm_model>                      │
│                                                             │
│ Extracted from: <source_title>                              │
│   (license: <license_status>)                               │
│                                                             │
│ Raw quote supporting this extraction:                       │
│   > "<raw_quote>"                                           │
│                                                             │
│ Current derived page summary:                               │
│   <first 200 chars of wiki/<type>/<slug>.md body>           │
└─────────────────────────────────────────────────────────────┘
```

Các tùy chọn AskUserQuestion:
1. **Accept** — extraction đúng như hiện trạng. UPDATE founder_decision='accepted'.
2. **Reject** — extraction sai. UPDATE founder_decision='rejected'. Nếu đây là extraction CUỐI CÙNG nối derived_page với source, founder quyết định có soft-delete derived_page không (prompt riêng).
3. **Edit** — extraction phần lớn đúng nhưng title/summary cần điều chỉnh. Mở Markdown trang derived để edit inline. UPDATE founder_decision='edited'.
4. **Merge** — thực thể này giống một thực thể hiện có. Dispatch đến `wiki-sync/merge`; founder chọn canonical slug.

Với các mục dedup-queue (pending merge cấp trang):
1. **Confirm merge** — đúng, chúng là cùng một thứ. Dispatch đến `wiki-sync/merge` với canonical = thực thể hiện có.
2. **Reject merge** — không, chúng riêng biệt. UPDATE cả hai trang: `review_state='founder_approved'`, clear `pending_merge_candidate_id` khỏi frontmatter.
3. **Skip for now** — để lại trong queue; session tiếp theo.

### Bước 3 — Rollup review_state cấp trang

Sau mỗi extraction được review, tính lại review_state cấp trang:
```sql
WITH ext_summary AS (
  SELECT
    derived_page_id,
    COUNT(*) AS total,
    SUM(CASE WHEN founder_reviewed = false THEN 1 ELSE 0 END) AS still_pending,
    SUM(CASE WHEN founder_decision = 'accepted' THEN 1 ELSE 0 END) AS accepted,
    SUM(CASE WHEN founder_decision = 'rejected' THEN 1 ELSE 0 END) AS rejected
  FROM ops.knowledge_extractions
  WHERE derived_page_id = $page_id
  GROUP BY derived_page_id
)
UPDATE ops.knowledge_pages SET review_state = CASE
  WHEN ext_summary.still_pending > 0 THEN 'pending_review'
  WHEN ext_summary.rejected = ext_summary.total THEN 'founder_rejected'
  ELSE 'founder_approved'
END
WHERE id = $page_id;
```

### Bước 4 — Tổng kết session

Sau khi tất cả các mục được xử lý (hoặc founder dừng qua `/skip-rest`):

```
✓ Review session complete:
  - N items reviewed
  - <accepted>/<rejected>/<edited>/<merged> decisions
  - <still_pending> remain in queue (run /wiki review again to continue)
  - Cost this session: $<cost>
```

Emit `ops.events`: `ritsu.wiki.review_session_completed` với tổng kết.

- **Digest Telegram hàng ngày** (cron `wiki-review-queue-digest`) là Tier A (Postgres chỉ đọc + gọi bot Telegram).
