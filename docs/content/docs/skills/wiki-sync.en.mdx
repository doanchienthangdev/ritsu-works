# Wiki Sync (umbrella)

## When to use

- Founder runs `/wiki sync <path>` → dispatches to `wiki-sync/ingest`.
- Founder runs `/wiki ask "<q>"` → dispatches to `wiki-sync/ask`.
- Founder runs `/wiki audit` → dispatches to `wiki-sync/audit`.
- Other agent calls `mcp__wiki__ask` → dispatches to `wiki-sync/ask`.

## Inputs

- `verb` — one of `sync` / `ask` / `audit` / `resync` / `list` / `status`.
- `args` — verb-specific args (see `.claude/commands/wiki.md`).

## Process

This skill is dispatcher-only. It reads the verb and delegates:

| Verb | Sub-skill | Purpose (v3.0) |
|---|---|---|
| `sync` (default = distill+extract) | `wiki-sync/ingest` | full pipeline (SOP-INGEST-001); Step 6 dispatches to `wiki-sync/distill` for entity extraction (Haiku for concept+idea; Sonnet for observation+decision); Step 7 dedup pass; multi-page write (source RECORD + N derived entities) |
| `sync --verbatim` | `wiki-sync/ingest` (verbatim path) | v2.0 fallback: single-page write, no distill, no entity pages. v3.1 auto-deprecation trigger: if invoked \< 1× in first 30 days post-promotion, flag removed in v3.1. |
| `sync --split=...` | `wiki-sync/ingest` + `wiki-sync/chapter-splitter` | Chapter split for big PDFs (TOC/count/heading); chapters feed distill independently |
| `sync --force` | `wiki-sync/ingest` with force=true | Re-extract everything; bypass chunk-diff |
| `resync` | `wiki-sync/ingest` | chunk-diff first; re-extract only changed chunks (v3.0 — Tier B if > 50% changed) |
| `distill` (alias) | `wiki-sync/ingest` | Same as `sync`; explicit verb for clarity |
| `extract --type=...` | `wiki-sync/distill` (selective) | Run extractor for one entity type only (concept/observation/decision/idea) |

| `list` | inline DB query (no sub-skill) | list wiki pages by type |

## Layout / Output (v4.0 source-grouped packages)

v4.0 (Sprint 1, 2026-05-18 onward) flips the on-disk layout from entity-type-grouped (`wiki/concept/<slug>.md`) to source-grouped packages — every ingest produces ONE folder under `wiki/<source-slug>/` containing the source RECORD and all derived entities extracted from it:

```
wiki/<source-slug>/
  source.md                          # source RECORD page (entity_type = book | article | episode | meeting | customer | ...)
  concepts/<concept-slug>.md         # derived concept entities (was wiki/concept/<slug>.md in v3.0)
  observations/<observation-slug>.md # derived observation entities
  decisions/<decision-slug>.md       # derived decision entities
  ideas/<idea-slug>.md               # derived idea entities
  chapters/chapter-NN-<slug>.md      # chapter slices for split books / long Markdown
```

**Composite UNIQUE rule (v4.0):** slug uniqueness is now composite `(extracted_from_source_id, slug)` for derived entities; source RECORDs keep global slug uniqueness. So `wedge` may legitimately exist as both `wiki/pg-do-things/concepts/wedge.md` AND `wiki/blank-4-steps/concepts/wedge.md` — different sources, different entities.

**`wiki/_index/`** (added in Sprint 2): reverse-lookup link-lists per entity type and slug — e.g., `wiki/_index/concept/wedge.md` lists every package containing a `wedge` concept page. The `_index/` tree is DERIVATIVE (regenerated by the `wiki-sync/index-rebuild` skill from `ops.knowledge_pages` + `ops.knowledge_extractions`); not a canonical entity store. `wiki-sync/audit` excludes it from orphan checks.
