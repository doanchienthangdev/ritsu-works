# wiki-sync / dedup (v3.0)

## Khi nào skill này chạy

- Được gọi bởi `wiki-sync/ingest` Bước 7 sau khi `distill` hoàn tất cho MỘT source.
- Được gọi bởi `wiki-sync/adapters/folder-adapter` sau khi TẤT CẢ file trong một folder hoàn tất distill cá thể, để aggregate các concept liên paper.
- CHỈ chạy khi `feature-flags.yaml::wiki_sync_distill_enabled = true` (ở chế độ `--verbatim` không có gì để dedup).

## Đầu vào

- `derived_entity_ids` (mảng uuid) — các dòng `ops.knowledge_pages` vừa được INSERT từ pass distill của source này
- `corpus_scope` (text) — `"single_source"` (Bước 7 từ ingest) HOẶC `"folder_aggregation"` (end-of-batch của folder-adapter)
- `existing_corpus` (filter tùy chọn) — mặc định, dedup so với TẤT CẢ các trang entity không bị xóa trong `ops.knowledge_pages` có `page_type` khớp

## Đầu ra

- Cho các match auto-merge (sim > 0.92): UPDATE `knowledge_extractions.derived_page_id` rewire từ duplicate sang canonical; soft-delete duplicate qua `knowledge_pages.deleted_at = now()`
- Cho các match queue (0.75-0.92): UPDATE duplicate `knowledge_pages.review_state = 'pending_review'` (founder thấy trong queue `/wiki review`)
- Cho distinct (\< 0.75): không thay đổi
- Một dòng `ops.agent_runs` tổng kết các match tìm được + action đã thực hiện
- Một dòng trong `ops.events` (`event_type='ritsu.wiki.dedup_completed'`)

## Quy trình

### Bước 1 — Fast path slug-equality

Với mỗi `derived_entity` trong `derived_entity_ids`:
```sql
SELECT id FROM ops.knowledge_pages
WHERE page_type = $derived_entity.page_type
  AND slug = $derived_entity.slug
  AND id <> $derived_entity.id
  AND deleted_at IS NULL
  AND legacy_v2_verbatim = false;
```

Nếu một dòng match (entity cũ hơn có cùng slug):
- **MERGE**: đây chắc chắn là duplicate (cùng canonical slug).
- Rewire `knowledge_extractions`: `UPDATE ops.knowledge_extractions SET derived_page_id = $existing_id WHERE derived_page_id = $derived_entity.id`
- Soft-delete duplicate mới: `UPDATE ops.knowledge_pages SET deleted_at = now() WHERE id = $derived_entity.id`
- Xóa file wiki: `rm wiki/<page_type>/<slug>.md` (bản canonical sống tại file_path của trang hiện có)
- Log vào audit trail merge (Bước 5)

Slug-equality rẻ (b-tree lookup); luôn chạy trước.

### Bước 2 — Tương đồng vector (cosine_distance qua pgvector)

Với mỗi `derived_entity` KHÔNG match ở Bước 1:
- Tính embedding của `(title + 200 ký tự đầu của summary)` nếu chưa có trong `ops.knowledge_embeddings`
- Truy vấn các neighbor gần nhất:

```sql
WITH new_entity_emb AS (
  SELECT embedding FROM ops.knowledge_embeddings
  WHERE source_kind = 'wiki_page' AND source_ref = $derived_entity.slug
  LIMIT 1
)
SELECT kp.id, kp.slug, kp.title, kp.page_type,
       1 - (ke.embedding <=> (SELECT embedding FROM new_entity_emb)) AS cosine_similarity
FROM ops.knowledge_pages kp
JOIN ops.knowledge_embeddings ke ON ke.source_ref = kp.slug
WHERE kp.page_type = $derived_entity.page_type
  AND kp.id <> $derived_entity.id
  AND kp.deleted_at IS NULL
  AND kp.legacy_v2_verbatim = false
  AND (1 - (ke.embedding <=> (SELECT embedding FROM new_entity_emb))) > 0.75
ORDER BY cosine_similarity DESC
LIMIT 5;
```

### Bước 3 — Action dựa trên ngưỡng tương đồng

Với mỗi match trả về ở Bước 2:

| Similarity | Action |
|---|---|
| **> 0.92** | **AUTO-MERGE**: giống Bước 1 merge (rewire extractions, soft-delete duplicate, xóa file wiki). Founder KHÔNG được notify (đủ tự tin auto). |
| **0.75-0.92** | **QUEUE**: UPDATE `knowledge_pages.review_state = 'pending_review'` trên CẢ entity mới VÀ match hiện có. Insert gợi ý vào `knowledge_pages.frontmatter::jsonb` với `pending_merge_candidate_id = <existing_id>` để `/wiki review` biết surface cặp này. |
| **\< 0.75** | **DISTINCT**: không action. Entity mới giữ làm trang riêng. |

### Bước 4 — Aggregation ở mức folder (corpus_scope = 'folder_aggregation')

Khi folder-adapter gọi skill này ở end-of-batch:
- Group các derived entity theo `(page_type, slug)` trên TẤT CẢ file trong folder
- Với mỗi group có size > 1: auto-merge các duplicate trong folder thành MỘT trang canonical; tập `knowledge_extractions` của trang canonical cite tất cả file source trong folder
- Sau đó chạy Bước 2-3 với corpus `knowledge_pages` toàn cục (để bắt cross-folder duplicate từ các ingest trước)

Theo spec A7: extraction observation của từng paper vẫn gắn với paper source của nó; chỉ concept mới auto-aggregate. Discriminator: `page_type = 'concept'` → aggregate; `page_type IN ('observation', 'decision', 'idea')` → giữ per-source.

### Bước 5 — Merge audit trail

## Kỷ luật HITL

- Mặc định Tier A (UPDATE additive + soft-delete; tất cả reversible).
- Tier B khi:
  - Queue 0.75-0.92 tạo một entry `pending_review` — digest Telegram hằng ngày tổng kết
  - Founder chạy `/wiki review` để xử lý queue (mỗi lần một item)
- Không bao giờ Tier C (không có schema change; không có governance edit).

## Tại sao các ngưỡng này?

- **0.92**: match semantic high-confidence. Tỷ lệ false-positive \< 5% trên (title + summary[:200]) cho cohort các entity GTM/growth/marketing đã test. Auto-merging ở ngưỡng này hiếm khi gây bất ngờ cho founder.
- **0.75**: match semantic low-confidence. Dưới ngưỡng này, các entity thường thực sự distinct (ví dụ: "active learning" concept giáo dục vs "active learning" paradigm training ML). Trên 0.75 xứng đáng được mắt người xem.
- **Giữa 0.75-0.92**: queue review của founder. Theo kinh nghiệm đây là nơi các từ đồng âm và near-synonym sống. Review 1-2 phút mỗi cặp qua `/wiki review`.

Các ngưỡng này là điểm khởi đầu v3.0.0; founder có thể retune ở v3.0.1 nếu 10 distill đầu tiên cho thấy drift (xem test falsifiability Muse M1).
