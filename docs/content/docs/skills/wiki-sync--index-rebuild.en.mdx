# wiki-sync / index-rebuild (Sprint 2 of v4.0 revise — v0.1)

## When to use

- Founder runs `/wiki index rebuild` → dispatches here.
- Auto-triggered at the end of every `/wiki sync <path>` (since Sprint 2) so the index stays in sync without manual rebuild.
- Optional cron entry deferred to v4.1 (re-trigger condition b in spec.md §8).

## Inputs

- `wiki_root` — absolute path to `wiki/` folder (default: `<repo>/wiki/`).
- `dry_run` — bool, optional. If true, list the index files that would be written but don't write.
- `alias_resolve` — bool, optional (default `false`). When true, reads each entity page's frontmatter `aliases: [...]` array and adds each alias as a separate `_index/<type>/<alias>.md`. v0.1: feature-flag gated; default off (alias resolution at the DB level via `ops.knowledge_extractions` is more efficient if it lands).

## Process

### Step 1 — Walk wiki/ for derived entity pages

```
For each subdir D under wiki/:
  if D is `_index`         → skip (don't recurse into our own output)
  if D is `capabilities`   → skip (Phase 8 promoted specs, not entities)
  if D matches v4 layout (has source.md + at least one of {concepts, observations, decisions, ideas, chapters}/) :
    for type in {concepts, observations, decisions, ideas}:
      for each <entity-slug>.md under wiki/<D>/<type>/:
        parse frontmatter (type, slug, aliases?)
        record (page_type, entity_slug, source_slug = D, file_path)
```

### Step 2 — Group by canonical name

Canonical name = entity_slug (kebab-case). Alias resolution OPTIONAL:
- If `alias_resolve=false` (default): only the slug counts as canonical name.
- If `alias_resolve=true`: each `aliases:` entry from frontmatter also gets its own index file pointing at the same entities.

Group by `(page_type, canonical_name)`. Each group becomes one `_index/<page_type>/<canonical-name>.md` file with N link entries (one per package).

### Step 3 — Generate index files

For each group, write `wiki/_index/<page_type>/<canonical-name>.md`:

```markdown
---
type: index
page_type: <concept|observation|decision|idea>
canonical_name: <name>
generated_by: wiki-sync/index-rebuild
generated_at: <iso8601>
package_count: <N>
---

# `<canonical_name>` — appears in <N> packages

Reverse-lookup link-list. This page is **derivative** — regenerated by
`/wiki index rebuild`. NEVER hand-edit. Excluded from `/wiki audit` orphan checks.

## Packages

- [<source_title> (`<source-slug>`)](../../<source-slug>/<page_type>s/<entity_slug>.md)
- [<another source>](../../<other>/<page_type>s/<entity_slug>.md)
- ...
```

The `<source_title>` is read from `wiki/<source-slug>/source.md` frontmatter. If unavailable, use the source-slug as fallback.

### Step 4 — Cleanup orphaned index files

After generating new index files, walk `wiki/_index/` and `rm` any file whose `(page_type, canonical_name)` wasn't in this run's set. Orphaned indexes accumulate otherwise as entities are deleted.

### Step 5 — Verify

Final sanity:
- `wiki/_index/{concept,observation,decision,idea}/` directories exist (created if absent).
- At least 1 file per type subfolder (only if there's at least 1 derived entity of that type in the corpus).

## Failure modes

| Symptom | Response |
|---|---|
| `wiki/` not found | Bail `wiki_root_missing`. |
| Frontmatter parse error on an entity page | Skip that page; record in skipped[] but continue. Surface count > 0 to founder. |
| File I/O error writing `_index/` | Bail with the path that failed; partial-state cleanup left to caller. |

## v0.2+ extensions

- Read aliases via `ops.knowledge_extractions.derived_aliases` column (if added in v4.1).
- Score packages by entity confidence (the highest-confidence appearance bubbles to top of the link-list).
- Optional `--type=<page_type>` flag to rebuild only one type's index.
