## When to use

Invoked by `resolver/orchestrator` when subcommand is `query`.

Operator-facing wrapper around `scripts/resolver/query.cjs`.

For **agent-to-agent** consumer use, invoke `resolver-query` (the consumer-
contract skill) instead; this skill is for operator-facing `/resolver
query "\<trigger>"` invocations.

## Process

1. Receive parsed args (trigger string + flags: --semantic, --plan, --json,
   --role, --kind)
2. Call `require('scripts/resolver/query.cjs').query({...})`
3. Render output:
   - Default (human): `[decision] <matched-id> conf=N latency=Nms\n  alternatives:\n  invocation: ...`
   - `--json`: pretty-print JSON
4. Write audit (via audit.cjs) — best-effort; defer on DB unreachable

## Error handling

Per `scripts/resolver/errors.cjs`:
- `InvalidTrigger` → print "Trigger required" usage
- `ResolverDown` → print "Resolver not initialized" + remediation
- All others → print error.code + message + suggested action
