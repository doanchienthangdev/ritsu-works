# Synthesize Morning Brief

> Reader skill for the daily founder brief. The brief is **produced server-side**; this skill **reads** it.

## Architecture

```
05:45 ICT daily ──► pg_cron fires `morning-brief-assembly`
                        │
                        ▼
                  scheduled-run-dispatcher Edge Function
                        │
                        ▼
                  minion-worker picks up scheduled_run row
                        │
                        ▼
                  makeSynthesizeMorningBriefHandler(deps)
                  → Anthropic Messages API (claude-haiku-4-5)
                        │
                        ▼
                  ops.agent_runs row inserted:
                    state: completed
                    skill: synthesize-morning-brief
                    output_payload.text: <4-bullet brief>
                        │
                        ▼
                  Founder opens `/ceo` later that day
                        │
                        ▼
                  CEO command reads THIS skill
                        │
                        ▼
                  Skill queries ops.agent_runs for most recent
                  morning-brief row (within 12h)
                        │
                        ▼
                  Returns brief to CEO context
                        │
                        ▼
                  CEO presents to founder + adds Top-3-today framing
```

## What the skill does

1. Query `ops.agent_runs` for the most recent row where:
   - `state_payload.skill = 'synthesize-morning-brief'` (or the equivalent skill-identification field per `schedules.generated.ts`)
   - `state = 'completed'`
   - `ended_at > now() - interval '12 hours'`

2. If row exists:
   - Read `output_payload.text` (the 4-bullet brief from Anthropic)
   - Read `output_payload.input_tokens`, `output_tokens` (for cost reporting)
   - Read `fired_at` (when the cron triggered)
   - Return `{ brief, fired_at, cost_usd_estimate, freshness: 'fresh' }`.

3. If no fresh row (cron failed OR > 12h):
   - Surface the staleness explicitly
   - Return `{ brief: null, freshness: 'stale-or-missing', fallback: 'CEO synthesizes inline' }`
   - CEO's playbook Pattern 1 takes over

## Output shape

  "cost_usd_estimate": 0.0015,
  "freshness": "fresh" | "stale-or-missing",
  "fallback_required": false | true

## When CEO uses this skill

Per `06-ai-ops/workforce-personas/ceo/command.md` opening behavior:

```
On /ceo with no argument:
  1. Read CEO dossier last 7 days
  2. Read last 3 ops.run_summaries filtered by persona_slug='ceo'
  3. Read top 3 KPI deltas from ops.kpi_snapshots
  4. **Invoke synthesize-morning-brief skill** ← this skill
  5. Read attention_log + pending HITL approvals
  6. Output morning brief: top 3 candidate priorities (one line each)
  7. Ask: "Pick one, recommend mine, or other?"
```

The skill makes step 4 a one-line fetch instead of CEO synthesizing from raw data — saves ~3000 tokens of context and eliminates inconsistency between days.

## Freshness contract

- **Fresh** (\< 12h): present verbatim with one-line "from 05:45 brief" attribution.
- **Stale** (12-36h): present + warn + recommend CEO synthesize fresh inline.
- **Missing** (> 36h or never): cron is failing. Surface as a P1 alert to founder + return fallback signal.

## Failure modes

| Case | Skill behavior |
|---|---|
| Cron didn't fire (pg_cron down) | `freshness: stale-or-missing`; CEO synthesizes inline. Surface alert to founder. |
| Cron fired but Anthropic API errored | Same as above; check `ops.agent_runs.error`. |
| Multiple briefs in 12h window (cron duplicated) | Return most recent; log anomaly. |
| Brief text empty | Same as cron failure path. |
| ANTHROPIC_API_KEY missing | Cron handler degrades to placeholder text per worker.ts; skill returns placeholder + warning. |
