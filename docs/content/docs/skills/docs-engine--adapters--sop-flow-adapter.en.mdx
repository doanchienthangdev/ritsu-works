# docs-engine/adapters/sop-flow-adapter

## Input pattern

`0[0-9]-*/sops/SOP-*/flow.yaml` + adjacent `README.md` (if present)

## Output pattern

`docs/content/sops/<pillar-slug>/<sop-id>.mdx`
e.g. `docs/content/sops/06-ai-ops/SOP-AIOPS-001-capability-lifecycle.mdx`

## Process

1. Parse `flow.yaml` (it's all YAML, no markdown).
2. Extract `id`, `title`, `description`, `pillar`, `cost_bucket`, `trigger`, `steps`, `acceptance_criteria`, `failure_handling`, `integrates_with`, `audit`.
3. Compute `source_hash` of the yaml file.
4. Render MDX with sections:
   - **Overview** (description prose)
   - **Trigger** (kinds + authorized_roles + hitl_tier)
   - **Inputs** (yaml table)
   - **Steps** — Fumadocs `<Steps>` component, each step rendered as collapsible with `name`, `kind`, `skill`, `timeout`, `on_failure`, `outputs`
   - **Acceptance criteria** (checklist)
   - **Failure modes** (table)
   - **Cross-Bài-toán integration** (table)
   - **Audit** (one-liner)
5. Add Fumadocs frontmatter:
   - `title: <sop-id>: <title>`
   - `description: <description>`
   - `pillar: <pillar-slug>`
   - `cost_bucket: <bucket>`
   - `status: <derived from pillar.stage_status>` (deep / lite / skeleton)
6. Add idempotency marker.

## Edge cases

- SOP yaml may have multi-line strings (`|` literal blocks) — preserve formatting.
- Some SOPs reference other SOPs in `integrates_with` — render as Fumadocs internal links.
- Adjacent `README.md` (if present) → prepend as "Operator Notes" section before the structured spec.
