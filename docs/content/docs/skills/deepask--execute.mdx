## Khi nào sử dụng
- Được gọi bởi `deepask/orchestrator` (Stage 3), once per sub-need, fanned out in parallel.

## Đầu vào
- `sub_need` (text + ia_type) và its `ResolverPlan v1` (`content_axis`, `capability_axis`, `governance_constraints`, `goal_metrics`, `no_coverage`). Mỗi `capability_axis` entry carries `hitl_tier` + `side_effect` (from resolver-plan enrichment).

## Quy trình — READ legs (`content_axis`)

### 1. Đọc mỗi `content_axis` recipient
Cho mỗi entry, dispatch the read per the recipient's `invoke` contract:
- `page/<slug>` → `Read("<path>")` · `wiki/<slug>` → `mcp__supabase-ops__wiki_ask` / `wiki_get_page`
- `view/<schema>__<name>` hoặc `metric/<id>` → `mcp__supabase-ops__query` (SELECT)
- `external-source/<id>` → per the entry's invoke pattern (read-only)
- gbrain (derived-memory) → `mcp__gbrain__{search,recall,traverse}` — **ưu tiên cheap `search`/`recall` hơn `think`**; respect the $100/mo cap (degrade gracefully if capped → record như là a gap, đừng fail the run).

### 2. AUTHOR the concrete call, grounded trong schema (the crux)
deepask KHÔNG receive pre-written SQL. Cho một `view`/`metric` read:
- Nếu the plan carries `columns_hint`, sử dụng nó directly.
- Else **đọc the DDL first** (`supabase/migrations/*.sql`) hoặc the metric def (`knowledge/kpi-ownership.yaml#<id>`) — then compose the SELECT. **NEVER invent a column name** (CLAUDE.md operating principle 3).
- `mcp__supabase-ops__query` is read-only by tool contract (SqlGuard rejects writes). Sử dụng the plan's `grounding_ref` để know what to read before writing.
- Worked example (MRR MoM): plan → `content_axis:[metric/mrr]`, `grounding_ref: kpi-ownership.yaml#mrr` (source `ops.kpi_snapshots`) → read grounding → write `SELECT date_trunc('month',ts), value FROM ops.kpi_snapshots WHERE kpi_id='mrr' …` → run → return evidence + the SQL + freshness.

Cùng authoring principle áp dụng cho every recipient: deepask frames the precise `wiki_ask` question / gbrain query / read params itself, grounded trong the recipient's contract.

## Quy trình — RUN legs (`capability_axis`)

### 3. Gate every capability leg (the read-vs-RUN rule)
Classify mỗi `capability_axis` recipient với the deterministic gate, then act trên `action`:
```js
const { classifyCapabilityLeg } = require('scripts/deepask/capability-gate.cjs');
const { action, reason } = classifyCapabilityLeg({ hitl_tier, side_effect }); // from plan enrichment
```
- **`auto_run`** (Tier-A, `side_effect: none`) → run it now. deepask AUTHORS the invocation (frames the precise skill params / `gbrain.think` prompt / tool args, grounded trong the recipient's contract trong `mcp-tools.yaml` / SKILL.md). Typical: `cost-report`, `thinking-toolkit/*`, `wiki_ask`, gbrain reads, `experiment-analyst`, `synthesize-morning-brief`.
- **`surface`** (Tier-B+, hoặc bất kỳ declared side effect nào) → **KHÔNG run.** Append tới `surfaced_capabilities[]` cho the orchestrator để present như là một HITL-gated suggestion ("để answer fully I'd run X (Tier B) — approve?"). Founder approval is required before bất kỳ side-effecting capability nào runs; deepask never auto-runs nó.
- **`refuse`** (Tier D-MAX) → never run, never surface như actionable. Record a gap (`gap_reason='not_built'`, `remedy="X requires D-MAX — beyond deepask's read/synthesize remit"`) so the answer is honest về the boundary.

### 4. Web leg → delegate to `deep-research`
Nếu một sub-need genuinely needs the **external web** (internal sources insufficient), delegate that leg tới the `deep-research` skill — deepask never web-searches directly (internal-first). Treat deep-research's cited report như một evidence source (`authority: SoR-external`, `freshness: live`).

## Cross-leg guards (READ + RUN)

### 5. Firewall (hard, always)
**Product data ONLY via `metrics.*` views** (the ETL mirror). NEVER query `product.*` / the product Supabase directly — the `pre-tool-supabase-product` hook blocks it (D-MAX). Nếu một sub-need seems to need product data not trong `metrics.*`, đó là một honest gap (`gap_reason='not_built'`, `remedy="expand the metrics.* ETL"`), không là một firewall bypass.

### 6. gbrain cap + cost
gbrain reads AND capability runs count against the global $100/mo cap (`pre-budget-check.sh`). Ưu tiên cheap `search`/`recall` hơn `think`; nếu the cap is hit, degrade gracefully (record a gap, đừng crash). Mỗi leg logs tới `ops.cost_attributions` (cost-bucket `ai-ops-deepask`).

### 7. Bounded self-correction
On a query/tool error: inspect → re-read the schema/DDL → retry **once** → else emit an honest `no_coverage` cho that leg ("can't safely query X — schema mismatch"). **NEVER fabricate a result row.** A partial failure của one leg must not sink the whole run.

## Ràng buộc
- **No routing** — execute runs the plan it's given; nó never decides WHICH recipient (resolver-plan did).
- **Auto-run Tier-A only**; surface Tier-B+; refuse D-MAX. Mỗi claim carries một `source_ref` (no uncited evidence reaches synthesis).
- Subscription billing trong session; gbrain dưới cap; API key out-of-band only.

## HITL / chi phí
Tier A cho the read legs + auto-run Tier-A capability legs. Tier-B+ capability legs are **surfaced** cho founder approval (never auto-run). Cost-bucket `ai-ops-deepask` + capped gbrain reads.
