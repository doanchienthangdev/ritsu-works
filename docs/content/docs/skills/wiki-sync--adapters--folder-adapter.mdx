# wiki-sync / adapters / folder-adapter (baseline Sprint 2 PR3 — v2.0.0)

## Khi nào adapter này chạy

Được điều phối bởi `wiki-sync/ingest` Bước 1 khi tham số `<path>` truyền vào `/wiki sync` là một thư mục (tức là `fs.statSync(path).isDirectory() === true`). 5 adapter còn lại đều yêu cầu file đơn lẻ; đây là adapter DUY NHẤT tiêu thụ input dạng thư mục.

source_kind: `folder_collection`
entity_type cho các con: được dẫn xuất theo từng file (mỗi adapter của file tự quyết định)
wiki target cho các con: `wiki/<col-slug>/<child-slug>/source.md` (layout source-grouped v4.0 — loại bỏ pattern flat-slug `<col-slug>__<file-slug>`; mỗi con được đặt tại đường dẫn package lồng nhau sạch sẽ dưới slug của collection)

## Inputs

- `path` — đường dẫn tuyệt đối đến một thư mục dưới `raw/<topic>/<folder>/`
- `entity_type_override` — tùy chọn; nếu được truyền, ép buộc TẤT CẢ các con dùng page_type này
- `force` — bool; truyền xuống mỗi lần ingest của con
- `depth` — int, tùy chọn. **v4.1** BFS max depth (thư mục gốc = depth 0). Mặc định 3. Hard cap 10. CLI: `--depth=N`.
- `max_nodes` — int, tùy chọn. **v4.1** Ngân sách BFS folder-node (số thư mục tối đa được duyệt). Mặc định 20. Hard cap 500. File trong một thư mục đã duyệt được ingest toàn bộ (không có cap theo từng file). CLI: `--max-nodes=N`.
- `out` — string, tùy chọn. **v4.2** tên thư mục namespace output (con của `wiki/`). Mặc định: slugify(basename(input)). Tự động thêm hậu tố `-1`, `-2`, … nếu `wiki/<name>/` đã tồn tại. CLI: `--out=<name>`.

### Bước 2 — Duyệt thư mục BFS (v4.1)

```pseudo
queue = [(rootPath, depth=0)]
packages = []        // [{folder_path, depth, files}]
folders_visited = 0
truncated = []

while queue not empty:
  if folders_visited >= max_folder_nodes:
    truncated = remaining queue       // ghi nhận nhưng KHÔNG ingest
    break

  (current, depth) = queue.shift()
  folders_visited += 1

  entries = readdir(current).filter(not .hidden)
  files = entries.files where extension in {.md, .markdown}
  subdirs = entries.dirs

  if files.length > 0:
    packages.push({folder_path: current, depth, files})   // leaf folder = một package

  if depth + 1 <= max_depth:
    for sub in subdirs:
      queue.push((sub, depth+1))
```

**Ngữ nghĩa:**
- "Node" trong ngân sách = folder node (không phải file). Mỗi lần dequeue thư mục tính 1 vào ngân sách.
- Một thư mục là "leaf folder" nếu nó chứa ít nhất 1 file markdown. Chỉ leaf folder mới trở thành package; các thư mục thuần cấu trúc (ví dụ `raw/5-star/` chỉ chứa thư mục con) được duyệt nhưng không tạo ra package.
- BFS đảm bảo hành vi "top-of-tree first" ổn định khi ngân sách bị áp lực. Khi ngân sách cạn, các thư mục sâu hơn / muộn hơn bị bỏ qua.
- Danh sách `truncated` được báo cáo trong output để founder biết những gì đã bị bỏ qua và có thể chạy lại với `--max-nodes=N` cao hơn để bao gồm chúng.

Nếu `packages.length === 0` sau khi duyệt: dừng lại với `empty_tree` kèm theo cài đặt ngân sách depth/node trong lỗi để có ngữ cảnh.

### Bước 2.5 — Resolve namespace (v4.2)

Sau khi BFS tìm được các package, resolve tên thư mục namespace:

- `namespace = slugify(--out value)` nếu cờ `--out` được truyền, ngược lại `slugify(basename(input))`.
- Nếu `wiki/<namespace>/` đã tồn tại, thử `<namespace>-1`, `<namespace>-2`, … cho đến `<namespace>-100`. Dừng lại với `namespace_too_many_conflicts` nếu cả 100 hậu tố đều đã dùng.
- Ghi lại namespace đã resolve + có bị đổi tên không (`was_renamed`, `suffix`) trong output để bên gọi thấy được.

Sau đó xác định chế độ layout:

- **Chế độ single-package** (collapse): nếu BFS tạo ra đúng 1 leaf folder ở depth 0 (tức là chính thư mục gốc input KHÔNG có thư mục con) VÀ `kebab-case(basename(input)) === namespace_original`, các file được đặt tại `wiki/<namespace>/<file>/source.md` — không có lớp col_slug bên trong. Dùng cho thư mục input đơn giản.
- **Chế độ multi-package**: bất kỳ trường hợp nào khác. Các file được đặt tại `wiki/<namespace>/<col-slug>/<file>/source.md` cho mỗi leaf folder được BFS phát hiện.

### Bước 5 — Điều phối theo từng file (thứ tự alphabet)

Với mỗi file được hỗ trợ:

1. Resolve adapter từ extension
2. Tính slug của file: `child_slug = derived-from-frontmatter-or-filename`
3. Đường dẫn source-grouped v4.0: RECORD nguồn con được đặt tại `wiki/<col_slug>/<child_slug>/source.md`. Trường slug của con trong `knowledge_pages` là `child_slug` (KHÔNG có tiền tố); tính duy nhất được đảm bảo bởi quy tắc composite `(extracted_from_source_id, slug)` + tính duy nhất slug toàn cục trên RECORD nguồn được giới hạn theo path. Đối với các thực thể được dẫn xuất dưới con, đường dẫn source-grouped tự nhiên đặt namespace cho chúng theo từng package.
4. Pre-check: phạm vi theo đường dẫn package — `SELECT 1 FROM ops.knowledge_pages WHERE file_path = 'wiki/<col_slug>/<child_slug>/source.md'`. Nếu tồn tại, log lỗi + tiếp tục (ngữ nghĩa partial-failure).
5. Acquire `ops.wiki_sync_lock(<file-page-type>, '<col_slug>/<child_slug>')`. Release tại COMMIT.
6. Gọi sibling adapter bình thường, nhưng inject:
   - `parent_job_id = <parent_id>` (từ Bước 4) — thêm vào row `ingestion_jobs` của con
   - `path_override = wiki/<col_slug>/<child_slug>/source.md` — bỏ qua việc dẫn xuất path mặc định của adapter (v4.0 thay thế pattern `slug_override = <col_slug>__<file_slug>` của v3.0)
7. Adapter trả về output bình thường; Bước 6-9 của ingest chạy cho mỗi con như thường lệ.

## Kỷ luật slug (v4.0 source-grouped)

Theo quyết định Tier C Hybrid B/A + việc lật layout source-grouped v4.0:
- v2.0/v3.0 dùng global UNIQUE flat slug `<col-slug>__<file-slug>`. v4.0 BỎ pattern này để chuyển sang đường dẫn package lồng nhau.
- Mỗi RECORD nguồn con sống tại `wiki/<col-slug>/<child-slug>/source.md`. Trường `knowledge_pages.slug` lưu `child-slug` (không phải dạng flat có tiền tố); composite UNIQUE `(extracted_from_source_id, slug)` cho phép cùng `child-slug` xuất hiện hợp lệ giữa các collection khác nhau (ví dụ, `attention` tồn tại trong cả `wiki/papers/attention/source.md` VÀ `wiki/ml-survey/attention/source.md`).
- BẢN THÂN COLLECTION KHÔNG có row knowledge_pages riêng trong v2.0/v4.0
  (row ingestion_jobs cha của folder-adapter là "collection" record duy nhất)
- v2.1 có thể thêm trang chỉ mục collection (tương tự như chapters index của chapter-splitter cho sách)
  + giá trị enum `'collection'` page_type
- Founder có thể khám phá các con qua tham chiếu `[[<file-page-type>/<child-slug>]]` được resolve trong package của collection, hoặc qua link-list reverse-lookup `wiki/_index/`.
