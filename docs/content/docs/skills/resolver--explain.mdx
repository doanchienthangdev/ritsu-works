## Khi nào dùng

Được invoke bởi `resolver/orchestrator` khi subcommand là `explain`. Gộp
`/resolver test` vào (architect simplification — cùng một verb, verbose hơn).

## Process

1. Parse trigger string (bắt buộc) + flags (--semantic tùy chọn)
2. Gọi `require('scripts/resolver/query.cjs').explain({...})`
3. Render verbose trace:
   - **NORMALIZED:** hiển thị trigger đã normalize
   - **KEYWORD HITS:** mỗi route, keyword nào trigger + confidence
   - **SEMANTIC** (nếu --semantic): embedding namespace nào được query,
     top-N hits với cosine scores
   - **RANKING:** candidates đã sort (DESC theo confidence)
   - **ROLE FILTER:** caller role + routes nào bị filter ra
   - **DECISION:** silent/surface/no_match + threshold context
   - **PERFORMANCE:** load_ms, match_count, filtered_count, total latency

## Output template

```
NORMALIZED: "<normalized trigger>"

KEYWORD HITS (N):
  ✓ "<keyword>" matched in <route_id> (confidence X.X)
  ...

SEMANTIC: (skipped — flag not set | enabled with N top hits)

RANKING:
  1. <route_id>  conf=X.X
  ...

ROLE FILTER (caller=<role>):
  <route_id>  role_scope=[...] → retained | filtered
  ...

DECISION:
  top confidence X.X <vs/below> silent_dispatch threshold 0.85
  → <decision>

PERFORMANCE:
  load: Xms (cache hit / cold)
  match: Xms
  total: Xms
```
