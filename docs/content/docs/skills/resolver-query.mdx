## Khi nào dùng skill này

Invoke từ một skill, agent, hoặc workflow khác khi bạn cần tìm đúng AI workforce
recipient cho một natural-language task — không cần grep filesystem hay hardcode
lookups.

**Ba consumer modes — chọn theo context:**

### Mode A (PREFERRED — in-session ambient catalog)

Bạn đang vận hành bên trong một Claude Code session. Catalog
`knowledge/recipients/{skills,commands,agents,personas,mcps}.md` **đã được load**
trong ambient context qua `.claude/CLAUDE.md` imports.

→ **Bạn KHÔNG cần invoke skill này.** Bạn chỉ cần reason về trigger một cách
tự nhiên và identify primary + supporting recipients từ ambient context. Sau đó
invoke recipient trực tiếp (`Skill({...})`, `Agent({...})`, vv.).

Tùy chọn ghi audit row qua `audit.cjs` nếu quyết định quan trọng (ví dụ:
orchestration delegation).

**Latency:** 0ms additional. **Cost:** $0 (không có LLM call thêm).

### Mode B (Explicit — operator-facing, audit/debug)

User invoked `/resolver query "<trigger>"` hoặc programmatic skill call.

Steps:
1. Load catalog (`scripts/resolver-v2/catalog-loader.cjs#loadCatalog()`)
2. Format structured prompt:
   ```
   System: \<catalog as text — all 5 files concatenated, hoặc kind-filtered nếu --kind cho>
   User: Cho trigger "\<trigger>", return JSON:
     \{ primary: \<recipient-id>, supporting: [\<id>...], rationale: "...", alternatives: [\<id>...] }
   ```
3. Current session LLM (bạn, Claude) reasons → emits JSON
4. Validate IDs tồn tại trong catalog (`byId.has()`); reject hallucinations
5. Build audit record qua `audit.cjs#buildRecord` với `mode='B', llm_reasoning=\<rationale>, composition_supporting=[\<supporting>]`
6. Write audit qua `mcp__supabase-ops__insert` to `ops.resolver_decisions`
7. Return human-readable output

**Latency:** ~5-500ms (catalog load + LLM reasoning). **Cost:** $0 in-session
(no separate API call); cached system prompt nếu invoked multiple times.

### Mode C (Keyword fallback — non-LLM consumers only)

CRON jobs, Edge Functions, pre-commit hooks. Không có LLM trong loop.

Invoke `scripts/resolver-v2/keyword-fallback.cjs#match(\{trigger})` trực tiếp.
Single-recipient response. ~30% recall (acknowledged degradation vs Mode A).

Dùng cái này **CHỈ KHI** bạn không thể reach LLM context. Encourage migration
sang Mode A.

**Latency:** \<5ms. **Cost:** $0.

## Failure modes

| Code | Cause | Handling |
|---|---|---|
| `INVALID_TRIGGER` | nil/empty trigger | Throw; caller phải provide |
| `CATALOG_DOWN` | recipients/ missing | Throw; fix install |
| `CATALOG_PARSE_ERROR` | malformed markdown | Throw với file+line |
| `DUPLICATE_RECIPIENT_ID` | same id trong 2 files | Throw; manual fix |
| `MISSING_REQUIRED_FIELD` | catalog entry incomplete | Throw với entry ID |
| `HALLUCINATED_RECIPIENT` | LLM trả về unknown ID | Mode B retries 1 lần với stricter prompt |
| `AUDIT_WRITE_FAILED` | DB unavailable | Best-effort; warn nhưng không throw |
