## Khi nào dùng

Invoke từ một skill khác khi bạn cần tìm recipient AI workforce phù hợp
cho task được giao. Trả về metadata + invocation spec; BẠN execute
invocation đó.

Ví dụ:
- Một skill đang xử lý user input: "user muốn tìm brand voice guide" →
  resolver-query trả về `\{ matched: \{ route: \{recipient: \{kind: 'wiki',
  slug: 'brand-voice'}}, ... } }`
- Một agent đang làm multi-step task: cần dispatch sub-skill cho
  step 2 — dùng resolver-query để tìm skill phù hợp thay vì
  hardcode tên
- Một scheduled job: nhận trigger generic "do this customer thing"
  → resolver-query route tới skill customer-pillar phù hợp

## Cách invoke (programmatic — Node.js consumer)

```javascript
const { query } = require('scripts/resolver/query.cjs');
const result = query({ trigger: 'investigate customer churn' });

switch (result.decision) {
  case 'dispatch_silently':
    // Confidence ≥0.85; auto dùng top match
    const { recipient, invocation } = result.matched.route;
    // Execute invocation.args qua mechanism phù hợp
    break;
  case 'surface_candidates':
    // 0.60 ≤ confidence < 0.85; trình bày alternatives cho user hoặc rank thêm
    console.log('Top candidates:', result.alternatives.slice(0, 3));
    break;
  case 'no_match':
    // < 0.60; cân nhắc flag --semantic (v1.1) HOẶC ambiguous_fallback
    break;
  case 'role_denied':
    // Caller role không match route.role_scope
    break;
}
```

## Decision thresholds (mặc định v1.0 từ registry.yaml)

- **≥0.85** — `dispatch_silently` → dùng top match không cần prompt caller
- **0.60-0.85** — `surface_candidates` → trả về top-3 candidates cho caller chọn
- **\<0.60** — `no_match` → fall through tới ambiguous_fallback (hoặc --semantic ở v1.1)

Tunable theo `config.default_confidence_threshold` trong `knowledge/resolvers/registry.yaml`.
