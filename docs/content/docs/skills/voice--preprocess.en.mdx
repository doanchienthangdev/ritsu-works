This is the in-session, subscription-billed step that turns flat text into a great
read. The model (you) does two things and writes two artifacts.

## A — Author the voice-direction block → `instructions.txt`

Write a tight, vivid block in the same shape OpenAI's `instructions` field and Gemini's
style prefix expect (see `runtime/tmp/whisper-samples/` for canonical OpenAI examples).
Cover, in 4–8 short labeled lines, what fits the content:

- **Voice / Affect** — the persona (e.g. "a confident, upbeat brand voice"; "a calm late-night radio host"; "a patient teacher").
- **Tone & Emotion** — the feeling and its arc across the piece (rising excitement; steady reassurance; intimate warmth).
- **Pacing** — fold in `--pace` as words, not numbers (numeric speed is ignored by both engines): very-low → "very slowly, with generous pauses"; very-fast → "rapidly but intelligible".
- **Pauses** — where to breathe: after the hook, before the CTA, between list items, at section breaks.
- **Pronunciation / Emphasis** — crisp key terms; stress the benefit word; spell out tricky names/acronyms if needed.
- **Volume / Intonation** — gentle rises and falls; lean in on the punchline; soften the close.
- **Word choice / Do-nots** — e.g. "no slang" for news; "warm contractions" for conversational.

Make it **specific to THIS script**, not a template. Quality bar: it should read like a
director's note a voice actor could act on.

## B — Mark up the script for speech → the script text

Lightly edit the text so the engine *performs* it. Never change meaning; never add
content the source didn't have. Techniques:
- **Pauses for BOTH engines** — commas, em-dashes (—), ellipses (…), and **paragraph breaks** are the universal pause language. Break a wall of text into short paragraphs at natural beats.
- **Sentence length** — split run-ons into short, speakable sentences (ads/news especially).
- **Numbers, dates, symbols** — write how they're SAID ("$29/mo" → "twenty-nine dollars a month"; "Q3" → "Q three") when clarity benefits.
- **Gemini-only inline tags** (strip these for `--use=openai-tts`): `[pause]`, `[short pause]`, `[excited]`, `[whispers]`, `[sighs]`, `[laughs]`, `[very slow]`, `[extremely fast]`, `[sarcastic]`. Use sparingly and only when they serve the content.

## Long-form / multi-file consistency (v0.3)

When the input is long or a folder (it will be split into many chunks generated independently),
**author the voice-direction ONCE, before splitting, and make it UNIFORMITY-first** — not
expressive. Replace "expressive / dramatize" language with: "this is ONE continuous reading; keep
the SAME single narrator, the same steady volume, pace, and even tone for EVERY part; do not
re-characterize or change energy based on a passage's content." Apply that *same* block to every
chunk; keep markup minimal + identical (no per-chunk creative `[tags]`). `params.withConsistency()`
provides the canonical clause. (Loudness drift is fixed separately + deterministically by `loudnorm`
at stitch time — you don't need to address volume in the direction.)

## Engine notes

- **OpenAI (`openai-tts` / whisper)** — the block becomes the `instructions` field (≤4096 chars); the marked-up text becomes `input`. **Strip inline `[tags]`** (OpenAI reads them literally). Pace = words in `instructions`.
- **Gemini (`gemini-tts-3.1-flash`)** — `gen.cjs` prepends the block as a natural-language style prefix, then the marked-up text. **Inline `[tags]` are honored** (expressive on 3.1). Pace = words + an optional pace tag.

## Output contract

Write the authored block to `<run>/instructions.txt` (one block per input — the whole
input narrates in ONE consistent voice). Save the marked-up script (per chunk/file) where
the recorder reads it. Then hand the paths to `scripts/voice/run.cjs --instructions-file=…`
(inline) or to the per-unit `gen.cjs` calls (Workflow). When you do NOT author a block,
`gen.cjs` falls back to `params.buildFallbackInstructions(type, pace)` — the deterministic
floor, never the target.
