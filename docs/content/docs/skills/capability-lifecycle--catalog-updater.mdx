# Catalog Updater (CLA Phase 8)

## Khi nào sử dụng

- Sau Phase 7 transitions state tới `deployed`.
- Tất cả sprint PRs merged, final E2E passed.

## Inputs

- `capability_id`
- Tất cả artifacts trong `.archives/cla/<id>/`
- `ops.capability_runs` row
- `ops.cost_attributions` history

## Quá trình

### Step 1 — Tạo retrospective

Đọc cost data, compute actual recurring cost, tạo retrospective.md.

### Step 2 — Từ chối nếu retrospective.md thiếu

Nếu không tồn tại, ABORT.

### Step 3 — Promote artifacts tới wiki

Sao chép spec.md và retrospective.md.

### Step 4 — Update CATALOG.md

Append/update row cho capability.

### Step 5 — Update registry.yaml

Update entry với state=operating.

### Step 6 — Append boilerplate patterns

Nếu có generic patterns, thêm vào notes.

### Step 7 — Final pnpm check gate

Run pnpm check, ABORT nếu fails.

### Step 8 — Persist state

UPDATE ops.capability_runs tới operating.

### Step 9 — Final report

Gửi report tới founder.

## Outputs

- `.archives/cla/<id>/retrospective.md`
- Promoted spec.md và retrospective.md ở wiki
- Updated CATALOG.md và registry.yaml
- ops.events rows

## State transition

`deployed → operating`

## HITL

Tier A. Auto-advance.

## Failure modes

Retrospective missing, wiki collision, drift fails.
