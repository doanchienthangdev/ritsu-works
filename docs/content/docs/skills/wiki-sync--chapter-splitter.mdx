# wiki-sync / chapter-splitter (Sprint 2 baseline — v2.0.0)

## Khi nào skill này chạy

Được dispatch bởi `wiki-sync/ingest` Bước 5 khi BẤT KỲ điều nào sau đây đúng:
- `path` kết thúc bằng `.pdf` AND `pdf-adapter` báo cáo `pages_or_size_metric > 100`
- `path` kết thúc bằng `.md` hoặc `.markdown` AND kích thước file > 25 KB
- Founder truyền cờ `--split=<mode>` rõ ràng qua command `/wiki sync`

Skill này KHÔNG chạy với các file dưới ngưỡng AND không có cờ rõ ràng — file nhỏ ingest dưới dạng trang đơn.

## Đầu vào (từ caller — `wiki-sync/ingest`)

- `parent_job_id` — UUID của dòng `ops.ingestion_jobs` cho parent book/file
- `book_slug` — slug được derive cho parent (ví dụ: `make-it-stick`)
- `raw_text` — toàn bộ text đã extract (từ pdf-adapter hoặc markdown-adapter)
- `pages_or_size_metric` — số trang (PDF) hoặc kích thước byte (Markdown)
- `split_mode` — explicit `toc | count=N | heading=h2 | null` (null = pick default)
- `source_kind` — `book` (PDF) hoặc `markdown_passthrough` (large MD)
- `source_ref`, `source_hash` — pass through cho các dòng con

## Quy trình

### Bước 1 — Giải quyết split mode

Nếu `split_mode == null`, founder được prompt qua `AskUserQuestion`:
```
Split <book_slug> (<N> pages) into chapters?
  [a] toc      — use PDF bookmarks / MD headings (DEFAULT if bookmarks exist)
  [b] count=N  — equal parts (founder picks N)
  [c] heading=h2 — split per H2 heading
  [d] no split — ingest as single page (overrides threshold trigger)
```

Nếu founder chọn `(d)`, return `{split: false}` cho caller; caller tiếp tục với ingest trang đơn.

### Bước 2 — Phát hiện ranh giới chapter

#### Mode `toc`

**Với PDF:**
1. Dùng `pymupdf.open(path).get_toc()` để lấy bookmark tree.
2. Filter còn depth ≤ 2 (chapter; sâu hơn = section, bỏ qua).
3. Nếu TOC rỗng → log cảnh báo, fallback sang mode `heading=h2`.
4. Mỗi entry TOC → `(chapter_index, chapter_title, start_page, end_page)`.

**Với Markdown:**
1. Scan các dòng `## ` H2 (regex `^## (.+)$`).
2. Mỗi H2 → bắt đầu chapter mới; H1 frontmatter trước đó → chapter 0 nếu không rỗng.
3. Nếu không có heading H2 → fallback sang `count=N` với N=4 (founder confirm).

#### Mode `count=N`

Validate N ≥ 2 và N ≤ 50. Bail nếu ngoài khoảng.

**Với PDF:**
- `chapter_pages = ceil(pages / N)`.
- Slice `pages = [chapter_i * chapter_pages .. (chapter_i+1) * chapter_pages)` cho mỗi chapter.

**Với Markdown:**
- `chapter_bytes = ceil(size / N)`.
- Slice raw_text thành N chunk gần đều, snap về biên newline gần nhất để không paragraph nào bị chia giữa dòng.

#### Mode `heading=h2`

Cả PDF (sau extract) và Markdown — giống path MD của mode `toc`: phát hiện biên qua regex `^## (.+)$`.

### Bước 3 — Tạo slug cho chapter

Cho mỗi chapter (đánh số từ 1):
```
chapter_slug_raw = kebab-case(chapter_title) | "untitled"
chapter_slug_capped = chapter_slug_raw.substring(0, 40)  // 40-char cap
NN = zero-pad chapter_index, 2 digits  // 01, 02, ... 99
final_slug = `${book_slug}__chapter-${NN}-${chapter_slug_capped}`
```

Kỷ luật slug (v2.0 — theo ops.decisions hybrid B/A):
- Namespace UNIQUE toàn cục dùng chung với mọi slug knowledge_pages khác
- Pre-check: nếu `final_slug` đã tồn tại trong `ops.knowledge_pages`, abort với lỗi conflict (founder giải quyết qua cờ `--force` hoặc đổi tên thủ công)

### Bước 4 — Acquire advisory locks

Với mỗi chapter slug, acquire `ops.wiki_sync_lock('book', final_slug)`. Giữ tất cả lock cho đến khi mọi chapter row được commit. Nếu lock acquire block > 30s → abort toàn batch (rollback các dòng con đã insert).

### Bước 5 — INSERT các dòng ingestion_jobs con

Cho mỗi chapter, theo thứ tự deterministic (chapter_index ASC):

```sql
INSERT INTO ops.ingestion_jobs (
  source_kind, source_ref, source_hash, content_hash, state,
  current_step, parent_job_id, attribution, metadata
) VALUES (
  $source_kind, $source_ref, $source_hash,
  sha256($chapter_text),   -- content_hash differs per chapter
  'processing', 'chapter_split',
  $parent_job_id,           -- v2.0 migration 00030 column
  jsonb_build_object('chapter_index', $chapter_index, 'chapter_title', $chapter_title),
  jsonb_build_object('mode', $split_mode, 'pages', $chapter_pages, 'bytes', $chapter_bytes)
) RETURNING id;
```

Note: `source_hash` là GIỐNG NHAU trên tất cả chapter (đó là hash của file parent). UNIQUE partial index dedup từ migration 00027 keyed trên `source_hash` cho active state — vì đây là batch đơn, ta acquire mọi dòng trong một transaction để UNIQUE partial áp dụng cho state CUỐI ('completed'), không phải 'processing' trung gian. Nếu batch fail, rollback xóa hết dòng.

**Quan trọng:** content_hash PHẢI khác nhau cho mỗi chapter (sha256 của text chapter) để UNIQUE partial index thứ hai (`idx_ingestion_dedup_content_unique`) không flag duplicate trong batch.

### Bước 6 — Delegation per-chapter

Cho mỗi chapter row, delegate ngược về `wiki-sync/ingest` Bước 6-9 (extract + link-extract + embed + viết wiki + phát events + cost). Mỗi chapter trở thành:
- Một dòng `ops.knowledge_pages` riêng với `page_type='book'`, `slug=<final_slug>`,
  `file_path='wiki/<book-slug>/chapters/chapter-NN-<chapter-slug>.md'` (v4.0 source-grouped: chapter sống dưới package của parent book),
  `frontmatter.chapter_of=<book_slug>`, `frontmatter.chapter_index=<NN>`
- Các dòng `ops.knowledge_links` (extract từ nội dung chapter)
- Các chunk `ops.knowledge_embeddings` (hoặc `embeddings_deferred=true` theo G3)
- Một dòng `ops.events` (`ritsu.wiki.synced` cho mỗi chapter)

Wiki file layout (v4.0 source-grouped — các chapter nest bên trong package của parent book bên cạnh source.md và bất kỳ folder derived entity nào):

## HITL

- Tier A nếu `split_mode` được truyền qua cờ HOẶC threshold-triggered với default `toc`
- Tier B (founder confirm qua AskUserQuestion) nếu:
  - Mode TOC được yêu cầu nhưng bookmark rỗng → đề xuất fallback heading=h2
  - Markdown không có H2 → đề xuất fallback count=4
  - Ước tính chi phí > $1.50 (cap per-task-kind `wiki-ingest-pdf` × 1.5)

## Các chế độ lỗi

| Triệu chứng | Phản ứng |
|---|---|
| TOC rỗng | Cảnh báo + fallback heading=h2 (Tier B confirm nếu interactive) |
| heading=h2 tìm thấy 0 heading | Cảnh báo + fallback count=4 (Tier B confirm) |
| count=N với N\<2 hoặc N>50 | Bail với thông báo lỗi rõ ràng |
| Slug conflict trên chapter row | Bail toàn batch; founder có thể `--force` hoặc rename book_slug |
| Lock acquire timeout (>30s) | Bail; release lock; báo cáo concurrent-write conflict |
| Một số chapter row thành công, một số fail | Rollback tất cả (transactional batch); parent vẫn ở 'processing' |
| Ước tính chi phí > ngưỡng Tier B | Báo cáo cho founder; chờ approval trước khi tiếp tục |

## Nhắc nhở kỷ luật slug

Theo quyết định hybrid B/A v2.0 (KHÔNG nới lỏng UNIQUE `(page_type, slug)` — đó là v2.1):
- Slug chapter `<book-slug>__chapter-NN-<chapter-slug>` là GLOBAL UNIQUE
- Slug book-level index `<book-slug>` cũng là GLOBAL UNIQUE
- Hai cái này CHIA SẺ namespace slug toàn cục. Nếu `<book-slug>` collide với một slug knowledge_pages hiện có (ví dụ: một concept có cùng tên), founder phải rename book_slug — chapter-splitter abort.
- v2.1 có thể nới lỏng sang `(page_type, slug)` UNIQUE; điều kiện trigger trong `wiki/capabilities/wiki-sync-from-refs/spec.md` v2 §0.
