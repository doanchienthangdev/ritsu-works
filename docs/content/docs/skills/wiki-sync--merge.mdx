# wiki-sync / merge (semantics v3.0 → v4.0 đảo)

## Semantics merge v4.0 (Sprint 1, 2026-05-18 trở đi)

Layout source-grouped v4.0 thay đổi merge từ "pass tổng hợp mặc định" thành "bước tổng hợp cross-package rõ ràng". UNIQUE composite `(extracted_from_source_id, slug)` cho phép cùng một slug derived-entity tồn tại hợp lệ trong nhiều source package (ví dụ `wedge` được trích từ cả `pg-do-things/` và `blank-4-steps/`). Mặc định, distill không còn auto-merge cross-source; merge là thao tác do founder gọi khi các thực thể cùng slug nên được HỢP NHẤT thành một trang canonical trích dẫn tất cả các nguồn gốc. Semantics của `--undo`, soft-delete, và rewire citation đều được giữ nguyên từ v3.0.

## Khi nào skill này chạy

- Founder chạy `/wiki merge <canonical-slug> <duplicate-slug>` — ghi đè dedup rõ ràng.
- `/wiki merge <slug-a> <slug-b> --undo` — đảo ngược lần merge gần nhất của cặp này.
- `wiki-sync/review` dispatch khi founder chọn "merge" trên một mục pending_review.

## Đầu vào

- `canonical_slug` — slug SỐNG SÓT (giữ tệp + row DB + tất cả các extraction)
- `duplicate_slug` — slug CHẾT (soft-delete; các extraction được rewire về canonical)
- `undo` (bool) — đảo ngược merge

## Đầu ra

- UPDATE `ops.knowledge_extractions SET derived_page_id = <canonical_id> WHERE derived_page_id = <duplicate_id>` (rewire)
- UPDATE `ops.knowledge_pages SET deleted_at = now() WHERE slug = <duplicate_slug>` (soft-delete)
- DELETE tệp `wiki/<source-slug-loser>/<page_type>s/<duplicate_slug>.md` khỏi hệ thống tệp (đường dẫn source-grouped v4.0 — khi merge cross-package, source-slug của duplicate là package "loser"; canonical sống tại đường dẫn source-slug của winner dưới `wiki/<source-slug-winner>/<page_type>s/<canonical_slug>.md` và ở lại)
- INSERT row `ops.events` (`ritsu.wiki.merge_executed` hoặc `ritsu.wiki.merge_undone`)
- Thêm dòng "Merged from \<duplicate_slug>" vào section `## Sources cited` của trang canonical
- Re-embed trang canonical (summary giờ phản ánh nội dung đã merge; embedding cũ stale)

### Bước 2a — Merge tiêu chuẩn (KHÔNG --undo) — dọn dẹp v3.0.5

```sql
BEGIN;

-- v3.0.5 enhancement (was best-effort in v0.1): capture exact extraction_ids
-- BEFORE rewire so --undo can restore the precise mapping. Caller (merge
-- skill) reads this into $extraction_ids_rewired variable for the audit event.
SELECT array_agg(id) AS extraction_ids_rewired,
       COUNT(*) AS rewire_count
  FROM ops.knowledge_extractions
 WHERE derived_page_id = $duplicate_id;

-- Also capture the knowledge_links to rewire (for clean --undo)
SELECT array_agg(id) AS link_ids_rewired
  FROM ops.knowledge_links
 WHERE target_page_id = $duplicate_id;

UPDATE ops.knowledge_extractions
  SET derived_page_id = $canonical_id
  WHERE derived_page_id = $duplicate_id;

-- Soft-delete duplicate
UPDATE ops.knowledge_pages
  SET deleted_at = now(),
      review_state = 'founder_rejected'
  WHERE id = $duplicate_id;

-- Rewire knowledge_links pointing to the duplicate
UPDATE ops.knowledge_links
  SET target_page_id = $canonical_id
  WHERE target_page_id = $duplicate_id;

-- Audit event (v3.0.5: payload includes precise extraction_ids + link_ids for clean undo)
INSERT INTO ops.events (event_type, source, payload)
VALUES (
  'ritsu.wiki.merge_executed',
  'wiki-sync/merge',
  jsonb_build_object(
    'canonical_page_id', $canonical_id,
    'duplicate_page_id', $duplicate_id,
    'canonical_slug', $canonical_slug,
    'duplicate_slug', $duplicate_slug,
    'extractions_rewired', $rewire_count,
    'extraction_ids_rewired', $extraction_ids_rewired,  -- v3.0.5: exact array for undo
    'link_ids_rewired', $link_ids_rewired,              -- v3.0.5: exact array for undo
    'merged_by', 'founder',
    'merge_kind', 'manual'  -- or 'review_dispatch' if invoked from review skill
  )
);

COMMIT;
```

### Bước 2b — Undo (chế độ --undo)

```sql
BEGIN;

-- Find the most recent merge_executed event for this pair
SELECT payload->>'extractions_rewired' AS count,
       payload->>'merge_kind' AS kind,
       occurred_at
  FROM ops.events
 WHERE event_type = 'ritsu.wiki.merge_executed'
   AND payload->>'canonical_slug' = $canonical_slug
   AND payload->>'duplicate_slug' = $duplicate_slug
 ORDER BY occurred_at DESC
 LIMIT 1;

-- (If no match found, bail: "No prior merge found to undo")
-- v3.0.5: also read precise extraction_ids_rewired + link_ids_rewired from payload
-- for clean reversal (replaces v0.1 best-effort approximation).
SELECT payload->'extraction_ids_rewired' AS extraction_ids,
       payload->'link_ids_rewired' AS link_ids
  FROM ops.events
 WHERE event_type = 'ritsu.wiki.merge_executed'
   AND payload->>'canonical_slug' = $canonical_slug
   AND payload->>'duplicate_slug' = $duplicate_slug
 ORDER BY occurred_at DESC
 LIMIT 1;

-- Re-clear soft-delete on duplicate
UPDATE ops.knowledge_pages
  SET deleted_at = NULL,
      review_state = 'founder_approved'
  WHERE id = $duplicate_id;

-- v3.0.5 clean undo: rewire EXACTLY the extractions captured at merge time
-- (was approximate in v0.1). Only valid if merge_executed was emitted v3.0.5+
-- with extraction_ids_rewired array in payload.
UPDATE ops.knowledge_extractions
  SET derived_page_id = $duplicate_id
  WHERE id = ANY($extraction_ids_rewired_array);  -- precise undo via captured ids

-- Rewire knowledge_links back
UPDATE ops.knowledge_links
  SET target_page_id = $duplicate_id
  WHERE id = ANY($link_ids_rewired_array);

INSERT INTO ops.events (event_type, source, payload)
VALUES (
  'ritsu.wiki.merge_undone',
  'wiki-sync/merge',
  jsonb_build_object(
    'canonical_page_id', $canonical_id,
    'duplicate_page_id', $duplicate_id,
    'extractions_restored', array_length($extraction_ids_rewired_array, 1),
    'links_restored', array_length($link_ids_rewired_array, 1),
    'undone_at', now()
  )
);

COMMIT;
```

Sau đó:
- Phục hồi tệp wiki bằng cách đọc từ lịch sử git (tệp đã được commit trước merge; git checkout \<commit-before-merge> -- \<path>)
- Gỡ footer "Merged from X" khỏi trang canonical

**Enhancement v3.0.5 (merge vào v0.2 của skill này):** undo giờ chính xác qua mảng `extraction_ids_rewired` + `link_ids_rewired` trong payload event `merge_executed`. ## Các tình huống lỗi

| Triệu chứng | Phản ứng |
|---|---|
| Canonical và duplicate khác page_type | Bail. Merge cross-type không được phép trong v3.0 (concept và observation không phải cùng loại thực thể). |
| Duplicate đã được soft-delete | Bail với "Already merged. Use --undo to reverse." |
| Xóa filesystem lỗi (quyền, tệp đã biến mất) | Merge DB đã commit. Log cảnh báo. Founder chạy `git status` để xem chuyện gì xảy ra. |
| Undo không tìm thấy event merge trước đó | Bail với "No merge to undo for this pair." |
| Undo chạy nhưng body canonical vẫn có footer "Merged from" | Vấn đề đã biết v0.1: founder gỡ footer thủ công. v3.0.5 sửa. |
