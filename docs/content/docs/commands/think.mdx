### `/think flow [problem]`

Đề xuất quy trình multi-skill. Nếu cung cấp `[problem]`, điều chỉnh nhẹ; ngược lại hiển thị flow canonical.

Canonical flow (theo `06-ai-ops/skills/thinking-toolkit/README.md`):

```
ambiguous problem
       │
       ▼
  TOSCA framing  ─────►  measurable goal
       │                       │
       ▼                       ▼
  gap analysis            driver tree (if metric-driven)
       │                       │
       ▼                       │
  options enumerated           │
       │                       │
       ▼                       │
  MECE check ◄─────────────────┘
       │
       ▼
  2x2 synthesis (if 4+ options)
       │
       ▼

       │
       ▼
  pyramid-principle-output (structure)
       │
       ▼

       │
       ▼
  ship
```

### `/think tosca <problem>`

Gọi skill `thinking-toolkit/tosca-problem-framing` với `<problem>` làm input. Skill tạo ra một tài liệu T/O/S/C/A 1 trang. Agent viết output tới conversation; founder có thể tùy chọn `--to=<path>` để lưu vào file (v1.2 — deferred).

```
/think tosca "Why is free→paid conversion stalled at 8% despite 3x signup growth?"
```

→ Output: Trouble / Owner / Success criteria / Constraints / Actors theo template `tosca-problem-framing`.

### `/think mece [list]`

Gọi `thinking-toolkit/mece-decomposition-check`. Nếu cung cấp `[list]` làm inline arg, dùng trực tiếp; nếu không, áp dụng vào list-shaped output gần nhất trong conversation.

```
/think mece "fixed-cost: rent, salaries, software; variable-cost: stripe-fees, ad-spend, vendor-payments"
```

→ Output: Gate 2-test (overlap? exhaustive?) với gợi ý remediation nếu có.

### `/think pyramid [conclusion]`

Gọi `thinking-toolkit/pyramid-principle-output`. Cấu trúc lại một đoạn/lập luận thành dạng top-line-first. Cặp bắt buộc với `so-what-test`.

### `/think so-what [conclusion]`

Gọi `thinking-toolkit/so-what-test`. Buộc một kết luận phải sống sót qua hai lần lặp "so what?". Output: hoặc là một kết luận được tăng cường hoặc là action item bị thiếu.

### `/think 2x2 <axis-x> <axis-y>`

Gọi `thinking-toolkit/2x2-synthesis-matrix`. Vẽ 4+ item trên hai trục trực giao mà founder cung cấp.

```
/think 2x2 "founder-effort-required" "expected-MRR-uplift"
```

→ Output: ma trận 2x2 với item được đặt trong quadrant, cộng với insight + recommendation mỗi quadrant.

### `/think driver-tree <metric>`

Gọi `thinking-toolkit/driver-tree-decomposition`. Phân rã một target metric thành upstream driver qua 5 loại logic-tree (theo Conn & McLean Ch 3).

```
/think driver-tree "free_to_paid_conversion"
```

→ Output: cây hiển thị driver được phân rã, MECE-checked, với khuyến nghị hành động ở lá cây.

2. **Thêm một hàng** vào bảng "Subcommands" trên:
   ```

   ```

3. **Cập nhật `06-ai-ops/skills/thinking-toolkit/README.md`** với framework mới
   trong bảng "What's in this folder".

   pnpm resolver:sync --apply
   pnpm resolver:index

6. **Commit + PR + merge.** Không cần `/cla` ceremony nếu pure-additive (theo `/cla extend` HITL B threshold).
