Giao diện đầu vào cho năng lực voice-platform. Phân tích các cờ, điều khiển skill ô dù `voice`
(`06-ai-ops/skills/voice/SKILL.md`), báo cáo kết quả. **Cả hai engine đều đã được kiểm chứng

## Cách dùng
```
/voice "<text>" [flags]
/voice --file=<path> [flags]
/voice --folder=<dir> [flags]
```
Một tham số vị trí sẽ được tự động phân loại: một thư mục đã tồn tại → chế độ folder; một
tệp đã tồn tại → chế độ file; ngược lại là văn bản nội tuyến.

## Luồng (điều phối tới skill ô dù `voice`)
1. Phân tích các cờ (`params.cjs`); xác định đầu vào (text/file/folder); phân giải `--use` dựa trên `knowledge/voice-adapters.yaml`.
2. **Tiền xử lý** (skill `voice/preprocess`) — đọc nội dung trong ngữ cảnh của `--type`; soạn một voice-direction nhận biết nội dung (giọng, tông, cảm xúc, `--pace`, các khoảng dừng, ngữ điệu) → `instructions.txt`; đánh dấu nhẹ cho script (các khoảng dừng; `[tags]` của Gemini).
3. **Ghi âm** — đầu vào nhỏ/đơn lẻ → `node scripts/voice/run.cjs` (chia chunk → `gen.cjs` cho mỗi chunk → ghép lại). Đầu vào dài / folder → một **Claude Code Workflow** trải song song `preprocess → gen`, rồi `stitch.cjs`.
4. Báo cáo `{ok, file, chunks, cost_usd, model, voice, warnings[]}` — luôn nêu rõ các cảnh báo; khi gặp `not_built|breaker_refusal|api_error|input_error`, đưa ra lý do đã được phân loại.

## Ví dụ
```
/voice "Master any subject in days, not weeks. Try Ritsu free." --type=ads --pace=fast --voice=Puck
/voice --file=blog/active-learning.md --type=blog --voice=marin --format=mp3
/voice --file=lesson.md --type=educational --pace=low --gender=female --use=gemini-tts-3.1-flash
/voice --folder=scripts/episodes/ --type=podcast --voice=Charon   # one mp3 per file, mirrored
/voice "A bedtime tale…" --type=story --use=openai-tts --voice=ballad --format=wav
/voice "anything" --dry-run                      # author + cost estimate, no spend
/voice "x" --use=elevenlabs                       # → not_built (proves the registry)
```
