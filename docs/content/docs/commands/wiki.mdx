**v4.0 (Sprint 1 của v4 revise, 2026-05-18): LAYOUT source-grouped.** Source RECORD
nằm tại `wiki/<source-slug>/source.md`; các derived entity tại
`wiki/<source-slug>/{concepts,observations,decisions,ideas}/<entity-slug>.md`
(composite UNIQUE trong phạm vi source). Per-book chapters tại
`wiki/<book-slug>/chapters/chapter-NN.md`. Skill có thể chỉ định
`input = wiki/<source-slug>/` như một input package mạch lạc. Reverse-lookup
link-lists tại `wiki/_index/<page_type>/<canonical-name>.md` (Sprint 2;

## Workflow

### `/wiki sync <path>`

1. **Phát hiện adapter** — đọc `<path>`:
   - Nếu directory → `folder-adapter` (v4.1: BFS-đệ quy giới hạn bởi `--depth=d` mặc định 3, `--max-nodes=N` mặc định 20. v4.2: output lồng dưới `wiki/<namespace>/`, trong đó namespace = flag `--out=<name>` hoặc input basename đã slugify + suffix `-N` nếu trùng).
   - Ngược lại extension / pattern URL → một trong 5 file adapter trong `knowledge/ingestion-sources.yaml`
   - Bail với lỗi hữu ích nếu không có adapter nào khớp
2. **Prompt chapter-split** — nếu PDF > 100 trang HOẶC có flag `--split`, chạy skill `chapter-splitter` mà dùng `AskUserQuestion` để confirm split mode (`toc` / `count=N` / `heading=h2`). Các con nhận row `ingestion_jobs` riêng với `parent_job_id` (migration 00030 Block C).
3. **Acquire lock** — `SELECT ops.wiki_sync_lock(<entity_type>, <slug>)` (migration 00027) để ngăn ghi đồng thời.
4. **Dedup check** — compute `source_hash = sha256(ref_content)`; query `ops.ingestion_jobs WHERE source_hash = ? AND state IN ('completed')`. Nếu tồn tại và `--force` không được set, return "ref unchanged; wiki up-to-date".
5. **Chạy SOP-INGEST-001** — gọi skill 6-step pipeline thông qua `06-ai-ops/sops/SOP-INGEST-001-wiki-sync/`. Với đường dẫn markdown + folder, ưu tiên CLI helper `scripts/wiki-sync/ingest.cjs` (v2.0 PR3) cho các bước thiên về file deterministic; các bước LLM-touching ở lại trong session của lệnh này.
6. **Confirm tới founder** — in tóm tắt (loại entity, slug, số trang, cost) + link tới đường dẫn wiki đã ghi. Với folder ingest, cũng in bảng tóm tắt per-file.

### `/wiki get --src=<spec>` (v4.3)

Extract context được bundle từ một wiki source-grouped package. Output phù hợp để pipe vào prompt của lệnh khác HOẶC ghi ra file thông qua `--to=<path>`. **Không gọi LLM** — chỉ filesystem read + lắp ráp thuần tuý.

**Ngữ pháp source spec:**

| Spec | Resolve thành |
|---|---|
| `<source-slug>` | Full source: frontmatter của source.md + tất cả chapter + tất cả entity (giới hạn bởi `--max-entities`) |
| `<source-slug>/chapter-N` | File chapter N + tất cả entity với frontmatter `source_chapter_index: N` |
| `<source-slug>/chapter-NN-<slug>` | File chapter cụ thể (full filename) + các entity citing nó |
| `<source-slug>/<type>` | Tất cả entity của type (concepts \| observations \| decisions \| ideas) |
| `<source-slug>/<type>/<entity-slug>` | Một entity page (full body + frontmatter tuỳ chọn) |

**Workflow:**

1. **Parse spec** — split theo `/`; resolve source dir; bail nếu không phải v4.0 source package (không có `source.md`).
2. **Thu thập chapters** — dựa trên scope.
3. **Thu thập entities** — filter theo frontmatter `source_chapter_index` (cho spec chapter-N) hoặc theo file path.
4. **Lắp ráp bundle** — header (spec + source metadata) + inventory + frontmatter source RECORD + các chapter body + các entity body + footer provenance.
5. **Output** — ghi vào `--to=<path>` (tạo parent dir) HOẶC stdout. Dòng tóm tắt ra stderr.

**Định dạng output**: Bundle markdown bắt đầu bằng `<!-- wiki-context-bundle generated by /wiki get v4.3 -->` + các section H1/H2/H3 có cấu trúc. Mọi entity mang theo provenance (file path, chapter index, confidence, review state). Footer nhắc operator KHÔNG edit bundle trực tiếp.

**Cap mặc định**: 100 entity mỗi bundle (over-cap được báo cáo dưới dạng `dropped` count). Tăng thông qua `--max-entities=N`.

**Flags:**

- `--src=<spec>` BẮT BUỘC. Source spec.
- `--to=<path>` Tuỳ chọn. Output file path (tương đối với repo root hoặc tuyệt đối). Không có nó, in ra stdout.
- `--summary` Chế độ compact: chapter → chỉ outline; entity → chỉ paragraph đầu tiên.
- `--include-frontmatter` Bao gồm YAML frontmatter của entity trong output (mặc định: bị strip, chỉ key metadata trong header).
- `--max-entities=<N>` Cap số entity (mặc định 100). Các drop được báo cáo.

**Ví dụ:**

- `/wiki get --src=marketing-management-kotler/chapter-14` — in Kotler MM Ch 14 + 8 entity ra stdout
- `/wiki get --src=marketing-management-kotler/chapter-19 --to=.archives/cla/<id>/ch19-context.md` — bundle ra file để `/cla propose` tái sử dụng
- `/wiki get --src=principles-of-marketing-kotler --summary --max-entities=20` — outline cấp cao của toàn bộ cuốn sách
- `/wiki get --src=marketing-management-kotler/decisions/decision-ritsu-direct-marketing-engine-email-lifecycle` — full body của một decision entity

**Cost**: $0 (không gọi LLM; chỉ filesystem read thuần).

**Composition pattern**: paste output (hoặc đọc từ file `--to=<path>`) vào prompt của lệnh kế tiếp. Chuỗi citation của bundle được bảo toàn thông qua các trích đoạn frontmatter.

### `/wiki ask "<question>"`

1. **Embed câu hỏi** — OpenAI `text-embedding-3-small`.
2. **Retrieve** — hybrid search: vector top-K (k=10) + keyword (BM25) join, dedup, scored theo Bài #14 ranking (vector*0.5 + keyword*0.3 + backlink*0.2).
3. **Optional rerank** — nếu flag `--rerank` được pass (mặc định off vì cost), gọi OpenAI rerank model trên top 10.
4. **Synthesize** — gọi skill `wiki-sync/ask` mà compose câu trả lời với citation discipline nghiêm ngặt (mọi tuyên bố cite một wiki path + chunk anchor; nếu không thể cite, nói "no wiki coverage").
5. **Return** — câu trả lời + danh sách citation. KHÔNG BAO GIỜ fall back về dữ liệu training.

### `/wiki audit`

1. **Hash check** — mỗi `source_hash` của row `ops.knowledge_pages` được tính lại từ `source_ref`; flag nếu drift > 0.
2. **Link walk** — mỗi `ops.knowledge_links.target_page_id IS NULL` → orphan.
3. **Dead URL check** — mỗi source RECORD page (`wiki/<source-slug>/source.md`) với `source_kind='url_article'` → HTTP HEAD `source_ref`; flag nếu 4xx/5xx.
4. **Stale-claim sample** — ngẫu nhiên 10 % các page; LLM-evaluate "tuyên bố này còn nhất quán với source ref không?" (sample rẻ; full sweep quá đắt).
5. **Write report** — `.archives/wiki-audits/<date>.md` với độ chính xác per-defect file:line + tổng tỉ lệ defect.
6. **Nếu `--fix`** — cho mỗi fix class (orphan, dead, stale), mở một PR với đề xuất remediation.

## Defensive notes

- **Wiki edit là của founder**. Lệnh ghi các trang với marker `<!-- generated-by: wiki-sync vN -->`. Các trang KHÔNG có marker này (hoặc bị strip nó) được coi là founder-edited; re-sync warn và show 3-way diff.
- **Re-sync regenerate mặc định.** Single-source-of-truth: ref = source, wiki = projection. Nếu founder hand-edit một generated page, đó là exception yêu cầu `--merge` (v1.1+) hoặc chấp nhận cảnh báo.
- **Tất cả file path log vào `ops.agent_runs`**. Dễ dàng tìm "trang nào đến từ ref nào."
