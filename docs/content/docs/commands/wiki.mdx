# /wiki

Lệnh phạm vi dự án dành cho ritsu-works. Giao diện front-end cho capability wiki-sync
(`wiki-sync-from-refs`). Bộ điều phối mỏng — logic phase nằm trong các skill
dưới `06-ai-ops/skills/wiki-sync/`. Tuân theo cùng pattern orchestrator như
`/cla` (ủy quyền cho skill; quản lý các HITL gate; lưu trữ trạng thái).

**v3.0 (từ 2026-05-18 trở đi): semantic MẶC ĐỊNH = distill+extract.** Các file nguồn
trở thành RECORD pages; tri thức quan trọng (concept / observation / decision / idea)
được LLM trích xuất thành các entity page `wiki/<type>/<slug>.md` được chiếu riêng
với citation qua `ops.knowledge_extractions`. Flag `--verbatim` chuyển sang
hành vi verbatim-projection v2.0.

**v4.0 (Sprint 1 của v4 revise, 2026-05-18): LAYOUT source-grouped.** Source RECORD
nằm tại `wiki/<source-slug>/source.md`; các derived entity nằm tại
`wiki/<source-slug>/{concepts,observations,decisions,ideas}/<entity-slug>.md`
(composite UNIQUE bên trong source). Các chapter theo từng cuốn sách nằm tại
`wiki/<book-slug>/chapters/chapter-NN.md`. Skills có thể chỉ định
`input = wiki/<source-slug>/` như một gói input mạch lạc. Các link-list reverse-lookup
tại `wiki/_index/<page_type>/<canonical-name>.md` (Sprint 2;
được regenerate bởi skill `index-rebuild`, bị loại trừ khỏi check orphan của `/wiki audit`).

## Quy trình làm việc

### `/wiki sync <path>`

1. **Phát hiện adapter** — đọc `<path>`:
   - Nếu là directory → `folder-adapter` (v4.1: BFS đệ quy giới hạn bởi `--depth=d` mặc định 3, `--max-nodes=N` mặc định 20. v4.2: output lồng dưới `wiki/<namespace>/`, trong đó namespace = flag `--out=<name>` hoặc basename input đã slugify + suffix `-N` nếu xung đột).
   - Ngược lại extension / pattern URL → một trong 5 file adapter trong `knowledge/ingestion-sources.yaml`
   - Thoát với lỗi hữu ích nếu không adapter nào khớp
2. **Prompt chia chapter** — nếu PDF > 100 trang HOẶC flag `--split` được truyền, chạy skill `chapter-splitter` sử dụng `AskUserQuestion` để xác nhận chế độ split (`toc` / `count=N` / `heading=h2`). Các con có row `ingestion_jobs` riêng với `parent_job_id` (migration 00030 Block C).
3. **Lấy lock** — `SELECT ops.wiki_sync_lock(<entity_type>, <slug>)` (migration 00027) để ngăn ghi đồng thời.
4. **Check dedup** — tính `source_hash = sha256(ref_content)`; truy vấn `ops.ingestion_jobs WHERE source_hash = ? AND state IN ('completed')`. Nếu tồn tại và không set `--force`, trả về "ref unchanged; wiki up-to-date".
5. **Chạy SOP-INGEST-001** — gọi skill pipeline 6 bước qua `06-ai-ops/sops/SOP-INGEST-001-wiki-sync/`. Với markdown + folder paths, ưu tiên CLI helper `scripts/wiki-sync/ingest.cjs` (v2.0 PR3) cho các bước file-side xác định; các bước LLM nằm trong phiên của lệnh này.
6. **Xác nhận với founder** — in summary (entity type, slug, số page, chi phí) + link đến đường dẫn wiki đã ghi. Với folder ingest, cũng in bảng summary per-file.

### `/wiki ask "<question>"`

1. **Nhúng câu hỏi** — OpenAI `text-embedding-3-small`.
2. **Truy xuất** — hybrid search: vector top-K (k=10) + keyword (BM25) join, dedupe, chấm điểm theo Bài #14 ranking (vector*0.5 + keyword*0.3 + backlink*0.2).
3. **Rerank tùy chọn** — nếu truyền flag `--rerank` (mặc định tắt vì chi phí), gọi OpenAI rerank model trên top 10.
4. **Tổng hợp** — gọi skill `wiki-sync/ask` soạn câu trả lời với kỷ luật citation nghiêm ngặt (mọi claim đều cite một wiki path + chunk anchor; nếu không thể cite, nói "no wiki coverage").
5. **Trả về** — câu trả lời + danh sách citation. KHÔNG BAO GIỜ rơi về dữ liệu huấn luyện.

### `/wiki audit`

1. **Kiểm tra hash** — `source_hash` của mọi row `ops.knowledge_pages` được tính lại từ `source_ref`; cờ nếu trôi dạt > 0.
2. **Đi qua link** — mọi `ops.knowledge_links.target_page_id IS NULL` → orphan.
3. **Kiểm tra URL chết** — mọi source RECORD page (`wiki/<source-slug>/source.md`) với `source_kind='url_article'` → HTTP HEAD `source_ref`; cờ nếu 4xx/5xx.
4. **Mẫu stale-claim** — ngẫu nhiên 10% các page; LLM đánh giá "claim này vẫn nhất quán với source ref không?" (mẫu rẻ; full sweep quá đắt).
5. **Ghi báo cáo** — `.archives/wiki-audits/<date>.md` với độ chính xác file:line cho từng defect + tỷ lệ defect tổng.
6. **Nếu `--fix`** — cho mỗi class fix (orphan, dead, stale), mở một PR với đề xuất khắc phục.

## Lưu ý phòng vệ

- **Các chỉnh sửa wiki là của founder**. Lệnh ghi các page với marker `<!-- generated-by: wiki-sync vN -->`. Các page KHÔNG có marker này (hoặc đã bị xóa) được coi là founder-edited; re-sync cảnh báo và hiển thị 3-way diff.
- **Re-sync regenerate theo mặc định.** Single-source-of-truth: ref = source, wiki = projection. Nếu founder hand-edit một generated page, đó là exception cần `--merge` (v1.1+) hoặc chấp nhận cảnh báo.
- **Tất cả file path được log vào `ops.agent_runs`**. Dễ tìm "page nào đến từ ref nào."
