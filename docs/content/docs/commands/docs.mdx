## Quy trình làm việc

### `/docs scaffold` (scaffold lần đầu)

1. Xác minh `docs/` không tồn tại (hoặc rỗng).
2. Chạy `npx create-fumadocs-app docs/ --template next-mdx --lang vi` (hoặc tương đương).
3. Tuỳ chỉnh `docs/source.config.ts` để pull từ file system của ritsu-works thông qua 9 nguồn nội dung adapter.
4. Thêm `docs/lint-secrets.cjs` (redactor fail-loud 3 lớp).
5. Thêm `docs/app/api/raw/[...slug]/route.ts` (endpoint raw-MDX cho AI-runtime).
6. Thêm `docs/.vercelignore` để bỏ qua các thư mục không liên quan.
7. Sync đầu tiên: chạy `/docs sync --area=all` tự động.
8. Phát event `ritsu.docs.built`.

**Chi phí:** ~$0.50 LLM (chủ yếu là sinh boilerplate source.config.ts). Một lần mỗi repo.

### `/docs sync` (con ngựa thồ)

Điều phối đến skill `docs-engine/sync` mà nó orchestrate SOP-AIOPS-003 bước 1-10:

1. **Cổng trôi dạt** — `pnpm check`. Hủy nếu không sạch.
2. **Walker** — theo phạm vi Phase 1 Q3 (~215 nguồn).
3. **Redaction secret lớp 1** (kiểm tra walker-exclude).
4. **Điều phối adapter** — 9 adapter render theo loại nguồn.
5. **Redaction secret lớp 2** (regex scrub trên MDX).
6. **3-way diff** cho mọi trang có marker `<!-- generated-by -->` (CTO mod #1) — ngăn ghi đè lên sửa thủ công.
7. **Ghi MDX** vào `docs/content/`.
8. **Bộ xác thực coverage** — `pnpm check` (mà bây giờ chạy `validate-docs-coverage.cjs`).
9. **Phát events** — `ritsu.docs.synced` + có thể `ritsu.docs.drift_detected`.
10. **Snapshot KPI** — `docs_drift_count`.

**Chi phí:** ~$0.40-1.00 mỗi lần sync đầy đủ (215 trang × chi phí adapter ÷ batching). Cap per-task-kind: $1.

### `/docs translate` (v1.2)

Dịch incremental sang tiếng Việt. Dispatch các Claude Code subagent song song — không cần `ANTHROPIC_API_KEY` khi được gọi từ phiên Claude Code Desktop.

1. **Cổng trôi dạt** — `pnpm check`. Hủy nếu không sạch.
2. **Khám phá** — chạy `node scripts/verify-vi-translation.cjs --list-needs-translation`. Trả về hợp của:
   - File chưa được dịch: tỉ lệ dấu tiếng Việt trong body VI \< 3% (vẫn còn chủ yếu là tiếng Anh).
   - File cũ: `translated_source_hash !== source_hash` HOẶC `needs_retranslation: true` trong frontmatter.
3. **Batch** — gom nhóm theo category, chia thành các batch 6 file (batch nhỏ hơn giảm thiểu các lỗi metadata-flip do context-fatigue được quan sát trong v1.1.1).
4. **Dispatch** — một Claude Code subagent cho mỗi batch (`subagent_type: general-purpose`, `model: "haiku"`). Mỗi subagent:
   - Đọc từng file.
   - Dịch prose trong body sang tiếng Việt (bảo toàn frontmatter, code fence, inline code, identifier, JSX comment, ký tự escape, URL link).
   - Đặt `translated_at` thành hiện tại, `translated_source_hash` thành `source_hash` hiện tại, gỡ cờ `needs_retranslation`.
5. **Re-verify** — chạy lại verifier. Nếu còn file chưa dịch/cũ, dispatch agent tập trung cho các file cụ thể đó. Lặp tối đa 3 lần.
6. **Build cục bộ** — `cd docs && pnpm build`. Nếu thất bại, HỦY.
7. **Commit + push** — message điển hình: `feat(docs-engine): incremental translation — N files`.

**Chi phí:** ~$0-$9 (miễn phí qua subscription Claude Code nếu dispatch bên trong phiên Desktop; ~$0.05-0.15 mỗi file qua haiku API).

**Cap per-task-kind:** $5.

### `/docs check`

Tất định — không LLM. So sánh kho file system của phạm vi walker với MDX trong `docs/content/` (qua frontmatter `source_path`). Báo cáo:
- Trang thiếu (nguồn tồn tại nhưng không có MDX) → `docs_drift_count` ++
- Trang mồ côi (MDX không có nguồn) → `docs_drift_count` ++
- source_hash cũ (nguồn đã đổi nhưng MDX chưa được regenerate) → `docs_drift_count` ++

Thoát non-zero nếu `docs_drift_count > 0`. Được dùng bởi `.github/workflows/docs-check.yml` như cổng PR mềm (v1.0); cổng cứng trong v1.1.
