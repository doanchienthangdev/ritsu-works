# /check-drift

Lệnh phạm vi dự án dành cho ritsu-works. Chạy Cross-Tier Consistency Engine
đã được xây dựng qua các PR #1, #3, #4, #5, #6, #7, #8, #9 (xem git log + main).

## Lệnh này làm gì

Đây là phiên bản theo yêu cầu của cùng các check đã tự động chạy:
- **L1** — mỗi `git commit` (qua `.husky/pre-commit`)
- **L2** — mỗi PR/push (qua `.github/workflows/cross-tier-consistency.yml`)
- **L3** — mỗi đêm lúc 03:00 UTC (qua `pg_cron` khi đã bật, xem runbook)

Sử dụng lệnh này khi bạn muốn xác minh trạng thái *ngay bây giờ* mà không commit,
hoặc khi bạn muốn kích hoạt L3 live-DB sweep thay vì đợi đến 03:00.

## Các chế độ

| Cách gọi | Phạm vi | Thời gian | Chi phí |
|---|---|---|---|
| `/check-drift` | L1 + 3 L2 quan trọng (manifest↔DB, skills↔tables, schedules↔registry) | ~3s | $0 |
| `/check-drift --full` | + 2 validator mức cảnh báo (ROLES.md, HITL.md heuristic) | ~5s | $0 |
| `/check-drift --remote` | full + gọi L3 sweep ritsu-ops + đợi 75s + truy vấn kết quả | ~80s | ~$0 |

## Cách gọi

Chạy pnpm script bên dưới tại thư mục gốc dự án:

```bash
pnpm check               # chế độ mặc định
pnpm check:full          # thêm warn-tier
pnpm check:remote        # kích hoạt L3 (cần DISPATCHER_SECRET + SUPABASE_ACCESS_TOKEN cục bộ)
```

Sau đó tóm tắt output cho người dùng bằng các bullet rõ ràng:
- Cho mỗi section (L1, L2 critical, L2 warn nếu --full, L3 nếu --remote):
  - Liệt kê mỗi check là ✓ sạch HOẶC ✗ FAIL HOẶC ⚠ warn
  - Với mỗi failure, hiển thị 1-2 dòng đầu của thông báo lỗi của validator
- Cuối cùng: nêu kết luận tổng thể (ALL CLEAN / N CRITICAL drift / N WARN drift)
- Exit code 0 = sạch, 1 = critical drift (chặn CI), 3 = chỉ warn, 2 = lỗi script

## Khi nào nên đề xuất chạy

- Người dùng vừa chỉnh `knowledge/manifest.yaml`, `knowledge/cross-tier-invariants.yaml`,
  hoặc `knowledge/schedules.yaml` → gợi ý `pnpm check` trước commit
- Người dùng vừa thêm migration mới → gợi ý `pnpm check` để xác minh entry manifest tồn tại
- Người dùng vừa thêm skill mới → gợi ý `pnpm check` (bắt schedule references)
- Người dùng muốn xác minh live DB khớp với repo → gợi ý `pnpm check:remote`
