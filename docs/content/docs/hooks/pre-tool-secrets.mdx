# Hook: pre-tool-secrets

> Cưỡng chế danh sách cho phép giữa role và secrets trong `governance/SECRETS.md` và `governance/ROLES.md`. Một role chỉ được DÙNG các secrets được cấp phép tường minh cho nó.

## Hook làm gì

Trước khi một tool call phân giải bất kỳ biến môi trường nào được hậu thuẫn bởi secret, hook xác minh:

1. Role của agent CÓ entry trong `governance/ROLES.md`
2. Secret đang được phân giải PHẢI nằm trong danh sách `secrets` của role đó
3. Secret PHẢI nằm trong danh sách `used_by` của `governance/SECRETS.md` cho role này
4. Role hiện đang hoạt động (không phải bị deprecated)

Bất kỳ sự không khớp nào → chặn.

## Vì sao kiểm tra hai phía (ROLES + SECRETS)

Việc kiểm tra xem xét CẢ HAI file vì chúng có thể trôi dạt (drift):

- ROLES.md nói role X dùng secret Y, nhưng SECRETS.md không liệt kê role X dưới Y → thất bại (drift)
- SECRETS.md liệt kê role X dưới Y, nhưng ROLES.md không liệt kê Y dưới role X → thất bại (drift)

Bất kỳ trôi dạt nào cũng là bug quản trị. Hook fail closed và bắt buộc con người giải quyết.

## Logic ra quyết định

```
function decide(payload):
    role = payload.agent_role
    resolved_secrets = inspect_payload_for_secrets(payload)

    if not resolved_secrets:
        return allow()  # no secrets in this call

    # Load policy (cached, mtime-checked)
    roles_md = load_roles_yaml()
    secrets_md = load_secrets_md()

    role_def = roles_md.find(role)
    if not role_def:
        return block(reason=f"role '{role}' not defined in ROLES.md")
    if role_def.status == 'deprecated':
        return block(reason=f"role '{role}' is deprecated")

    role_allowed_secrets = set(role_def.secrets)

    for secret_name in resolved_secrets:
        # Check 1: ROLES.md says this role can use this secret
        if secret_name not in role_allowed_secrets:
            alert_security(payload, secret_name, role)
            return block(reason=f"role '{role}' not allowed secret '{secret_name}'")

        # Check 2: SECRETS.md says this secret is used by this role
        secret_def = secrets_md.find(secret_name)
        if not secret_def:
            return block(reason=f"secret '{secret_name}' not defined in SECRETS.md")
        if role not in secret_def.used_by:
            alert_security(payload, secret_name, role, kind="drift")
            return block(reason=f"drift: ROLES.md grants '{secret_name}' to '{role}' but SECRETS.md disagrees")

    return allow()
```

## Kiểm tra payload để tìm secrets

Hook cần biết tool call nào dùng những secrets nào. Các cách tiếp cận:

**Cách 1 — Cấu hình tĩnh (ưu tiên cho v0.2):**

Mỗi MCP server trong `mcp/servers.yaml` khai báo các tên biến môi trường mà nó tiêu thụ:

```yaml
email_sender:
  command: ...
  env_uses:
    - RESEND_PROD_TRANSACTIONAL_KEY
    - RESEND_PROD_MARKETING_KEY
```

Hook đọc khai báo này và coi tất cả env var được liệt kê là "secrets có thể được dùng bởi tool call này."

**Cách 2 — Kiểm tra lúc runtime (chính xác hơn, phức tạp hơn):**

Hook chặn tầng phân giải env-var của secret manager (1Password CLI, Doppler CLI, v.v.) và lấy danh sách thực tế các secret được fetch cho lần gọi này.

Spec v0.2 dùng Cách 1. Phiên bản v1.x có thể nâng cấp lên Cách 2.

## Các trường hợp đặc biệt

- **Secrets được truy cập bởi bản thân các hook:** hook đôi khi cần secrets riêng (ví dụ token Telegram bot để gửi cảnh báo bảo mật). Các hook KHÔNG chịu kiểm tra này — chúng là hạ tầng runtime đáng tin cậy. Ghi tài liệu mỗi hook dùng secrets nào trong frontmatter của spec.

- **Xoay (rotation) secret đang diễn ra:** trong quá trình rotation, cả secret cũ và mới có thể hợp lệ trong ~5 phút. Việc kiểm tra danh sách cho phép dùng TÊN secret, không phải giá trị, nên rotation không ảnh hưởng đến việc kiểm tra.

- **Role founder:** `founder` có `"*"` trong danh sách secrets theo ROLES.md. Hook coi `"*"` là "bất kỳ secret đã được định nghĩa nào" — nhưng secret vẫn phải tồn tại trong SECRETS.md. Không có secret ma.

- **Role mới được thêm:** nếu một PR thêm một role + việc sử dụng secret nhưng danh sách cho phép đã deploy chưa được làm mới, hook chặn dựa trên cấu hình cũ. Người vận hành phải redeploy hoặc chờ cache TTL.

## Phòng thủ theo lớp (defense in depth)

Hook này là một tầng. Các tầng khác:

- Secret manager giới hạn phạm vi tài khoản dịch vụ vào các vault cụ thể (không phải mọi secret đều hiển thị với mọi caller)
- Bản thân các MCP server xác minh phạm vi ở upstream (một restricted key của Stripe vẫn sẽ không cho phép refund ngay cả khi bị rò rỉ)
- Audit log bắt được lạm dụng theo kiểu hồi tố ngay cả khi việc chặn thời gian thực thất bại

Một kẻ tấn công có quyết tâm đã có được token tài khoản dịch vụ vẫn có thể bypass hook này trong một số kịch bản. Biện pháp giảm thiểu là xoay (rotation) nhanh (theo nhịp độ trong SECRETS.md) cộng với các tầng audit/cảnh báo.

```python
import yaml
from functools import lru_cache
from pathlib import Path

@lru_cache(maxsize=1)
def _load_roles(mtime: float):
    return yaml.safe_load(Path('governance/ROLES.md').read_text())

def load_roles():
    mt = Path('governance/ROLES.md').stat().st_mtime
    return _load_roles(mt)

# Similar for SECRETS.md ...

def decide(payload):
    role = payload['agent_role']
    secrets = inspect_payload_for_secrets(payload)
    if not secrets:
        return {'decision': 'allow', 'reason': 'no secrets in call'}

    roles = load_roles()
    role_def = next((r for r in roles if r['slug'] == role), None)
    if not role_def:
        return {'decision': 'block', 'reason': f"role '{role}' not defined"}

    allowed = set(role_def.get('secrets', []))
    if '*' in allowed:
        # founder; all defined secrets allowed
        defined_secrets = set_of_all_secrets_in_secrets_md()
        unknown = [s for s in secrets if s not in defined_secrets]
        if unknown:
            return {'decision': 'block', 'reason': f"unknown secrets: {unknown}"}
        return {'decision': 'allow', 'reason': "founder full access"}

    for s in secrets:
        if s not in allowed:
            alert_security(payload, s, role)
            return {'decision': 'block',
                    'reason': f"role '{role}' not allowed '{s}'"}
        # drift check: SECRETS.md must agree
        if not secrets_md_grants(s, role):
            alert_security(payload, s, role, kind="drift")
            return {'decision': 'block',
                    'reason': f"drift: ROLES grants {s} to {role} but SECRETS doesn't"}

    return {'decision': 'allow', 'reason': 'all checks passed'}
```
