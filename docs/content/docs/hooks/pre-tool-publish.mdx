# Hook: pre-tool-publish

> Bất kỳ tool call nào publish ra bên ngoài đều phải đi qua HITL theo `governance/HITL.md`. Hook này chính là cơ chế cưỡng chế.

## Hook làm gì

Đối với bất kỳ lời gọi tool nào tạo ra bề mặt bên ngoài (gửi email, đăng nội dung công khai, merge PR), hook sẽ:

1. Phân loại tier của hành động theo `governance/HITL.md`
2. Kiểm tra yêu cầu dry-run đã được đáp ứng cho Tier C/D
3. Xác minh kích thước người nhận/khán giả so với các ngưỡng
4. Khởi động luồng phê duyệt HITL nếu là Tier C/D
5. Chặn nếu Tier D-MAX mà chưa có nghi thức override phù hợp

## Logic phân loại tier

```
Tool: email_sender / resend_*
  recipients_count == 1 (transactional template) → B (notify-after)
  recipients_count == 1 (custom content) → C (approve-before)
  recipients_count 2-50 → C
  recipients_count 51-1000 → D-Std
  recipients_count > 1000 → D-MAX

Tool: twitter_post / linkedin_post / discord_announce
  Always Tier C minimum (public surface)
  If account has > 10K followers → D-Std (larger blast radius)
  If post mentions a person/competitor by name → D-Std

Tool: youtube_upload
  Always D-Std (irreversible-ish; takedowns are public events)

Tool: github_pr_merge
  PR merging non-Tier-1 to non-main → C
  PR merging to main → C
  PR merging Tier 1 changes → D-Std
  Force-merge bypassing CI → D-MAX

Tool: github_release_create
  Release with tag → D-Std (public artifact)

Tool: slack_post (channel with external members)
  Same as social → C minimum
```

## Cưỡng chế dry-run

Đối với Tier C trở lên, payload của tool BẮT BUỘC phải chứa output đã render mà agent định gửi. Hook xác minh:

- `dry_run` đã được thực thi trước đó cho cùng payload này (kiểm tra `ops.agent_runs` cho dry-run khớp trong vòng 30 phút gần nhất)
- Tin nhắn phê duyệt chứa preview của dry-run (luồng phê duyệt của host gắn kèm điều này)

Nếu không tìm thấy dry-run:
- Lý do: `dry_run_required: tier {{X}} action without preview`
- Quyết định: `block` (agent phải chạy dry-run trước)

## Tích hợp luồng phê duyệt

Khi hook trả về `escalate`, host sẽ:

1. Tạm dừng hành động
2. Gửi yêu cầu phê duyệt Telegram tới founder (theo định dạng riêng cho từng tier của HITL.md)
3. Bao gồm preview của dry-run trong tin nhắn
4. Chờ phản hồi theo chính sách timeout của HITL.md
5. Nếu `Approve & Execute` → hành động tiếp tục với payload gốc
6. Nếu `Reject` → trả về cho agent dưới dạng `block`
7. Nếu timeout → hoãn lại theo HITL.md

Bản thân hook không triển khai Telegram bot — nó trả về `escalate` và host thực hiện việc kết nối. Nhưng hook BẮT BUỘC phải bao gồm đủ context trong `log_extras` để bot có thể render tin nhắn phê duyệt:

```json
{
  "decision": "escalate",
  "reason": "Tier C: external publish requires approval",
  "log_extras": {
    "tier": "C",
    "tool": "twitter_post",
    "audience_size_estimate": 2500,
    "preview_payload_hash": "sha256:...",
    "dry_run_run_id": "<run_id>",
    "expected_telegram_buttons": ["Approve & Execute", "Reject", "View details"]
  }
}
```

## Đếm số người nhận

Đối với gửi email:
- `to`, `cc`, `bcc` được cộng dồn
- Distribution list (ví dụ `subscribers@`) được tính theo kích thước đã giải quyết nếu biết; nếu không biết, coi như > 1000 (tier bi quan nhất)

Đối với bài đăng mạng xã hội:
- Khán giả = số người theo dõi + tiềm năng retweet. Dùng ước lượng thận trọng.
- Nếu không thể ước lượng khán giả, coi như > 1000 để nghiêng về phía an toàn

## Các trường hợp đặc biệt

- **Cờ `is_dry_run: true` trong payload:** hành động CHÍNH NÓ là một dry-run. Hook trả về `allow` (dry-run là Tier A). Output của dry-run được lưu trữ để cuộc gọi thật tiếp theo tham chiếu.
- **Trả lời thread sẵn có:** nếu trả lời một người đã nhắn cho ta trước, Tier giảm một bậc (trả lời ít mang tính xâm nhập hơn). Dùng context của payload để phát hiện.
- **Auto-reply cho các sự kiện do chính người dùng kích hoạt:** email giao dịch (đặt lại mật khẩu, xác nhận thanh toán) gửi để phản hồi hành động của người dùng là Tier B nếu từ template đã được duyệt trước.
- **Kênh Slack nội bộ (không có thành viên ngoài):** coi như Tier B nếu độ dài tin nhắn \< 500 ký tự; A nếu ngắn hơn.

## Tham chiếu triển khai

```typescript
function classifyTier(toolName: string, payload: any): Tier {
  if (toolName.startsWith('email_sender_')) {
    const recipients = countRecipients(payload);
    const isTransactional = toolName.endsWith('_transactional')
                            && payload.template in APPROVED_TRANSACTIONAL_TEMPLATES;
    if (isTransactional && recipients === 1) return 'B';
    if (recipients === 1) return 'C';
    if (recipients <= 50) return 'C';
    if (recipients <= 1000) return 'D-Std';
    return 'D-MAX';
  }
  if (toolName === 'twitter_post' || toolName === 'linkedin_post') {
    if (mentionsExternalEntity(payload.content)) return 'D-Std';
    return 'C';
  }
  // ...
}

export function decide(payload: HookInput): HookDecision {
  if (payload.tool_payload.is_dry_run === true) {
    return { decision: 'allow', reason: 'dry-run' };
  }
  const tier = classifyTier(payload.tool_name, payload.tool_payload);
  if (tier === 'A' || tier === 'B') {
    return { decision: 'allow', reason: `tier ${tier}` };
  }
  if (tier === 'C' || tier === 'D-Std') {
    if (!hasDryRunRecord(payload)) {
      return { decision: 'block', reason: 'dry_run_required' };
    }
    return { decision: 'escalate', reason: `tier ${tier} requires HITL`,
             log_extras: { tier, /* ... */ } };
  }
  // D-MAX
  if (!hasFullCeremony(payload)) {
    return { decision: 'block', reason: 'D-MAX requires override ceremony' };
  }
  return { decision: 'escalate', reason: 'D-MAX with active ceremony' };
}
```
