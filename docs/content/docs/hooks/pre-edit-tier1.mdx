# Hook: pre-edit-tier1

> Blocks direct edits tới Tier 1 files. Forces tất cả changes qua PR + governance per `governance/HITL.md`.

## Những gì nó làm

Inspects file path cho bất kỳ Edit/Write/MultiEdit operation nào. Nếu path matches một Tier 1 protected pattern VÀ operation trên `main` branch (hoặc detached HEAD trên một Tier 1 file), hook escalates hoặc blocks per file's specific tier.

## Protected paths

Các protected patterns map tới HITL tiers như sau:

```
00-charter/**                    → Tier C  (escalate, require PR)
governance/ROLES.md              → Tier C  (escalate, require PR)
governance/HITL.md               → D-MAX   (block unless override+ceremony)
governance/SECRETS.md            → D-MAX   (block unless override+ceremony)
governance/BUDGET.md             → C       (khi file tồn tại; planned)
knowledge/manifest.yaml          → C       (escalate)
knowledge/schemas/*.sql          → D-Std   (escalate, magic phrase)
.claude/hooks/*                  → D-Std   (escalate; modifying hooks weakens safety)
.claude/agents/*                 → C       (escalate)
**/SOP-*/**                      → C       (escalate)
skills/**                        → C       (escalate)
mcp/servers.yaml                 → C       (escalate)
mcp/custom/**                    → C       (escalate)
_build/**                        → C       (escalate)
workflows/**                     → C       (escalate)
```

Paths KHÔNG trong danh sách không được Tier 1 protected. Hook cho phép chúng qua vô điều kiện:

- `wiki/**`, `raw/**`, `.archives/**` (workspace plane)
- `.archives/**/*.gitkeep` (shell tracking)
- README.md và CLAUDE.md ở root → những cái này ARE Tier 1, nhưng special-cased: agents propose updates via PR only via standard flow

## Logic quyết định

```
function decide(payload):
    path = payload.tool_payload.file_path
    branch = current_git_branch()  # từ cwd

    if path matches D-MAX pattern:
        if has_active_override(payload.session_id, action="edit:" + path):
            log_extras["override_check"] = "passed"
            return allow(reason="override active")
        return block(reason="D-MAX file requires override ceremony per governance/HITL.md")

    if path matches D-Std pattern:
        if has_active_override(payload.session_id, action="edit:" + path):
            return allow(reason="override active")
        return escalate(reason="D-Std file edit; HITL approval required")

    if path matches Tier C pattern:
        if branch == "main" and not is_pull_request_context():
            return block(reason="direct edit to main forbidden; create branch and open PR")
        return escalate(reason="Tier 1 edit; PR + founder approval required")

    return allow()
```

## Dữ liệu đầu vào cần thiết

- `payload.tool_payload.file_path` — tập tin được chỉnh sửa
- `payload.session_id` — cho override check
- Current git branch — đọc từ `.git/HEAD` hoặc `git symbolic-ref HEAD`
- Override state — query `ops.agent_runs.was_override` recent rows cho session_id này (cache aggressively)

## Các trường hợp đặc biệt

- **Symlinks:** resolve tới canonical path trước khi matching
- **`.gitignore`'d paths matching protected patterns:** vẫn block, ngay cả khi change sẽ không được committed (defense in depth)
- **Multi-file operations (MultiEdit):** apply check tới mỗi tập tin; nếu bất kỳ single file nào sẽ bị block, toàn bộ operation bị block
- **`create_file`:** treated tương tự như Edit — creating `governance/HITL.md` afresh còn dangerous hơn editing
- **Renames trong protected dirs:** treated như Edit trên destination

## Mutation cases

Hook này không bao giờ mutates payloads. Always allow/block/escalate.

## Ghi chú hiệu năng

- Cache `governance/HITL.md` và path-pattern table; re-read chỉ khi mtime change
- Override check nên hit một local cache được populate bởi Telegram bot ack callback; falling back tới Supabase query là acceptable nhưng slow

## Quan sát

Log mỗi block với `match_rule = "<path-pattern>"` để dashboard có thể show tập tin nào trigger most blocks. High-frequency blocks chỉ ra (a) một confused agent (training opportunity) hoặc (b) một workflow gap mà nên trở thành recipe.
