# Hook: pre-tool-supabase-product

> Bức tường lửa. Operating AI không được phép ghi vào Product Supabase. Hook này cưỡng chế ranh giới đó một cách vô điều kiện.

## Hook làm gì

Kiểm tra bất kỳ tool call nào nhắm vào dự án Product Supabase (`ritsu`). CHỈ cho phép:

1. Role `etl-runner`
2. Các thao tác chỉ đọc (câu lệnh SELECT, endpoint GET)
3. Các thao tác chống lại các view đọc đã được phê duyệt trước

Chặn tất cả những thứ còn lại, kể cả các thao tác ghi của chính `etl-runner`.

## Vì sao hook này đặc biệt

Đây là **hook duy nhất mặc định là BLOCK** thay vì allow hoặc escalate. Lý do:

- Ranh giới này mang tính cấu trúc, không phải quy trình
- Không có quy trình nghiệp vụ nào nên đòi hỏi `ritsu-works` phải ghi dữ liệu Product
- Các trường hợp ngoại lệ dựa trên nhu cầu phải đi qua thiết kế ETL (ghi vào `ritsu-ops` `metrics.*`, không phải Product)
- Sai lầm ở đây có phạm vi tác động lớn nhất trong toàn bộ hệ thống

Hook không bao giờ escalate. Không có lối "founder approval" nào mở được cánh cổng này. Nếu founder thực sự cần Operating AI tác động đến Product, quy trình đúng là:

1. Mở một PR đề xuất luồng ETL mới đi vào `ritsu-ops`
2. Việc thay đổi được triển khai trong **product repo**, không phải ở đây
3. Operating AI tiêu thụ các metric kết quả, không bao giờ ghi ngược lại

## Logic ra quyết định

```
function decide(payload):
    target = identify_target(payload)

    if target.project != "ritsu" (Product):
        return allow()  # not our concern

    # Target is the Product project
    if payload.agent_role != "etl-runner":
        alert_founder_security(payload)
        return block(reason="non-etl-runner role attempted Product Supabase access")

    # Role IS etl-runner; check operation
    operation = identify_operation(payload)

    if operation.type != "read":
        alert_founder_security(payload)
        return block(reason="etl-runner attempted non-read on Product Supabase")

    # Read operation by etl-runner
    if not target.view in PRE_APPROVED_VIEWS:
        return block(reason=f"read target '{target.view}' not in pre-approved view list")

    return allow()
```

## Các view đã được phê duyệt trước

Danh sách các view/bảng mà `etl-runner` được phép đọc từ Product Supabase. Được bảo trì bởi product team phối hợp với repo này. Danh sách khởi điểm v0.2 (TBD khi việc provisioning thực tế diễn ra):

```yaml
pre_approved_views:
  - public.etl_user_metrics      # daily user counts, signup rates
  - public.etl_subscription_state # subscription tier counts (no PII)
  - public.etl_session_aggregates # aggregate engagement metrics
  - public.etl_content_stats      # content generation stats
```

Các view này được thiết kế để:
- Tước bỏ PII (email người dùng, tên) ở cấp định nghĩa view trong Product DB
- Tổng hợp ở mức độ mà Operating AI cần (không có dữ liệu người dùng cấp hàng)
- Chỉ ở dạng append-only / current-state-only (không có lịch sử có thể tái dựng lại để định danh lại)

Bất kỳ việc mở rộng nào của danh sách này đều là hành động Tier D-Std (PR + nghi thức).

## Cách xác định target

`target` trong tool_payload phụ thuộc vào tool:

- Đối với MCP server `supabase-product`: project ref hoặc URL tường minh
- Đối với tool `postgres-*` thô: connection string bao gồm URL dự án
- Đối với các cuộc gọi Supabase JS SDK: URL của constructor client

Hook phân giải về dạng chuẩn: `(project_ref, schema, view_or_table, operation_type)`.

## Các trường hợp đặc biệt

- **Truy vấn liên dự án (foreign data wrapper):** nếu `etl-runner` dùng FDW từ `ritsu-ops` để pull từ `ritsu`, lần đọc vẫn đi qua hook này vì kết nối nền tảng nhắm vào Product. Chỉ ALLOW nếu FDW được cấu hình chống lại các view đã được phê duyệt trước.
- **Connection string bị cấu hình sai:** nếu một role không phải `etl-runner` bằng cách nào đó có được credential Product (bản thân điều này đã là vi phạm `pre-tool-secrets`), hook này là tuyến phòng thủ thứ hai.
- **`schema = pg_catalog` hoặc các system schema:** coi như đọc metadata hệ thống. Chỉ cho phép với `etl-runner` và chỉ khi không phơi bày dữ liệu người dùng qua bảng hệ thống.
- **`SELECT FROM auth.users`:** BLOCK CỤ THỂ — auth.users không bao giờ nằm trong danh sách đã được phê duyệt trước, kể cả tình cờ.

False positive trong hook này rất hiếm. Nếu chúng xảy ra, sửa nguyên nhân gốc (thường là tool hoặc role bị cấu hình sai), đừng nới lỏng hook.

## Tích hợp với các hook khác

Hook này hoạt động cùng với `pre-tool-secrets` như phòng thủ theo lớp:

- `pre-tool-secrets` đảm bảo chỉ `etl-runner` MỚI GIỮ credential Product
- Hook này đảm bảo dù credential có bị rò rỉ, thao tác cũng bị chặn

Cả hai hook đều phải vượt qua thì mới truy cập được Product Supabase. Một trong hai thất bại sẽ chặn lời gọi.

## Tham chiếu triển khai

```python
PRE_APPROVED_VIEWS = {
    'public.etl_user_metrics',
    'public.etl_subscription_state',
    'public.etl_session_aggregates',
    'public.etl_content_stats',
}

PRODUCT_PROJECT_REF = 'XXXXXXXX'  # from manifest.yaml after Phase B

def identify_target(payload):
    """Parse target project, schema, table from any supported tool format."""
    # ...
    return {'project': '...', 'schema': '...', 'view': '...', 'op': '...'}

def decide(payload):
    target = identify_target(payload)
    if target['project'] != PRODUCT_PROJECT_REF:
        return {'decision': 'allow', 'reason': 'not Product project'}

    role = payload['agent_role']
    if role != 'etl-runner':
        alert_security(payload, 'non_etl_role_attempted_product_access')
        return {'decision': 'block',
                'reason': f"role '{role}' has no Product access"}

    op_type = target['op'].lower()
    if op_type not in ('select', 'read'):
        alert_security(payload, 'etl_runner_attempted_write')
        return {'decision': 'block',
                'reason': f"operation '{op_type}' is not read"}

    full_path = f"{target['schema']}.{target['view']}"
    if full_path not in PRE_APPROVED_VIEWS:
        # check if it's a system schema read
        if target['schema'] in ('pg_catalog', 'information_schema'):
            return {'decision': 'allow', 'reason': 'system metadata read'}
        return {'decision': 'block',
                'reason': f"view '{full_path}' not pre-approved"}

    return {'decision': 'allow', 'reason': 'etl-runner read of pre-approved view'}
```
