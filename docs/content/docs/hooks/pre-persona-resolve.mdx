# Hook: pre-persona-resolve

> Resolves một invocation `/<slug>` hoặc `@<slug>` của workforce persona registry, injects `persona_slug` và `bound_role` vào agent context, và surfaces một clear error khi slug là unknown. **Does NOT broaden permissions** — narrowing only. Permission ceiling stays với bound role per `governance/ROLES.md`.

## Tại sao đây là một hook, không phải là một skill

Một slash-command hoặc subagent invocation là FIRST event trong một turn. Khi một skill có thể được invoked, persona context đã được cần. Một hook chạy trước bất kỳ user-facing tool call nào, đó là injection point đúng.

Hook này là một **resolver**, không phải một gate. Hard gate sống trong `pre-delegate-check.md` (PR 1) mà bây giờ cũng đọc `persona_slug` từ context để áp dụng persona-level narrowing trên top của role's HITL ceiling.

## Những gì nó làm

Khi first signal của một turn là `@<slug>` hoặc một slash command matching `/<slug>`:

1. Đọc `knowledge/workforce-personas.yaml`.
2. Tìm kiếm `personas.<slug>`:
   - Nếu missing → trả về `decision: block`, `reason: "Unknown persona slug <slug>. Suggest closest: <fuzzy match>. See knowledge/workforce-personas.yaml."`
   - Nếu `status: planned|deferred` → trả về `decision: block`, `reason: "Persona <slug> is not active (status: <s>). Fallback per CEO routing-matrix.md."`
   - Nếu `status: retired` → trả về `decision: block`, `reason: "Persona <slug> retired. See dossier history at 06-ai-ops/workforce-personas/<slug>/dossier.md."`
   - Nếu `status: active` → tiếp tục.
3. Resolves `binds_to.primary` → tìm kiếm `governance/ROLES.md` role definition.
4. Injects vào agent context:
   - `persona_slug = <slug>`
   - `bound_role = <role>`
   - `persona_default_hitl_max = <tier>` (từ registry; không bao giờ rộng hơn role's `hitl_max_tier`)
5. Trả về `decision: allow` cộng với `log_extras: { persona_slug, bound_role, persona_default_hitl_max }`.

## Tương tác với `pre-delegate-check`

`pre-delegate-check` (existing hook) tiêu thụ `persona_default_hitl_max` từ context khi có. Nếu tier của action vượt quá persona narrowing, nó blocks với persona-narrowing reason. Nếu action cũng vượt quá role's ceiling, role-level block được ưu tiên (rules layered, không song song).

## Quy tắc phân giải

- **Persona slug** = lowercase 3-5 chars (per `knowledge/workforce-personas.yaml` `naming_policy`).
- **Slash form** `/<slug>` vs **mention form** `@<slug>` — cả hai phân giải qua cùng một hook; chỉ agent file vs command file sử dụng downstream khác (xem `.claude/agents/<slug>.md` và `.claude/commands/<slug>.md`).
- **No double-resolution.** Một khi `persona_slug` trong context, subsequent tool calls KHÔNG re-resolve. Resolution là idempotent per session.
- **No fabrication.** Nếu registry entry bị malformed (missing `binds_to.primary`), hook này trả về `decision: block` và surfaces schema error thay vì guessing.

## Audit signal

Hook này KHÔNG write vào `ops.agent_runs`. Companion hook `post-persona-log.md` làm điều đó ở end-of-invocation với final `tier` và outcome. Audit responsibility bị chia intentionally: resolver injects, logger persists.

## Failure modes được bao phủ

| Case | Hook decision | Audit footprint |
|---|---|---|
| Unknown slug | block | none (slug never resolved) |
| Slug ở `status: planned` | block | `log_extras.block_reason='planned-persona'` |
| Slug active nhưng `binds_to.primary` role missing trong ROLES.md | block | `log_extras.block_reason='binding-broken'` |
| Slug active, role exists, nhưng `default_hitl_max` > role's ceiling | block + alert | `log_extras.block_reason='persona-broadens-role'` — should never happen nếu validators chạy; nếu có thì drift incident |
| All clean | allow | `log_extras.persona_slug` populated |

## Tại sao narrowing-only

Per ADR-003. Personas là façade. Broadening = persona claims more authority hơn underlying role có. Đó là forbidden category — bất kỳ attempted broadening nào là một `pre-delegate-check` hard block + một `verify-persona-narrowing` validator failure (PR 2/4).
