# Hook: post-persona-log

> Writes final `persona_slug` attribution vào `ops.agent_runs` ở end của invocation, và appends một one-line entry vào `06-ai-ops/workforce-personas/<slug>/dossier.md` cho non-trivial actions (Tier B+).

## Tại sao đây là một hook, không phải là một phần của persona itself

Nếu persona phải nhớ để log chính nó, nó sẽ quên. Bằng cách làm cho audit write xảy ra ở runtime layer, mỗi invocation đều được logged bất kể persona đã làm gì hay không làm gì bên trong turn.

Đây là same pattern như `pre-llm-call-budget.md` writing vào `ops.cost_attributions` sau LLM call. Audit sống ở layer có thể đảm bảo execution.

## Những gì nó làm

Trên mỗi tool call completion (post-tool), nếu `context.persona_slug` được set:

1. Append/update `ops.agent_runs` row cho invocation này:
   ```sql
   UPDATE ops.agent_runs
      SET persona_slug = $1,            -- e.g. 'ceo'
          state_payload = state_payload
            || jsonb_build_object('persona_default_hitl_max', $2,
                                  'bound_role', $3)
    WHERE id = $current_run_id;
   ```
   Note: `agent_slug` bị left untouched — đó là technical role làm công việc (ví dụ `gps`). Một row mang cả hai planes (per `ops.agent_runs` schema bumped trong migration 00024).

2. Nếu action vừa completed là Tier B+, append một one-line entry vào dossier của persona:
   ```
   06-ai-ops/workforce-personas/<slug>/dossier.md
   ```
   Format:
   ```
   2026-05-15T14:32:01Z | tier=B | summary=<≤90 chars> | run_id=<uuid>
   ```
   Dossier writes là append-only. Nếu file không tồn tại, tạo nó với một one-line header.

3. Emit một `run_summary` vào `ops.run_summaries` per `knowledge/memory-architecture.md` (existing pipeline; hook này chỉ set `persona_slug` trên row).

## Những gì nó KHÔNG làm

- Decide tiers (đó là `pre-delegate-check`).
- Block bất kỳ cái gì (đó là post-hoc).
- Write `dossier.md` cho Tier A actions (quá chatty).
- Touch `governance/HITL.md` hoặc bất kỳ tier ceremony nào.
- Make new tables. Uses existing `ops.agent_runs` + new `persona_slug` column (migration 00024).

## Tương tác với `pre-persona-resolve`

`pre-persona-resolve` injects `persona_slug` vào context. Hook này đọc nó lại. Nếu `persona_slug` unset (direct-role invocation mà không có persona), hook này trở thành no-op — `ops.agent_runs.persona_slug` stays NULL, đó là intentional design (không phải mỗi run là persona-routed).

## Quy ước tập tin dossier

- Path: `06-ai-ops/workforce-personas/<slug>/dossier.md`
- Format: một dòng per Tier B+ action.
- Sort order: chronological append (newest ở bottom).
- Trim policy: ở 1000 lines, oldest 500 lines move tới `dossier-archive-<YYYY-MM>.md`.
- Read by: persona ở session start (per command.md "Session memory" section), Friday review aggregation, founder ad-hoc.

## Schema cho dossier line

```
ISO8601-ts | tier=<A|B|C|D-Std|D-MAX> | summary=<text up to 90 chars, no pipes> | run_id=<uuid>
```

Pipes bên trong `summary` được escaped thành `&#124;` để giữ format parseable bằng simple split.

## Failure modes được bao phủ

| Case | Hook behavior |
|---|---|
| `persona_slug` không trong context | No-op. agent_runs row giữ `persona_slug = NULL`. |
| `ops.agent_runs` row chưa được commit | Hook queues update; runtime flushes sau row commit (avoids race). |
| Dossier file missing | Create với one-line header, sau đó append. |
| Dossier file unwritable (filesystem error) | Log vào `ops.audit_log`; do NOT block; surface ở next session's `synthesize-morning-brief`. |
| Tier escalated mid-action | Use FINAL tier (cái thực sự execute), không phải originally-planned tier. |
