# Use Issue Trees by Default; Reserve Hypothesis Pyramids for Two Cases Only

**Type:** decision · **From:** *Cracked It! How to Solve Big Problems and Sell Solutions Like Top Strategy Consultants* (Bernard Garrette, Corey Phelps, Olivier Sibony, 2018), Ch 5 — Structure the Problem: Pyramids and Trees

## Summary

The chapter's central actionable recommendation: default to issue trees for problem structuring. Reserve hypothesis pyramids only when (1) you have deep, verified expertise that justifies a candidate solution, or (2) time pressure or stakeholder expectations make an issue tree infeasible. In all other situations the issue-driven path produces more thorough, less biased analysis even if it takes longer and is harder to communicate.

## Raw quotes (verbatim, for citation)

- **From [Ch 5 — Structure the Problem: Pyramids and Trees](../chapters/chapter-05-structure-the-problem-pyramids-and-trees.md)** (PDF pp. 86–110, confidence 0.95):

  > the "default choice" should be to use an issue tree, unless there are compelling reasons to be content with a hypothesis pyramid.

  > Whenever you have sufficient time and latitude to investigate the problem in depth, issue trees should be your first call.

## Ritsu relevance

Ritsu's `/cla propose` workflow should default to issue-tree decomposition during Phase 2 (Domain Deep-Dive) to avoid premature solution lock-in, switching to hypothesis-pyramid style only after a credible candidate architecture has emerged from open analysis.
