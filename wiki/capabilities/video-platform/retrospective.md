## What we set out to fix

We had produced a good 2:55 explainer film and **an artifact, not a capability**. Every decision —
the beat structure, the asset-code system, media prep, composition patterns, QC — was derived live
and lived in one folder. The next video restarted from zero.

Worse: several lessons were **invisible to every gate we owned**. `hyperframes check` passed,
`snapshot` passed, and the first render came out **mostly blank**.

## What went right

**Verifying the reviewer paid for itself.** `@cto` returned *request-changes* with three findings.
All three were **independently checked against the code before acceptance** — and all three were
real:

1. `voice-adapters.yaml:66` — `elevenlabs` was `registered-not-built`, `voices: 0`. The founder's
   automation decision **could not execute as written**. The 11 voice-overs on the reference film
   had been generated by a one-off script, which was precisely the gap.
2. `grep -rn "hyperframes"` across `scripts/`, `.claude/`, `knowledge/`, `06-ai-ops/` returned
   **only prose**. A co-founder could run `/install-ritsu-works`, watch `/test-ritsu-works` report
   SUCCESS, and still be unable to run `/video`.
3. `/voice` — the closest sibling — keeps its 23 types as `const TYPES` in code. Copying the
   nearest pattern would have broken registry-driven extensibility on day one.

**Empirical gates beat asserted ones.** Rather than declaring thresholds, we measured the real
render: content luma std-dev **19.6** vs flat **3.8** (~5× separation → threshold 8), and bitrate
**2.6 Mbps broken vs 4.3 Mbps correct** (→ floor 3500). Then each gate was demonstrated **failing**
on a deliberately broken fixture before the sprint was called done.

**The loudness gate independently rediscovered the bug we had fixed by hand** — raw sources spread
**4.5 LU** (VO-11 −13.5 vs AV-03 −18.0), the exact seam the founder heard. Strong evidence the
mechanism is real and not a rationalisation.

**The biggest reuse win was already written.** `scripts/voice/lib/audio.cjs` exports
`measureLoudness` / `normalizeLoudness` with `DEFAULT_LUFS = { i: -16, tp: -1.5 }` — literally the
target lesson #1 demands, built for `/voice` v0.3.1 and never wired to video. Reading the code
instead of the docs turned the most painful lesson into a `require()`.

## What we got wrong along the way

- **A test asserted the wrong thing.** The handoff-subset test mutated `explainer`, which declares
  *every* slot — so nothing was invalid and the test failed for the right reason. `default` (no
  `screen`, no `avatar`) was the honest case. The validator was correct; the test was not.
- **First registry append landed inside a block scalar.** Appending to the end of
  `capability-registry.yaml` put the entry inside a `notes: |` literal. Fixed by finding the real
  top-level boundary rather than assuming the file ended with the list.
- **`drawtext` is absent from this ffmpeg build**, and `ffprobe -f lavfi -i movie=` returned
  nothing. Both discovered by failure. The QC gate uses an `ffmpeg rawvideo` pipe instead, and
  `selfcheck.cjs` now **probes** filters rather than remembering.

## The design decision that mattered most

**SLOT-level state, not stage-level.** A `stage: "composing"` enum cannot survive the hand-off,
because the blocking condition is per-asset — *"waiting on 4 of 22 screen captures"*. And because
the founder's sync contract gitignores media, a teammate who clones sees `stage: composed` with
**zero bytes on disk**. So `--resume` **reconciles by probing and checksumming**; recorded state is
a hint, the disk is the authority.

## Honest limitations

- **`lint-stage-video.cjs` cannot resolve external stylesheets or the real cascade.** A PASS is not
  proof; `verify-render.cjs` on the finished mp4 is the authority. This is stated in the code, the
  SOP, and the tool's own output.
- **Lesson #6 (no invented figures) is only half-automatable.** The *citation* is checkable; the
  *truth* of a figure is not. The citation spine converts "don't lie" into "cite your capture",
  which is the best available proxy.
- **Framing (#5) is ~80% spec-side.** We can state the forbidden band in the record spec and
  reject an obviously-wrong ingest; we cannot enforce it at capture time.
- **The bitrate floor is a heuristic.** It is deterministic, it costs one `ffprobe`, and it is the
  tell that actually fired — but a legitimately sparse film could trip it. That is why the
  blank-segment check exists alongside it.

## Deferred deliberately

- `ops.video_runs` + KPIs — `run.json` is a forward-compatible superset; promoting it later is
  INSERT-wiring, not rework. Same Option A+ precedent as `/voice` and `/image`.
- Veo automation — no API. `/video` authors the prompts and hands off.
- Publishing — the kit is produced; posting stays Tier C.

## The test that still has to be run

Sprint 2's stated exit gate was: **reproduce `ritsu-product-launch` end-to-end from its committed
`SCRIPT.md` + supplied assets.** The gates were verified against that project's real render, and
the scaffold/state/registry layers were smoke-tested — but a full clean-room rebuild through every
pipeline stage has **not** been executed. Until it is, the honest claim is *"the contract and the
gates are proven; the full loop is not"*.
