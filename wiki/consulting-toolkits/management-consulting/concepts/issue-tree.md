# Issue Tree (MECE)

*Category: diagnosis · Toolkit: Management Consulting*

## What it is
A hierarchical breakdown of a problem (or question) into mutually exclusive, collectively exhaustive sub-issues.

**Origin:** Core of the McKinsey problem-solving method; rooted in Barbara Minto's logical-tree work.

## Why it works
Big problems are unanalysable whole; decomposing them MECE-ly into smaller, independent branches makes each piece testable and ensures nothing is double-counted or missed.

## When to use
To structure any problem or question before analysing it.

## Visual
`tree`

## Step-by-step tutorial
1. State the key question at the root.
2. Break it into 2-4 MECE sub-questions (a diagnostic 'why?' tree or a solution 'how?' tree).
3. Recurse each branch until leaves are concrete enough to analyse.
4. Check MECE: no overlaps, no gaps, at every level.
5. Prioritise the branches most likely to matter (hypothesis-driven) and analyse those first.

## Real-life example — McKinsey (method)
For 'how do we grow revenue?', a McKinsey team splits it into price × volume, then volume into new vs existing customers, etc., so each leaf is a discrete analysis — the backbone of nearly every case.

**So what:** A MECE tree turns an overwhelming question into a finite set of answerable ones.

## Pitfalls
- Branches that overlap or leave gaps — counter: run the 2-test MECE check.
- Going too deep before prioritising — counter: prune to high-impact branches first.
