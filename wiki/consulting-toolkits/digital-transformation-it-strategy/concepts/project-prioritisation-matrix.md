# Project Prioritisation Matrix (Value vs. Feasibility 2×2)

*Category: portfolio · Toolkit: Digital Transformation & IT Strategy*

## What it is
A 2×2 matrix that plots candidate digital projects on Strategic Value (y-axis) and Feasibility (x-axis), classifying them into four quadrants: Must-Do Now, Strategic Bets, Quick Wins, and Deprioritise — enabling transparent, evidence-based portfolio decisions.

**Origin:** Adapted from the McKinsey/BCG portfolio matrix tradition and the McKinsey Digital agile transformation methodology (published from 2018). The 'Value vs. Effort' variant is standard in consulting-led digital programme design.

## Why it works
Digital transformation generates far more candidate projects than any organisation can fund. Without a structured method, portfolio decisions are political. The 2×2 imposes discipline: every project scores on the same two dimensions using the same rubric, making the comparison fair. The two-axis design captures the core tension: high-value projects that are hard to deliver vs. easy projects that may not be strategically important.

## When to use
Use in Phase II Step 8 to prioritise the candidate digital project portfolio; in Phase IT-III to prioritise the IT initiative portfolio. Use whenever a leadership team needs transparent resource allocation decisions.

## Step-by-step tutorial
1. 1. Define Strategic Value rubric (0–10): weight 4 criteria — alignment to strategic objectives (30%), customer impact (25%), financial opportunity (25%), digital maturity improvement (20%). Score each criterion 1–5 per project.
2. 2. Define Feasibility rubric (0–10): weight 4 criteria — implementation complexity (30%; 5=simple), investment required (25%; 5=low cost), time to first value (25%; 5=<6 months), organisational readiness (20%). Same calculation.
3. 3. Score all projects as a team: use anchored behavioural descriptions for each score level to ensure inter-rater consistency.
4. 4. Plot on 2×2: x=Feasibility, y=Strategic Value. Use bubble size for estimated NPV.
5. 5. Draw quadrant boundaries at midpoints (5,5). Label quadrants.
6. 6. Validate with ExCo: allow challenges to individual placements; document reclassifications and rationale.
7. 7. Sequence the portfolio: Must-Do Now → Wave 1; Strategic Bets → Wave 2/3; Quick Wins → selectively Wave 1; Deprioritise → remove from scope.
8. 8. Re-score quarterly: conditions change; projects not yet started should be re-scored at each quarterly portfolio review.

## Real-life example — ING Bank (Netherlands)
ING's 2014 agile digital transformation used a systematic 'Now / Next / Future' classification equivalent to the prioritisation matrix. 'Now' (high value, high feasibility): mobile banking notifications redesign, debit card digitalisation, savings target feature. 'Future' (high value, low feasibility): full core banking system replacement. By 2018, ING had 350 squads operating across the portfolio with >12,000 sprint goals. The classification discipline created portfolio clarity that enabled execution at scale.

**So what:** The prioritisation matrix is as valuable for what it removes (deprioritised projects) as for what it approves. ING's discipline in keeping the 'Now' portfolio small and high-value was a key factor in its transformation speed.

## Pitfalls
- Scoring without anchors — define behavioural descriptions for each score level; without them scores are subjective.
- Prioritising quick wins over strategic bets — protects short-term optics at the cost of long-term value.
- Static prioritisation — re-score at each quarterly portfolio review; conditions change.
- NPV bubble size dominating quadrant placement — NPV is context, not the primary sorter; use the rubric scores.
