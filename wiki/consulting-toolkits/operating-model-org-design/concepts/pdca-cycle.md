# PDCA Cycle (Plan-Do-Check-Act)

*Category: continuous-improvement · Toolkit: Operating Model & Organization Design*

## What it is
A four-step iterative improvement methodology: Plan (identify the problem and design a solution), Do (implement on a small scale), Check (measure the result against the expectation), Act (standardize if successful; adjust and repeat if not).

**Origin:** Walter Shewhart, Bell Labs, 1930s. Popularized by W. Edwards Deming in post-war Japan, leading to its alternative name 'Deming Cycle'. Formalized in ISO 9001 quality management standards.

## Why it works
Improvement is most effective when treated as a scientific experiment rather than a project. PDCA enforces hypothesis-testing discipline: before acting, predict the result; after acting, compare actuals to prediction. This converts tacit knowledge ('I think this will work') into explicit organizational learning ('this works in conditions X, Y, Z').

## When to use
Use in Phase 5 (Continuous Improvement step) for all in-flight initiatives, and embed as a permanent management rhythm after program close.

## Step-by-step tutorial
1. PLAN: Define the problem in measurable terms (e.g., 'Average order processing time is 5 days; target is 2 days'). Run a 5-Why root-cause analysis to identify the primary cause. Design a solution hypothesis and predict its effect ('if we automate the approval step, cycle time will drop to 2.5 days').
2. DO: Implement the solution in a controlled pilot (one team, one region, one process instance). Run for 4–6 weeks. Collect the same metrics that defined the problem.
3. CHECK: Compare actual results to the prediction. If actual = predicted, the hypothesis is confirmed. If actual ≠ predicted, diagnose why—was the root cause wrong? Was the solution poorly implemented?
4. ACT: If successful, document the new standard operating procedure and roll out to the full organization. If unsuccessful, update the hypothesis and re-run from Plan.
5. Embed monthly PDCA reviews into the governance calendar for all active initiatives.

## Real-life example — Toyota
Toyota's Toyota Production System (TPS) is built on continuous PDCA cycles at every level of the organization. The 'andon cord'—which any production line worker can pull to stop the line—triggers an immediate PDCA loop: Plan (identify what went wrong), Do (fix it at the source), Check (verify the fix worked), Act (update the standard and potentially change the process across all lines). Toyota averages over 1 million PDCA cycles per year across its production system.

**So what:** PDCA at scale requires psychological safety—workers must feel safe to stop the process and report problems. Toyota's greatest operational advantage is not the PDCA cycle itself but the management system that makes it safe and expected to use it.

## Pitfalls
- Skipping the 'Check' step and assuming the pilot worked—this is the most common failure and the source of 'improvements' that do not stick.
- Running PDCA cycles that are too long (> 3 months)—the shorter the cycle, the faster the learning. Target 4–8 week cycles for most operational improvements.
- Not documenting the results in a shared lessons-learned register—individual PDCA cycles that are not captured become organizational amnesia.
