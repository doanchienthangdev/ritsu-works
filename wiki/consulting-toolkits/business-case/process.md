# Business Case Toolkit

**Build a compelling, board-ready investment case for any project in three disciplined phases.**

*Core value: The analytical rigour and structured methodology to justify investment in any new initiative — from a clean project description, through strategic and financial assessment, to a prioritised, presentation-ready recommendation the board will fund.*

---

## Use This Toolkit When Your Project Needs Executive Funding

Fifty-five percent of projects fail to deliver their expected business value. The causes are nearly always the same: vague objectives, missing stakeholder buy-in, optimistic assumptions, poor risk management, and a financial model no one trusts. This toolkit eliminates each failure mode before it can take hold.

Use it whenever you need to:
- Justify a new business initiative, product launch, or improvement programme to an executive committee or board of directors
- Build a credible financial model that survives board scrutiny
- Choose among competing investment demands with a defensible portfolio view
- Present a recommendation with the clarity and confidence of a senior McKinsey partner

**Who should use it:** Strategy leaders, product managers, management consultants, finance leads, and entrepreneurs — anyone who must secure executive buy-in for a significant investment.

## Phase 1 — Project Description: Lock Down What the Project Actually Is

**Goal:** Establish a complete, unambiguous picture of the project before any assessment begins. If the description is fuzzy, the assessment will be contested and the board will send you back.

**Key question:** Do we have a clear, complete, and agreed description of what this project is and what it aims to achieve?

**Duration:** 1–2 weeks

### Step 1.1 — Frame the Situation Using SCQ

**How:** Use the Situation-Complication-Question structure. Write one paragraph for each: the Situation (the factual backdrop everyone agrees on), the Complication (the specific event or trend that creates the problem or opportunity), and the Question (the implicit question the complication forces). Then state the Proposed Solution in one sentence. This shared frame prevents stakeholders from arguing about symptoms.

**Input:** Market data, internal performance data, management observations
**Output:** One-page SCQ framing + proposed solution statement
**Owner:** Project sponsor

### Step 1.2 — Define SMART Objectives and KPIs

**How:** Translate the proposed solution into 3–5 SMART objectives. For each objective: define the KPI that will measure success, record the current baseline, set a target, name the measurement owner, and set a cadence. Objectives without measurable KPIs cannot be tracked or reported to a board — they become aspirations, not commitments.

**Input:** Proposed solution statement; corporate strategic goals
**Output:** Objectives-and-KPIs table with baselines, targets, owners, and cadence
**Owner:** Project sponsor + PMO

### Step 1.3 — Scope, Approach, and RACI

**How:** Write explicit in-scope inclusions, out-of-scope exclusions, and items to-be-decided. Map the delivery approach: the methodology, workstreams, and key milestones. Assign the project team in a RACI matrix with named individuals in each role. An undocumented scope assumption is a scope-creep bomb.

**Input:** Objectives and KPIs; resource availability
**Output:** Scope boundary document + workstream map + RACI matrix
**Owner:** Project manager (R), Sponsor (A)

### Step 1.4 — Build the WBS and Gantt Plan

**How:** Decompose the project into a Work Breakdown Structure: workstreams → activities → tasks, with the deliverable each produces. Then sequence the activities on a Gantt chart: estimated duration, dependencies, and the critical path. Identify which activities determine the earliest completion date — these are where schedule risk lives.

**Input:** Scope and approach; team availability
**Output:** WBS + Gantt chart with milestones and deliverables list
**Owner:** Project manager

### Step 1.5 — Build the Risk Register

**How:** Brainstorm 5–10 risks in four categories: execution (timeline, resources), market (demand, competition), technology (integration, reliability), and regulatory (approvals, compliance). Rate each on Likelihood × Impact (1–5 scale), plot on a risk matrix, and assign an owner, a mitigation action, and a contingency for every critical risk. A board that sees a credible risk register will trust the financial model more.

**Input:** Project plan; stakeholder interviews; analogous project post-mortems
**Output:** Risk register with scores, mitigations, contingencies + risk matrix
**Owner:** Project manager + risk lead

**Phase 1 Deliverable:** A complete project description document covering all five components above, sponsor-approved.

**Exit Gate:** Is the description complete and agreed? No assessment begins until this is locked.

## Phase 2 — Project Assessment: Build the Investment Thesis

**Goal:** Test the project rigorously across three dimensions — strategic alignment, value creation, and ease of implementation — to create a defensible investment thesis.

**Key question:** Is this project strategically aligned, financially attractive, and feasible enough to warrant investment?

**Duration:** 2–3 weeks

### Step 2.1 — Score Strategic Alignment

**How:** List the organisation's strategic priorities (typically 3–5 pillars from the corporate strategy). For each pillar, score the project's contribution (0–10) and write a one-sentence rationale. Compute the weighted average. Also score organisational capability alignment: does the company have the culture, capabilities, and resources to execute this type of project? Any pillar scoring below 5 needs a narrative explaining why this project should still be funded.

**Input:** Corporate strategy documents; strategic priority list; capability self-assessment
**Output:** Strategic alignment matrix with scores per pillar, weighted total, and narrative
**Owner:** Strategy team + sponsor

### Step 2.2 — Quantify Value Creation

**How:** Build a Value Driver Tree: the root node is total project value, which decomposes into primary drivers (additional revenue generated, cost savings achieved, risk avoided, strategic options created). For each driver, model the contribution explicitly — not a lump assumption. For revenue, use a top-down market sizing reconciled with a bottom-up demand model. Benchmark every key assumption against industry peers or comparable projects: a benchmarked assumption is much harder for a board to challenge than an internal estimate.

**Input:** Market data, internal performance data, industry peer benchmarks
**Output:** Value driver tree with quantified drivers and sourced benchmarks
**Owner:** Finance team + project team

### Step 2.3 — Score Ease of Implementation

**How:** Rate the project on four implementation dimensions (each 1–5): (1) Organisational readiness — does the company have the skills, culture, and change appetite? (2) Technology readiness — is the current infrastructure sufficient? (3) Change management complexity — how many stakeholders, how disruptive? (4) Regulatory/compliance risk — how uncertain are approvals? Compute a weighted ease score. A score below 3 means the project needs either a phased approach or explicit de-risking actions before funding is justified.

**Input:** Team capability audit; technology readiness assessment; change impact analysis
**Output:** Implementation ease scorecard with dimension ratings, weighted score, and narrative
**Owner:** PMO + HR + IT

**Phase 2 Deliverable:** Project assessment report with alignment score, quantified value case, and ease scorecard.

**Exit Gate:** Does the project pass all three assessments at threshold? If not, redesign or de-prioritise before Phase 3.

## Phase 3 — Prioritisation, Financial Model, and Presentation: Earn the Investment Decision

**Goal:** Place the project in portfolio context, build a financial model that survives scrutiny, and present with the clarity of a top-tier consultant.

**Key question:** Given competing demands for capital, should this project be funded now?

**Duration:** 2–4 weeks

### Step 3.1 — Plot the Prioritisation Matrix

**How:** Gather the Phase 2 assessment scores (Value and Ease) for every competing investment candidate. Plot all of them simultaneously on a 2x2 matrix: Value on the Y-axis, Ease on the X-axis. Quadrant logic: top-right (Quick Wins) = fund immediately; top-left (Major Projects) = phase carefully; bottom-right (Fill-Ins) = do only if capacity allows; bottom-left (Time Sinks) = kill. The board must see the whole portfolio — not just the project being proposed.

**Input:** Phase 2 assessment data for this project and all competing candidates
**Output:** Prioritisation matrix with all candidates plotted and a funding recommendation for each
**Owner:** Portfolio manager + executive committee

### Step 3.2 — Build the 7-Component Financial Model

**How:** Build the financial model in seven structured components:
1. **Assumptions log** — every key assumption with its source (market data, benchmark, internal estimate) and a sensitivity flag (H/M/L impact if wrong)
2. **Initial investment** — all upfront capex, one-time setup, and pre-launch costs by category
3. **Ongoing project costs** — recurring opex, people (FTE × loaded cost rate), technology licences, and maintenance, by year
4. **Additional revenue generated** — top-down market sizing reconciled with bottom-up demand model; revenue ramp modelled explicitly
5. **Cost savings** — savings by category, timing, and methodology
6. **Financial summary** — NPV (at agreed WACC), IRR, payback period, ROI, and year-by-year free cash flow
7. **Dashboard** — a single-page visual showing the key financial outputs and scenario comparison

Run three scenarios (base, upside, downside) by varying the 3–5 most sensitive assumptions. Present all three to the board.

**Input:** Value case from Phase 2; detailed cost estimates; agreed discount rate (WACC or hurdle)
**Output:** Full financial model spreadsheet + one-page dashboard
**Owner:** Finance team (R), Project manager (A)

### Step 3.3 — Present Using the Pyramid Principle

**How:** Structure the board presentation top-down: slide 1 states the governing recommendation in full ('We recommend funding Project X at $Xm; it delivers NPV of $Xm, IRR of X%, and is consistent with our strategic priority Y'). Then three pillars (strategic alignment, value, ease) support it, each with two or three data slides. Open the verbal delivery with SCQ. Write every slide title as an action statement — the argument the slide makes, not the topic it covers. Test: read only the slide titles out loud — does the logical argument come through without any explanation? If yes, the structure is right.

**Input:** All Phase 1–3 outputs; board audience priorities
**Output:** Board-ready presentation with governing thought, three pillars, financial model summary, risk register, and next-step slide
**Owner:** Project sponsor

**Phase 3 Deliverable:** Prioritisation matrix, full financial model with scenarios, and board-ready investment presentation.

**Exit Gate:** Board approves investment with named owners and a start date.

## The Frameworks and Tools

### SCQ — Situation, Complication, Question
A three-sentence narrative structure that opens any communication by establishing shared facts (Situation), introducing the tension (Complication), and posing the question the rest of the document answers. Developed by Barbara Minto at McKinsey. Used in Steps 1.1 and 3.3.

### SMART Objectives
Objectives written to be Specific, Measurable, Achievable, Relevant, and Time-bound — each with a KPI, baseline, and target. Developed by George T. Doran (1981). Used in Step 1.2.

### RACI Matrix
A responsibility-assignment tool that maps each project deliverable to four roles: Responsible (does the work), Accountable (owns the outcome), Consulted (provides input), Informed (receives updates). No deliverable should have more than one Accountable. Used in Step 1.3.

### Work Breakdown Structure (WBS)
A hierarchical decomposition of the project into workstreams, activities, and tasks — each with a defined deliverable. The foundation of every realistic project plan. Used in Step 1.4.

### Gantt Chart
A timeline visualisation of project activities showing start dates, durations, dependencies, and milestones. The critical path (the longest sequence of dependent activities) determines earliest completion. Used in Step 1.4.

### Risk Matrix
A Likelihood × Impact grid that plots every project risk to prioritise mitigation resources. Critical risks (high × high) require owners, active mitigations, and contingencies. Grounded in PMI PMBOK and ISO 31000. Used in Step 1.5.

### Strategic Alignment Matrix
A scoring tool that measures how directly a project supports each corporate strategic priority. A project that is financially attractive but strategically misaligned is less likely to receive ongoing support. Used in Step 2.1.

### Value Driver Tree
A hierarchical decomposition of total project value into its causal drivers — revenue uplift, cost reduction, risk avoided, strategic options. Makes every assumption visible and auditable. Used in Step 2.2.

### Benchmarking
The practice of comparing project assumptions and performance targets against peer organisations, industry data, or analogous past projects. Turns contested internal estimates into defensible evidence. Used in Step 2.2.

### Implementation Ease Scorecard
A four-dimension scoring tool (organisational readiness, technology readiness, change complexity, regulatory risk) that converts implementation difficulty into a comparable, decision-ready score. Used in Step 2.3.

### Prioritisation Matrix (Value vs. Ease)
A 2x2 portfolio matrix that plots all investment candidates by Value and Ease to force funding decisions across a portfolio — not project by project in isolation. Used in Step 3.1.

### Financial Model — NPV, IRR, Payback
The three core investment metrics: Net Present Value (absolute value in today's dollars), Internal Rate of Return (yield vs. cost of capital), and Payback Period (liquidity risk). Always model three scenarios. Used in Step 3.2.

### Scenario Analysis
A structured method for stress-testing a financial model by varying the 3–5 most sensitive assumptions to produce base, upside, and downside cases. Forces explicit acknowledgement of uncertainty. Used in Step 3.2.

### Pyramid Principle
A top-down communication structure where the governing conclusion is stated first, supported by MECE arguments, each backed by evidence. Developed by Barbara Minto at McKinsey. Used in Step 3.3.

## Worked End-to-End Example: Unilever Sustainable Packaging Investment

When Unilever evaluated a multi-billion-euro investment in sustainable packaging across its top 20 brands, the business case team followed all three phases rigorously.

**Phase 1 — Description:** The SCQ framing established the situation (EU single-use plastics regulation tightening to full enforcement by 2025), the complication (€1.2B in potential liability across the portfolio), and the proposed solution (a €600M investment in recycled-content packaging infrastructure). SMART objectives set a 50% recycled-content target by 2025 with annual cost-per-tonne KPIs and a lifecycle reduction in virgin plastic use. The RACI assigned 14 brand teams, the supply chain function, and external packaging suppliers. The risk register flagged supplier concentration (top 3 suppliers = 70% of volume) as a Critical risk, with a mitigation plan to dual-source within 18 months.

**Phase 2 — Assessment:** Strategic alignment scored 9/10 — sustainability is Pillar 1 of the Unilever Compass strategy, directly referenced in the CEO's public commitments. Value creation was decomposed into a Value Driver Tree with three drivers: €340M NPV in regulatory cost avoidance, €180M NPV in consumer willingness-to-pay premium (benchmarked against Nielsen sustainable-product data showing 8–12% premium), and €580M NPV in avoided stranded-asset risk. Implementation ease scored 5/10 — the supply chain restructuring was complex and the technology for bio-based packaging was still maturing — triggering a phased approach.

**Phase 3 — Prioritisation and Financial Model:** The prioritisation matrix placed sustainable packaging in the 'Major Projects' quadrant (high value, medium ease), ahead of three lower-value digital marketing initiatives that were re-classified as Fill-Ins. The financial model showed NPV of €1.1B at a 9% WACC, IRR of 24%, and a 4-year payback period. The downside scenario (€150M less consumer premium, 12-month regulatory delay) still showed NPV of €620M. The board presentation opened: 'Investing €600M in sustainable packaging delivers €1.1B NPV, protects the brand from €1.2B in regulatory exposure, and is consistent with our 2025 sustainability commitments — we recommend Phase 1 approval today.' The board approved Phase 1 funding in the first meeting.

## Pitfalls and Best Practices

**1. Describing activities instead of outcomes in objectives.**
The most common SMART failure: writing 'Conduct a customer survey' instead of 'Increase NPS from 32 to 50 by Q4.' Fix: every objective must describe a measurable state of the world, not a task.

**2. Assessing the project in isolation.**
A project that looks attractive in isolation may be the third-best use of capital when viewed against all competing investments. Always run the prioritisation matrix with all candidates before recommending.

**3. One-scenario financial models.**
A financial model with only a base case is a marketing document, not an investment decision tool. The board will always ask 'what's the downside?' — have the answer ready before the meeting.

**4. Burying the recommendation.**
Presenters who build to the conclusion at the end lose the board in the first five minutes. State the governing recommendation on slide 1 — every other slide is the proof.

**5. Generic risk labels.**
Risks labelled 'market risk' or 'technology risk' without a specific trigger provide no actionable guidance. Name the specific event ('Key supplier X has only one packaging line — if it goes down, we lose 40% of supply') and own it.

**6. Unsourced financial assumptions.**
Every assumption in the financial model should have a source: a market research report, a competitor benchmark, or an internal performance record. Unsourced assumptions invite challenge and destroy board confidence in the entire model.

**7. RACI with multiple Accountables.**
A deliverable with two Accountables has none — each party assumes the other is responsible. Fix: one name in the A column for every deliverable.
