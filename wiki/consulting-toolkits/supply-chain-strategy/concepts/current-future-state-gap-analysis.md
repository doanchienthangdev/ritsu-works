# Current-Future State Gap Analysis

*Category: analysis · Toolkit: Supply Chain Strategy*

## What it is
A structured three-column analysis that documents (1) the current state of a supply chain process or capability with its measured performance, (2) the desired future state with its target performance, and (3) the specific capability, process, technology, or people gaps that must be closed to move from current to future state.

**Origin:** A core technique in Lean value-stream mapping (Taiichi Ohno, Toyota Production System, 1970s–1980s) and business process reengineering (Hammer & Champy, 1993). The supply-chain strategy application is standard in McKinsey and BCG operational transformation engagements.

## Why it works
The gap analysis forces clarity on two often-blurred concepts: where we are and where we need to be. Without a disciplined current-state baseline, future-state targets are aspirational fiction. Without a disciplined future-state definition, the gap list is incomplete and the initiative portfolio will miss critical interventions. The three-column structure also prevents the most common consulting failure: jumping to solutions (Phase III initiatives) before the problem is clearly defined.

## When to use
Use in Phase II for each functional pillar to establish the rigorous baseline that informs Phase III initiative generation. Also use at the mid-point of a transformation (18 months in) to re-assess which gaps have been closed and which new ones have emerged.

## Step-by-step tutorial
1. 1. For each pillar, document the current state: describe the actual process (not the intended process — verify with process observation and artifact review), the technology in use, the team structure, and the measured KPI performance with a specific data date.
2. 2. Define the future state: based on the Phase I strategic objectives and the KPI targets agreed with the CSCO, describe the future-state process, technology, team, and performance level. The future state is not theoretical best-practice — it is calibrated to what the organization needs to achieve its strategy.
3. 3. Identify the gaps: for each dimension (process, technology, people, data), identify what must change. Be specific — 'need better technology' is not a gap. 'Currently using 18 disconnected Excel spreadsheets for demand planning; future state requires an integrated IBP platform with statistical baseline and AI-enabled exception management' is a gap.
4. 4. Validate the gaps with SMEs: confirm that the identified gaps are real (not already being addressed by an existing project) and that they represent the true root cause of the performance shortfall (not a symptom).
5. 5. Classify gaps by type: (a) Process gap (the right process does not exist or is not followed), (b) Technology gap (systems are missing or inadequate), (c) People gap (skills or capacity are insufficient), (d) Data gap (data quality or availability is inadequate).
6. 6. Prioritize gaps: rank each gap by its impact on the Phase I strategic objectives. The top-priority gaps become the direct input to Phase III initiative identification.
7. 7. Document the gap analysis: create a one-page gap summary per pillar (current state → gap list → future state) and validate with the Pillar Owner before proceeding to Phase III.

## Real-life example — Heineken
Heineken's 'Evergreen' supply chain transformation (launched 2015) was built on a rigorous current-future state gap analysis across its 165 breweries in 70 countries. For demand planning, the current state showed forecast accuracy at 68% WMAPE with planning done in weekly silos per country using local Excel tools. The future state target: 85% WMAPE with a unified global IBP platform and regional planning centres of excellence. The gap analysis identified four specific gaps: (1) no global demand signal aggregation (data gap), (2) no statistical baseline demand model (process gap), (3) planners lacked advanced analytics skills (people gap), and (4) no integrated planning system across sales, marketing, and supply (technology gap). Each gap became a distinct workstream in the transformation — and Heineken's disciplined gap identification prevented initiative scope creep by keeping each workstream focused on closing one specific gap.

**So what:** The gap analysis is most valuable when it is specific enough to be wrong. Vague gaps ('we need better integration') cannot be closed — they just generate more consultants. Specific gaps ('we have no statistical baseline demand model') generate actionable initiatives.

## Template
For each functional pillar, complete the current state, future state, and gap identification for each key process and capability dimension. Validate each row with the relevant SME before finalizing.

- [ ] Pillar (D&SP / S&P / Manufacturing / L&D)
- [ ] Dimension (Process / Technology / People / Data)
- [ ] Current State Description (specific, evidence-based)
- [ ] Current KPI Performance (value + date)
- [ ] Future State Description (specific, aligned to Phase I strategy)
- [ ] Target KPI Performance (3-year target)
- [ ] Gap Description (specific — what is missing or inadequate)
- [ ] Gap Type (Process / Technology / People / Data)
- [ ] Gap Priority (H/M/L based on strategic impact)
- [ ] Linked Initiative (from Phase III, populated after gap analysis is complete)

## Pitfalls
- Documenting the process-as-designed instead of the process-as-used: the current state must reflect what actually happens, not what the procedure manual says. Process observation and gemba walks are essential.
- Future-state defined as theoretical best-practice rather than strategic requirement: the future state should be calibrated to what the organization needs to achieve its strategy — going beyond that wastes resources and increases transformation risk.
- Gaps that are symptoms, not root causes: a gap of 'poor forecast accuracy' is a symptom. The root-cause gap might be 'no statistical baseline model' or 'S&OP process does not include market intelligence.' Dig to root cause.
- Incomplete gap lists that miss people and data dimensions: gap analyses routinely capture process and technology gaps but miss people (skill deficits) and data (quality, availability, integration) gaps. These are often the root cause of process and technology failures.
