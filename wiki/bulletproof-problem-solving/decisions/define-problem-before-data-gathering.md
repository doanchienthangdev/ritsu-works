# Define the Problem Before Launching Data Gathering

**Type:** decision · **From:** *Bulletproof Problem Solving* (Charles Conn, Robert McLean, 2018), Ch 2 — Define the Problem

## Summary

The chapter's opening imperative: teams must establish clear problem boundaries, success criteria, time frame, and required accuracy before beginning data collection or expert interviews. Premature data gathering without problem definition leads to wasted effort and solutions that miss decision-maker values.

## Raw quotes (verbatim, for citation)

- **From [Ch 2 — Define the Problem](../chapters/chapter-02-define-the-problem.md)** (PDF pp. 61–78, confidence 0.95):

  > Teams and individuals surge off into data gathering or expert interviews without being very clear about the boundaries of the problem, the criteria for success, the time frame, or level of accuracy required. This is bound to lead to disappointment.

## Ritsu relevance

The /cla workflow enforces this: problem framing (Phase 1) and domain analysis (Phase 2) must complete before options are generated (Phase 4) — preventing the premature-analysis failure mode the chapter describes.
