# Hypothesis-Driven Workplanning

**Type:** concept · **From:** *Bulletproof Problem Solving* (Charles Conn, Robert McLean, 2018), Ch 4 — Build a Great Workplan and Team Processes

## Summary

Best-practice workplanning requires that every analysis is tied to an explicit hypothesis and a pre-visualized output ('dummying the chart'). No model is built without a clear question it answers. Analyses are ordered logically—those that can knock out later analyses come first—and responsibilities and deadlines are explicit to prevent wasted work.

## Raw quotes (verbatim, for citation)

- **From [Ch 4 — Build a Great Workplan and Team Processes](../chapters/chapter-04-build-a-great-workplan-and-team-processes.md)** (PDF pp. 117–140, confidence 0.95):

  > we don't do any analysis for which we don't have a hypothesis. We never go off and build a model without a very good idea about what question it answers.

  > We sharpen our thinking even more by requiring that we can visualize what form the output might take (we call this dummying the chart), so we know if we would want it if we had it.
