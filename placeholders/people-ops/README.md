# Placeholder: People Operations

## Why this pillar exists (eventually)
First non-AI hire (contractor, employee, formal cofounder) triggers a stack of operational concerns: hiring funnel, human onboarding, payroll, performance management. The "1-person AI Native Company" thesis tested when this trigger fires — does the company hire, or does it stay solo + cofounder + AI?

## Entry condition
**Trigger:** First non-AI hire commits (contractor signed OR employee offer accepted).

Note: this is distinct from cofounder. The cofounder is already operational and has founder-tier permissions per `governance/ROLES.md`. People-Ops activates for the SECOND human past the cofounder.

Until trigger: defer. AI workforce + founder + cofounder is the experiment.

## Initial sub-pillars when activated
- `hiring-funnel` — sourcing, screening, interview process, offer mechanics
- `human-onboarding` — first-30-days for a human (different from `05-customer/02-onboarding/`, which is for customers)
- `payroll-vn-or-other` — depends on hire location; coordinates with `placeholders/compliance-vn/` if VN-based

## On activation
1. Founder + cofounder approval Tier D-Std (hiring is high-magnitude, semi-reversible)
2. PR opens with sub-pillar tree
3. Move from `placeholders/` to top-level
4. **Cultural decision:** does this hire change the "1-person AI Native Company" thesis? Document explicitly in `00-charter/charter.md` if so. If not, this is auxiliary hire (contractor, advisor); thesis intact.
